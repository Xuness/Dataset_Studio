# 审美评审模型输出协议

当前业务版本为 1。权威实现是 [固定输出指令与解析器](../../crates/studio-application/src/aesthetic.rs)及 [DTO](../../crates/studio-domain/src/aesthetic.rs)。

System Prompt 负责定义审美标准、并列条件、顶级提名标准和不可评判条件。程序自动把冻结的任务指令、当批短 ID 与对应图片加入 User 消息；不需要在 System Prompt 中写死 ID、图片数量或文件身份。

## 返回格式

返回一个完整 JSON 对象，只保留下列四个字段。下例假设本批输入为 img01 到 img06：

```json
{
  "schema_version": 1,
  "tiers": [
    ["img03"],
    ["img01", "img04"],
    ["img02", "img05"]
  ],
  "elite_candidates": ["img03"],
  "unjudgeable": [
    {"id": "img06", "reason": "图像内容无法辨认，无法可靠评价"}
  ]
}
```

- `schema_version` 固定为整数 1。
- `tiers` 按审美从高到低排列。同一梯队表示在本次标准下没有有意义的差异；组内没有先后。梯队不能是空数组；全部无法评判时，外层 `tiers` 可以是 `[]`。
- 本批每张图必须在 `tiers` 或 `unjudgeable` 中恰好出现一次，不得遗漏、重复、添加未知 ID。常规批量目标为 16 张，实际批量可能更小，以输入为准。
- `elite_candidates` 是独立的顶级标准提名，可为空或含多张。ID 必须已经出现在 `tiers`，且提名列表内不能重复。不能强制每批选第一名；后端将其送入保护候选池，提名不直接加分。
- `unjudgeable` 每项只能包含 `id` 和 `reason`。原因去除两端空白后不能为空，原字符串最多 1000 个 UTF-8 字节。普通低质量图片应进入靠后的梯队，不能用“不可评判”代替低排名。
- 四个字段必须存在；空集合用 `[]`。不要返回额外的分数、排名编号、逐图点评、置信度或推理过程字段，当前解析器拒绝未知字段。
- 不使用 Markdown 代码围栏，不在 JSON 前后添加说明。返回需正常结束；截断、拒绝、多个候选结果或未知结束状态不能作为有效评审。业务 JSON 上限为 256 KiB。

排名是本批图片的相对比较；顶级提名使用 System Prompt 中的独立标准。Rating 分组由后端处理，不要求模型猜测元数据或输出 Rating。

## 可以附在 System Prompt 末尾的协议要求

> 最终只返回符合调用方规定的 schema_version=1 的 JSON 对象，包含 tiers、elite_candidates、unjudgeable。严格使用本次提供的图片 ID，不添加额外字段或 JSON 之外的文字。每张输入图片必须恰好归入一个梯队或不可评判列表。按审美高低排列梯队；并列表示没有有意义的差异。顶级提名只依据本文规定的顶级标准，允许零张或多张，提名图片仍参加普通排序。无法可靠评价的图片应给出简短具体原因，不将其当作低质量。

建议先在独立小样本上检查输出合法率、并列与不可评判比例、重复评审一致性和提名尺度，再确定标准。接口接通或 mock 验证通过不能替代真实审美质量校准。

## 图片输入与请求预算

新阶段默认允许完整请求体 32 MiB，可配置 8–48 MiB。单张图片仍最多 2 MiB；常规批量目标 16 张，超出该阶段字节预算时在发送前重组，不能把批量数量写死在 System Prompt。此预算是本地上限，不代表任意供应商都接受相同大小。

图片 ID 与图片以相邻内容块发送，源文件名不作为 ID。当前短 ID 是 img01、img02 等批内标签；相同标签在不同批次可能对应不同图片。新阶段显式说明每个 ID 对应紧随其后的图片。传输和恢复语义见 [ADR 0031](../decisions/0031-aesthetic-transport-and-recovery.md)。
