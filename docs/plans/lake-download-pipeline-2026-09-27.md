# 数据湖下载流水线与可配置调度

状态：已实现并完成隔离验收，正式运行器已加载新代码；原任务保持暂停。延续已发布的在线湖与不可变任务范围/图片配方，不重新创建暂停任务。最终兼容决策见 [ADR 0041](../decisions/0041-lake-download-pipeline.md)，证据范围见[验收记录](../verification/2026-09-27-lake-pipeline.md)。

## 调度与恢复边界

- 分离元数据扫描、下载、编码与归档发布。单湖下载并发、每站点 API/图片请求起始速率可配置；三个湖共享编码并发、解码内存、SSD 暂存及可选带宽预算。
- 单个 HTTP 会话只供所属下载线程使用，跨图片复用连接；429/503 的 Retry-After 作用于站点相应请求通道，冷却期间不继续发起同通道请求。
- 支持边扫描边下载以及先扫描完整清单。候选元数据保存在控制库；前看记录数限制元数据积压，图片暂存另受数量与字节配额限制。
- 下载完成的原件和编码完成文件分别保存可核验收据。暂停/退出保留完整阶段产物；重启从已有收据恢复，未完成临时文件不会作为成功结果。
- 同湖元数据及媒体发布共用串行检查点协调，防止并发发布倒退元数据游标；E 盘保持设备级顺序写入、校验与短事务热发布。
- 发布批次按数量、输出体积和最长等待时间触发。停止发放新工作后等待已开始的工作退出，完成产物可恢复；不在网络或编码阶段持有正式湖写锁。
- 设置独立于任务不可变定义，以修订保护持久保存。下调并发/空间限制只约束后续准入，不中断已占用资源的工作；运行器周期读取新设置。暂停的旧任务仍使用原 ID、范围、编码配方与检查点。

## 可配置参数

建议初始值是本机调优起点，不代表站点公布限额：各站 4 路下载、0.9 API 请求/秒、2 图片请求/秒；全局 2 路编码、2 GiB 解码内存估算预算、8 GiB 暂存、2 GiB 磁盘保留空间。128 MiB 单图下载上限、1 亿像素上限保持已有默认值。图片队列 64 项，元数据前看 5000 条；发布 32 项/64 MiB/10 秒，任一满足即可提交。带宽限制默认关闭。

每秒请求是 HTTP 请求起始频率，包括重试和备用地址；图片/秒是整个处理链的产出指标，MiB/s 是字节吞吐，三者分开展示。用户测得的 Danbooru 约 2.75 图/秒属于其历史环境观测，未证明是服务端固定请求限额。

## 进度与验收

显示扫描状态、待下载/下载中/等待编码/编码中/待发布/已入湖/异常，以及窗口平均下载字节率、图片入湖速率、各阶段累计处理时间。计数区分未完成与异常，停止后清空瞬时速率，不沿用上一张图片的速度。

验证覆盖并发上限、阶段重叠、连接复用、限速/冷却、资源背压、配置冲突、混合大小图片、编码失败、暂停/续跑、崩溃收据恢复、元数据游标单调、元数据预算与发布去重；再执行契约生成、项目完整检查、集成与前端验收。正式任务保持暂停，升级后提供续跑入口。
