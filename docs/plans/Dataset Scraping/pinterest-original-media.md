# Pinterest 原图获取与验证

创建日期：2026-10-09。状态：获取方案与有限 CDN 样本验证；当前详情与媒体文件的完整对应链路待验证。

Pinterest 图片采集优先从 Pin 详情的媒体清单取得来源明确报告的原始媒体，再通过实际下载和解码确认文件。页面缩略图、尺寸档位和 `/originals/` 路径分别作为不同强度的线索，不能单独证明已取得创作者原件。该规则是 [Pinterest 采集方案](pinterest-collector-design.md)进入后续入口与质量试验的前置条件。

## 原图的含义

| 层次 | 本方案中的含义 | 所需依据 |
| --- | --- | --- |
| 页面预览或缩略图 | 用于列表、封面或页面展示的版本 | 实际返回位置及媒体角色 |
| 已知最大可用版本 | 在本次已经发现并验证的候选中，尺寸和角色适合的版本 | 候选清单、下载及尺寸验证，不宣称不存在更大文件 |
| Pinterest 原始媒体 | 当前来源数据明确以原始媒体字段报告，且成功验证的文件 | 原始字段路径、所属媒体、实际响应及文件 |
| 创作者原件 | 有出处证据支持的创作者发布文件 | 原站作品与作者、具体文件和版本关系核对 |
| Studio 存储文件 | 数据湖实际保存并供原图读取或导出的字节 | 存储记录及可能存在的编码配方 |

Pinterest 原始媒体也可能很小，可能已经是上传者保存的压缩图、截图或裁切。通过原图地址下载，不会恢复上传前丢失的信息。尺寸越大只说明像素数量，不自动证明编码质量更高或更接近创作者原件。

Studio [ADR 0071](../../decisions/0071-original-media-export.md)中的原图读取和导出针对湖中存储的文件。它可以证明读取的是存储字节，不能替来源采集过程证明文件在 Pinterest 上的角色与出处。

## 已核对的取数依据

gallery-dl 的 Pinterest 实现以详细 Pin 数据解析媒体：普通静态图片读取 `images.orig`；故事内容按页和块处理；轮播逐槽处理；视频独立解析。部分图片块使用 `image.images.originals`，其他情况下会依据签名或替换路径构造原始媒体候选。[固定版本源码](https://github.com/mikf/gallery-dl/blob/382b1c717eb5d0b856d6b4c66fa9bce6573a3cf9/gallery_dl/extractor/pinterest.py#L90)

该版本的详情参考入口为 `/resource/PinResource/get/`，请求选项包含 `id` 和 `field_set_key=detailed`，从 `resource_response.data` 读取 Pin。这里描述客户端参考路径，不承诺匿名访问或接口长期稳定。[详情实现](https://github.com/mikf/gallery-dl/blob/382b1c717eb5d0b856d6b4c66fa9bce6573a3cf9/gallery_dl/extractor/pinterest.py#L437)

官方 API 的响应示例包含不同尺寸档位，示例中的 `1200x` 实际宽高却是 402×536。它说明应读取实际宽高并下载核验，不能把档位名称当成文件尺寸。官方 API 与网页内部 JSON 分别解析，不混用字段契约。[官方媒体示例](https://developers.pinterest.com/docs/work-with-organic-content-and-users/create-boards-and-pins/)

`img.src`、`srcset`、`og:image` 或搜索结果的展示图可以帮助定位媒体，但没有原始媒体依据时只作为预览或候选。官方 Download image 是另一条可用时的对照路径；官方同时说明部分 Pins 不支持下载，帮助文档没有承诺其文件等于创作者最高质量原件。[下载说明](https://help.pinterest.com/en/article/download-an-image)

## 建议的获取顺序

1. **定位 Pin 并读取详情。** 保存入口与访问条件，确认返回的 Pin 身份。发现列表可以复用已取得的信息；媒体清单、角色或原始字段不充分时补充详情，不能直接把列表展示图作为最终结果。
2. **按媒体类型生成清单。** 普通静态图、多页内容、轮播、视频和封面分别处理，保留页、槽或块的位置。不能只取根节点第一张图片就宣布整个 Pin 完成。
3. **优先读取明确的原始媒体字段。** 保存完整 URL、声明尺寸、媒体身份、原始 JSON 字段路径及响应引用。保留 URL 的原始参数和后缀；不能统一强制改成 JPG。
4. **在明确依据下补充候选。** 只有实际数据支持且规则已经验证时，才根据同一媒体路径或签名构造有限候选。路径替换或后缀推导必须保留为推导依据；成功返回图片后，仍需核对媒体角色与关联。
5. **下载并核验文件。** 对实际 GET 返回的文件检查媒体类型、完整解码、尺寸、帧数及内容哈希，并与对应清单比较。写入成功后再推进该媒体的取得状态。
6. **保留回退状态。** 原始媒体不能取得而其他版本可用时，可以保存已知可用版本，但继续保留原始媒体缺口，等待后续复查。
7. **按需核对外部出处。** 若 Pin 指向可识别的 Pixiv 等来源，交给对应来源采集器复查作品与文件。新取得的外部文件独立保留，不覆盖 Pinterest 的观察与媒体版本。

该顺序中的“优先原始媒体”是目标选择规则；来源的原始字段可用性、映射规则以及各媒体类型的处理仍需实现与测试。

## URL 候选与回退边界

`https://i.pinimg.com/736x/...` 替换为 `https://i.pinimg.com/originals/...` 可以产生待验证的候选，但不能作为普遍可靠的原图解析器。原始文件可能不存在、不可访问，扩展名和媒体角色也可能不同；不能对所有缩略图批量改路径后就标记成功。

优先级由证据决定：来源明确报告的原始媒体优先，其次是已核对的页面媒体和已声明版本，推导 URL 最后考虑。`image_signature` 等来源标识按原字段保留，不能直接当作下载文件的 SHA-256 或物理对象身份。

回退候选先核对是否为同一媒体、是否经过裁切以及是否属于封面，再比较实际尺寸。像素面积不能用于把视频封面、故事背景或其他内容误选成目标图片。所有已尝试候选保留来源、结果和失败原因；不使用无界路径、尺寸和后缀枚举。

| 请求结果 | 处理方式 |
| --- | --- |
| 网络超时或临时服务故障 | 有界重试，保留进度与失败证据 |
| 401、403、登录页或挑战页 | 记录访问条件问题并暂停相应请求，核对会话或权限；不能判成原图不存在 |
| 429 | 按来源提示冷却，保留尚未完成的媒体任务 |
| 404、410 | 记录本候选不可用；按复查策略重新核对详情，不立即推断整个作品消失 |
| 200 但不是目标图片 | 记录无效响应、占位图或角色不符，不能按成功文件计数 |
| 原始媒体失败而预览成功 | 保存预览时标明回退，原始媒体任务继续体现缺口 |

对访问拒绝不循环尝试其他后缀或通道来消除错误记录。当前条件下能取得的其他版本与原始媒体权限是两项独立事实。

## 文件验证与保留

建议为每个下载结果保存以下证据，具体字段命名在后续契约阶段确定：

- Pin 和媒体身份、页或块的位置、角色、所依据的详情响应及观察时间。
- URL 的来源字段或推导规则、请求 URL、最终 URL、HTTP 状态与响应类型。
- 来源声明的宽高、实际解码宽高、EXIF 方向以及必要时的显示尺寸。
- 检测到的文件格式、实际字节数、帧数、SHA-256 和解码结果。
- 原始媒体依据、下载状态、回退原因及外部出处核对状态。

HTTP Content-Type 与扩展名只提供线索，文件本身仍需识别与完整解码。HEAD 或 Range 可以用于预检和续传，但不能替代完整文件验证；续传需要确认返回范围和版本一致性，避免拼接不同版本。下载与解码分别设置有界资源预算，超限明确报告，不能把截断数据记为成功。

同尺寸、同文件大小或相同解码像素都不等于原始字节相同。物理字节去重使用实际内容哈希；像素或感知相似用于另一层分析，不删除来源观察和原文件差异。

下载后首先保留返回字节。预览、缩放、WebP 转码、模型输入及其他衍生文件保留配方与关系，不覆盖来源文件，也不用放大或超分结果填补原图取得状态。数据湖的保存策略若进行有损转换，应明确哪些源文件仍被保留。

## 媒体类型的特别处理

| 类型 | 需要保留或验证的内容 |
| --- | --- |
| 普通静态图 | 对应 Pin 的原始媒体字段、实际文件与版本 |
| 轮播和多页内容 | 每个槽或页的媒体及顺序，不能只保存第一项 |
| 故事或分块内容 | 背景、前景图片、文字、贴纸及合成输出的角色；组件清单不等于最终展示成品 |
| 视频 | 视频文件或媒体清单独立处理；封面不能代替视频取得成功 |
| 动画图片 | 文件格式及帧信息，不能把首帧预览当成完整动画 |
| 外部链接图片 | 来源页面、作品和具体媒体的对应关系，外链不直接证明原作者 |

首轮可以优先实现普通静态图，但其他类型必须被识别并保留明确的延后或未支持状态。若一张 Pin 的画面包含多个合成组件，仅下载背景图无法保存其完整视觉内容；这类情况需要单独验证站点是否提供合成媒体。

## 取得状态建议

媒体候选的依据与下载结果分别保存。推荐区分来源原始字段、已声明版本、页面媒体及推导路径；下载结果区分已验证、临时失败、访问拒绝、未找到和无效媒体。创作者原件的核对状态另列。

| 对外结果 | 判定条件 |
| --- | --- |
| Pinterest 原始媒体已取得 | 当前来源明确报告为原始媒体，且目标文件与清单核对通过 |
| 原始媒体候选已下载 | 推导路径或参考地址取得有效图片，但当前来源身份或角色依据不足 |
| 已取得回退版本 | 取得预览或较小版本，原始媒体仍有缺口 |
| 需要访问条件核查 | 认证、权限或其他访问拒绝阻止了详情或媒体取得 |
| 媒体不可用或待重试 | 当前候选均无有效目标文件，保留具体原因 |

原始媒体取得率只按第一类统计。候选和回退文件可有独立的下载成功计数，不能计入“原图已取得”。完整 Pin 的完成条件还需覆盖其清单中的所有目标媒体及明确的范围排除。

## 本轮有限样本结果

本轮使用 gallery-dl [公开测试中的 CDN 地址](https://raw.githubusercontent.com/mikf/gallery-dl/master/test/results/pinterest.py)进行匿名 GET，并以 Pillow 完整解码成功响应。共检查四个媒体样本的三个尺寸路径，其中两个媒体来自同一个故事 Pin。样本用于检验目录、尺寸和文件之间的关系，不构成随机抽样。

| 样本 | `236x` 实际尺寸 | `736x` 实际尺寸 | `originals` 结果 |
| --- | --- | --- | --- |
| 静态图 `858146903966145189` | 236×354 | 399×600 | 200，399×600 |
| 静态图 `725220346239561090` | 236×236 | 736×736 | 200，1080×1080 |
| 故事 `858146904010573850` 的第一个参考媒体 | 225×400 | 225×400 | 403 |
| 同故事的第二个参考媒体 | 225×400 | 225×400 | 403 |

十二次媒体 GET 中，十次返回可解码 JPEG，两次返回 403。第一张静态图的 `736x` 与 `originals` 均为 77,302 字节，SHA-256 不同，解码后的 RGB 像素相同；第二张的 `originals` 为 149,436 字节，大于 `736x` 的 82,706 字节。

前两个故事参考媒体的可读版本视觉上均为渐变背景；由于没有取得当前详情，不推断它们是该 Pin 的完整展示内容、占位图或完整的故事页。这进一步要求媒体角色与文件可读性分别核对。

对 `858146903966145189` 的一次匿名详细 Pin 请求返回 403，未重试访问拒绝。本轮的 CDN 地址来自测试资料，而不是本轮成功获取的详情。

后续补测中，同一请求带上网页客户端请求头和 `csrftoken` Cookie 后匿名返回 200，因此该 403 不能归因为必须登录。详情的 `images.orig` 声明 399×600，指向上表的 `originals` 地址；重新下载的文件 SHA-256 与上表一致。这只覆盖一张普通静态图，其他媒体类型的对应关系仍待验证，见[发现策略与入口实测](pinterest-discovery-strategy.md)。因此，这些结果证明了所列 URL 的实际响应、尺寸和文件差异，尚未证明当前详情到原始媒体的完整映射、站点原图覆盖率或创作者原件身份。

本机证据保存在 `.local/reports/pinterest-research-20261009-e33e7b13/report.json`，包含请求结果、实际尺寸及哈希，不随仓库分发。文档日期使用本轮客户端日期；报告另保留执行环境的 UTC 采样时间。临时下载文件不作为生产图片入湖。

## 下一阶段验收

1. 在允许且正常可用的访问条件下，取得当前 Pin 详情，核对普通图片的原始字段与下载文件。匿名和登录条件分别记录，不把一次 403 的原因直接归为必须登录。
2. 比较详情字段、页面预览、已声明版本及可用时的站点下载文件，覆盖大图、小图和不同编码格式；确认尺寸档位、扩展名与实际文件的关系。
3. 验证多页、轮播、故事合成内容及视频封面的角色，证明每项媒体都关联到正确条目，不把组件或封面当作完整内容。
4. 检查原始媒体失败但回退成功、候选尺寸相同但字节不同、响应结构改变、访问条件变化和暂停恢复等情况，确保不误报原图完成。
5. 按可识别的外部出处核对少量原站文件，分别报告来源原始媒体与创作者原件的证据；然后再开展发现入口收益和审美质量试验。
