# 契约 v1 隔离校验记录

日期：2026-10-03。结论：45 项数据与恢复模型检查、17 组 JSON Schema 正反例通过。检查对象是设计契约及固定样例，不是已实现的 Pixiv 采集器。

## 已验证

- 三份 SQL 可以在目标空库或隔离的控制 7 样例上执行；外键和版本约束成立。
- 相同文件的多个页关系、不同取得收据的身份，以及同一收据的稳定重放可区分。
- 跨作品详情绑定、跨页资产绑定、重复页位置和重复当前关系被拒绝。
- 新关系尚未发布时，旧水位继续读取旧清单；新页缺图不会借用同槽位旧图。
- 文件与标签逻辑身份不依赖在线整数行号；包含空格的标签可作为一个字面身份查询。
- 归档检查点与 commit 同步确认；重复键不重复推进，错误 revision 回滚新提交。
- 在隔离控制库中追加新结构后，旧任务、凭据样例和旧表数据保持一致；旧 worker 拒绝不支持的新控制版本。
- outbox 允许控制确认先于在线发布，同时禁止未发布时提前释放。
- 现有原文编解码保留 UTF-8、空白及未知字段，并拒绝错误摘要；四类现有图片配方可通过原规范化器。
- 10 组有效 API/档案形状与 7 组无效输入得到预期结果，覆盖字符串 ID、凭据隔离、配方、扩展范围和既有错误外壳。

## 验证边界

SQLite 中的提交和水位操作是说明性模型。固定样例重复构建不等于真实 archive_rebuild 已支持新格式；旧表数据保留检查也不等于三站运行回归已经完成。未启动网络采集、修改正式运行器、生成生产 OpenAPI、执行生产迁移或测量持续吞吐。

实际实现仍须验证跨进程所有权、文件持久写入、真实中断恢复、Python 与 Rust 互通、旧读取版本与项目引用，以及登录后各网页入口的行为。

本机证据位于 `.local/reports/pixiv-contracts-20261003/`，包含模型报告、API 报告及复现材料，不随仓库分发。使用项目已有 Python 环境和 PowerShell JSON Schema 检查，没有安装额外依赖。
