# 多来源图片采集规划

创建日期：2026-09-30。更新日期：2026-10-03。状态：Pixiv 阶段 1–3 已实现，已完成公开小样本取数与后端回读；前端页面暂缓。[接入说明](../../architecture/source-collections.md)与[实现验收](../../verification/2026-10-03-pixiv-stages-1-3.md)描述当前能力，以下草案保留设计过程。

本目录记录 Dataset Studio 后续扩展图片来源的采集规划，供来源采集器、数据处理和调度设计使用。当前已有 Danbooru、Gelbooru、Yandere 数据湖及下载补全机制；新的来源需要自行发现作品、获取媒体并保存原始元数据。

当前方向是各来源维护独立采集器，由统一调度层协调资源和运行状态。首先展开 Pixiv，其他来源随后分别设计。采集流程已有草案，现阶段聚焦统一湖的多媒体关系、后端执行与恢复、来源读取和独立验证入口；前端页面留待后续。

Pixiv 已明确优先基于网页端、以作者为扩展核心并纳入登录认证。先细化网页取数、作者关系扩展和内容可见性，再根据实际取得的数据结构设计存储湖与接入。

## 已对齐的方向

1. 优先扩大图片与原始元数据的覆盖，尽量减少采集和转换造成的可避免损失。
2. 倾向先下载，再在本地进行哈希、近似重复识别和聚类。跨来源的相似图片仍可能提供新的版本、标签和出处。
3. 相同文件的物理存储、站点作品身份和历史观察分别表达。物理去重不能删除来源关系或覆盖历史元数据。
4. 同一站点的已知任务可以合并和续抓；同一作品的新版本仍需识别。避免重复请求同一任务，与提前排除跨站近似图是不同的问题。
5. Pixiv、Pinterest 等来源具有不同的发现入口、媒体结构、可见性和更新语义，各自实现完整采集流程。
6. 采集器内部由多个子模块协作，发现、元数据获取、媒体下载及后续处理保持相对独立，并有持久进度和有界积压。
7. 先明确采集流程、数据保留和覆盖判定，再安排实现与采集验证。本目录的设计草案不代表采集器已经实现或验证通过。

## 职责边界

| 层次           | 负责的内容                                                                         |
| -------------- | ---------------------------------------------------------------------------------- |
| 来源采集器     | 来源发现、实体身份、分页、元数据解释、媒体清单、版本识别、来源内重试和覆盖判定     |
| 统一调度层     | 来源间资源预算、运行准入、开始暂停、优先级、冷却协调和状态汇总                     |
| 共享基础能力   | HTTP 传输、断点文件、哈希校验、暂存准入和通用运行记录；具体复用边界待设计          |
| 本地处理与归档 | 编码、物理对象复用、近似重复分析、聚类及数据湖发布；与来源采集通过可恢复的结果交接 |

统一调度层不推测某站点的下一页，也不替来源采集器判断作品是否完整。来源采集器报告自己的进度、等待原因和可继续执行的工作，并遵守统一资源预算。

未来入湖设计应延续图片对象、来源资产、历史观察和原始元数据分离的原则，保留站点自身语义。现有读取入口见 [ADR 0035](../../decisions/0035-source-registry-and-dispatch.md)，阶段独立执行的已有经验见 [ADR 0043](../../decisions/0043-independent-lake-stages.md)。这些文档描述既有能力，不表示新采集器已接入。

## 来源设计进度

| 来源           | 当前进度                              | 后续重点                                            |
| -------------- | ------------------------------------- | --------------------------------------------------- |
| Pixiv          | 新湖、采集任务、后端 API / SDK 已接入 | 真实登录和可见性验证、大规模持续采集、后续前端      |
| Pinterest      | 已识别为独立设计对象                  | Pin、画板与分区的关系，推荐扩展，原始外链与媒体版本 |
| Konachan       | 待展开                                | 帖子目录遍历、原图、标签字典与历史更新              |
| Anime-Pictures | 待展开                                | 列表与详情补全、访问可用性、原件取得状态            |
| Zerochan       | 调研中提出的补充候选，尚未确定接入    | 是否纳入后续范围及对应采集成本                      |

上述顺序是当前讨论安排，不是实施排期或吞吐承诺。

## 后续工作

阶段 1–3 的版本分派、新湖读写、采集控制和后端接口见 [ADR 0052](../../decisions/0052-pixiv-collections-and-canonical-media.md)。后续补充真实登录、目标可见性和较大作者图的持续运行验收，再恢复前端设计。公开目录和有限图片已验证，不代表完整作者覆盖。

实现阶段的验证应覆盖设计中明确的边界。公开接口的小样本响应仅能作为接口证据，不能替代完整采集器的功能验证、覆盖审计或持续吞吐测量。
