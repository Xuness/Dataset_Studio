# 多来源图片采集规划

创建日期：2026-09-30。更新日期：2026-10-09。Pixiv 已完成采集核心、后端、现有界面接入、增量复查与周期计划。[接入说明](../../architecture/source-collections.md)、[最新决定](../../decisions/0053-pixiv-public-operation-and-incremental-refresh.md)与[公开生产验收](../../verification/2026-10-03-pixiv-public-production.md)描述现状，以下草案保留设计过程；[阶段 1–3 验收](../../verification/2026-10-03-pixiv-stages-1-3.md)是此前的小样本基线。Pinterest 第一批指定 Pin 已贯通独立采集、原图下载、归档发布、Rust 读取和现有工作台；图版、推荐和持续运行按后续批次实施。

本目录记录 Dataset Studio 后续扩展图片来源的采集规划，供来源采集器、数据处理和调度设计使用。当前已有 Danbooru、Gelbooru、Yandere 数据湖及下载补全机制；新的来源需要自行发现作品、获取媒体并保存原始元数据。

各来源维护独立采集器，由统一调度层协调资源和运行状态。Pixiv 已接入统一多媒体湖及现有工作台，其他来源随后分别设计。

Pixiv 已明确优先基于网页端、以作者为扩展核心并纳入登录认证。先细化网页取数、作者关系扩展和内容可见性，再根据实际取得的数据结构设计存储湖与接入。

下一重点扩展来源为 Pinterest。直接在项目中打通指定 Pin 的原始媒体、归档和浏览，再扩展图版、推荐与搜索；访问、媒体角色和发现收益随正式实现验证。Rule34 保留为后续 Booru 扩展候选。

## 已对齐的方向

1. 优先扩大图片与原始元数据的覆盖，尽量减少采集和转换造成的可避免损失。
2. 倾向先下载，再在本地进行哈希、近似重复识别和聚类。跨来源的相似图片仍可能提供新的版本、标签和出处。
3. 相同文件的物理存储、站点作品身份和历史观察分别表达。物理去重不能删除来源关系或覆盖历史元数据。
4. 同一站点的已知任务可以合并和续抓；同一作品的新版本仍需识别。避免重复请求同一任务，与提前排除跨站近似图是不同的问题。
5. Pixiv、Pinterest 等来源具有不同的发现入口、媒体结构、可见性和更新语义，各自实现完整采集流程。
6. 采集器内部由多个子模块协作，发现、元数据获取、媒体下载及后续处理保持相对独立，并有持久进度和有界积压。
7. 先明确采集流程、数据保留和覆盖判定，再安排实现与采集验证。本目录的设计草案不代表采集器已经实现或验证通过。
8. Pinterest 独立维护来源业务与下载编排，只共享通用传输、哈希、资源调度和归档基础。首期采用 SHA-256 字节去重并保留 MD5；嵌入、感知去重和跨湖近似匹配留给后续共享分析，不作为接入前提。

## 职责边界

| 层次           | 负责的内容                                                                         |
| -------------- | ---------------------------------------------------------------------------------- |
| 来源采集器     | 来源发现、实体身份、分页、元数据解释、媒体清单、版本识别、来源内重试和覆盖判定     |
| 统一调度层     | 来源间资源预算、运行准入、开始暂停、优先级、冷却协调和状态汇总                     |
| 共享基础能力   | HTTP 传输、断点文件、哈希校验、暂存准入和通用运行记录；具体复用边界待设计          |
| 本地处理与归档 | 编码、物理对象复用、近似重复分析、聚类及数据湖发布；与来源采集通过可恢复的结果交接 |

统一调度层不推测某站点的下一页，也不替来源采集器判断作品是否完整。来源采集器报告自己的进度、等待原因和可继续执行的工作，并遵守统一资源预算。

未来入湖设计应延续图片对象、来源资产、历史观察和原始元数据分离的原则，保留站点自身语义。现有读取入口见 [ADR 0035](../../decisions/0035-source-registry-and-dispatch.md)，阶段独立执行的已有经验见 [ADR 0043](../../decisions/0043-independent-lake-stages.md)。这些文档描述既有能力，不表示新采集器已接入。

## 后续工作

Pinterest 已按[独立接入设计](pinterest-backend-and-lake-design.md)打通第一批“新建湖 → 指定 Pin → 详情与媒体清单 → 原图下载 → 归档发布 → 项目浏览”，并完成隔离恢复/接口/界面验证和一个匿名真实样本。后续在相同路径上加入图版分页、推荐搜索与增量复查，不另建独立抓取原型，也不等待视觉预筛模型选型。

阶段 1–3 的版本分派和归档协议见 [ADR 0052](../../decisions/0052-pixiv-collections-and-canonical-media.md)，公开运行及现有界面接入见 [ADR 0053](../../decisions/0053-pixiv-public-operation-and-incremental-refresh.md)。真实登录和显示条件在凭据提供后验收；搜索、榜单、新作入口是作者／作品种子及关系扩展之外的后续入口，不影响已实现范围的周期运行。

实现阶段的验证应覆盖设计中明确的边界。公开接口的小样本响应仅能作为接口证据，不能替代完整采集器的功能验证、覆盖审计或持续吞吐测量。
