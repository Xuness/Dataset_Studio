# Pinterest 有界物理组批方案

日期：2026-10-10。状态：已实现，并完成 Windows 故障恢复及外接容量盘有界合成验证；证据见[组批验收](../../verification/2026-10-10-pinterest-bounded-packing.md)。此前生命周期修复见[审查修复验收](../../verification/2026-10-10-pinterest-production-review-fixes.md)。本文件不构成百万级生产验收。

## 已确认的问题

改动前，每个逻辑任务立即封存一个物理 Batch。Windows 隔离环境中，经正式 Runner 处理 100 个指定 Pin、100 张不同字节的静态图片，产生 201 个 segment 目录、1,403 个普通文件和 100 个 TAR。改动后相同构造为 5 个目录、31 个文件、2 个 TAR。两次都完成深验证、原始响应往返、独立重建和固定水位比较。这个结果证明文件数量减少，不代表真实源站吞吐。

归档接受与逻辑回执身份已分离，采用“不可变逻辑回执 + 持久化组批计划 + 多回执物理批次”，保持 Pinterest 自己的事实、分页和覆盖语义。共享文件、TAR 和资源预留底层，不通过 Pixiv 的作者或作品任务表达 Pinterest。

## 组批边界

第一版采用以下边界，并由共享资源准入进一步收紧；不能超过现有单批 10,000 行和 32 MiB 元数据硬上限：

| 维度 | 当前界限 |
| --- | --- |
| 逻辑回执 | 64 个 |
| 事实行数 | 8,000 行，为对象和资产记录留出余量 |
| 规范元数据 | 24 MiB |
| 媒体字节 | 128 MiB，且不超过当前共享暂存可承诺的额度 |
| 等待时间 | 120 秒窗口，在请求/结果边界检查；无可执行前置工作、预算用尽或暂存承压时提前提交。在途传输可以延后封包，不因组批期限中断已发送请求 |

合法单条结果超过媒体或元数据软目标时单独提交，仍受硬行数、元数据、下载、内存和共享暂存额度约束。媒体引用按保守字节数计入目标，重复引用可能让组批提前结束。采样及访问条件变化是提交屏障，优先让后续任务看到已经接受的判断。

Pinterest 默认元数据请求速率为每秒 0.5 次，图片为每秒 1 次。尚未组批的 prepared 回执跨 15 秒调度时间片保存，时间片结束不会强制封包。UI 分别显示等待归档的结果/原图记录、已归档计数与已发布水位。时间片结束不等于结果丢弃，也不等于归档接受。

只合并同一作业、同一冻结定义、相容访问上下文中的独立结果。意图回执、旧版 prepared，以及同一分页流中有前后依赖的结果继续单独处理。合并同主键事实时，内容相同可以去重；内容不同必须报完整性错误。需要前序结果的后续任务仍只由已接受回执产生。

## 已实施的生命周期

1. 控制库 v22 增加 `pinterest_outbox` 和 `pinterest_batches`，沿用备份及升级锁。prepared 保存 receipt ID、task ID、claim、冻结定义/输入指纹、结果文件哈希和媒体引用。注册后任务处于 `prepared`，不会重新领取。冻结组员与 batch 映射同事务提交；恢复使用原映射。
2. 归档仍为格式 3，新增必需能力 `receipt-bundles-v1`，replay envelope 为 v2。新 reader 支持原四项能力或包含新能力的完整集合，拒绝未知能力。旧湖在首次组批前原子更新根能力声明；旧 segments 字节、路径、receipt ID、sequence 不变。在线格式 4、generation、事实身份与固定版本引用不变，在线能力检查仍只接受原集合。
3. 每个物理批次至多一个媒体 TAR，以及每张非空事实表一个 Parquet。同主键事实相同则去重，冲突报错；同批相同 SHA 只写一个对象。每个逻辑回执分别写入 journal，并共享物理 sequence。
4. 每页最多读取 128 个物理 sequence，每个 sequence 最多 64 个回执；同包所有成员在一次控制事务中回放，然后推进作业水位。逐成员中断不会留下半包控制结果。
5. 下载和 prepared 元数据预留跨时间片保留，冻结后原子合并到共同 TAR。重启先恢复已有占用及未来承诺，再开放其他来源准入；下调额度不会抹掉既有承诺。发布、逐回执清理及批次清理分别记录责任，中断后继续回收。暂停保留未接受结果；取消先发布已接受证据，再清理未接受结果。
6. 准入预算、去重、最小扩展深度和采样配额同时考虑待归档结果；进度总数仍只体现已接受结果。采样屏障避免后续媒体使用尚未确认的列表清单。

失败媒体的有界诊断与回收继续沿用本轮修复：失败回执接受后回收无消费者的坏文件；显式重试产生新 generation，并在新下载准入前处理旧代清理。需要调查样本时应另设有容量限制、可见的保留策略，不能默认把全部失败文件留在共享 spool 中。

## 验收与后续边界

- 故障注入覆盖注册、冻结、写 TAR、seal、rename、journal 接受、控制回放、在线发布和清理。另以真实进程终止覆盖冻结、写 TAR、接受、清理四个边界，恢复后没有重新请求已保存响应/图片。
- 覆盖同批同字节、同 URL 多绑定、旧 prepared、新旧归档混排、128 个逻辑回执边界内的整包事务恢复、预算接续、采样、软目标切批和共享暂存竞争。
- Windows 外接 12 TB USB 容量盘上完成 1,000 Pin、500 MiB 媒体的合成运行，18 个时间片中包含暂停与运行器/资源池恢复；原始响应、深验证、独立重建与比较通过。归档目录/TAR/Parquet 数量、归档文件字节、暂存峰值和重建时间见验收记录；物理设备扇区写入量未测量。
- 尚未进行百万级历史、大规模真实联网或多日无人值守压力验证。容量盘测试使用合成响应和有效 PNG 加尾部填充，不代表源站速率、真实图片解码负载或长期磁盘故障率。

已有公共接口和格式对照见[主设计](pinterest-backend-and-lake-design.md)。[Pixiv 的组批经验](../../decisions/0055-pixiv-receipts-and-bounded-batches.md)可用于检查生命周期边界，其字段、深度和账户语义不进入 Pinterest 模块。
