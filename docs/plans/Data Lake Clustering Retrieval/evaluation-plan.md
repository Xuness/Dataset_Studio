# 评估与分阶段推进

日期：2026-10-11。状态：建议实验方案，尚未执行。约束见[总体规划](README.md)，候选与文献依据见[模型选型](model-selection.md)。本文件不批准自动清理原始数据，也不把样本实验等同于全湖质量或吞吐证明。

## 要回答的问题

1. NaFlex 与 EmbeddingGemma 2，哪一种更能组织当前多来源图片的内容、场景和构图？
2. Kaloscope 3.0 与 2.0 能否聚合跨画师的相近画风，并区分同画师的明显风格变化？
3. 感知哈希与 SSCD 各自漏掉哪些转载变化，又会误合并哪些有效差分？
4. 在完整读盘、解码、推理和写入链路上，处理成本是否适合长期增量运行？
5. 聚类与检索结果能否改善工作集筛选，并带来可度量的采集收益？
6. 以来源元数据训练的属性探针，迁移到 Pinterest 后能否可靠识别漫画、线稿、截图、照片等属性？单独验收的 AI 生成识别能否跨生成模型、画风与后处理条件迁移？
7. 画风方向上，Kaloscope 的画师监督相对原版 DINOv3 和通用画风模型 CSD 是否带来跨画师画风聚合的实际收益？

不把向量截断或量化收益列为本轮研究问题。输入分辨率、长宽比和裁剪策略仍需评价，它们决定模型实际看到的内容。

## 样本与人工依据

### 可视检索切片

正式面板之前，先用约 2 万张覆盖五类来源的分层样本建立候选图库，以感知哈希、NaFlex 与 Kaloscope 3.0 生成首批邻居。人工抽查分层查询的前 20 个左右邻居，不要求穷举全部图片。首轮画风比较尽早加入原版 DINOv3，与 Kaloscope 在相同候选范围和查询样本上对照；CSD 留作后续补充。重点观察水印、签名、边框、留白或透明背景是否主导相似度，内容是否盖过画风，以及转载副本是否挤占邻居名额。

切片只产出失效方式清单与初步观感，用于修正预处理和困难图片对的设计，并决定后续多尺度区域及属性探针实验的优先级；不计算正式指标，不作选型结论。浏览页和结果放在 `.local/` 研究目录，不进入 Studio 正式格式。

### 分层覆盖

建议先建立规模可人工检查的研究面板，修正配方与评估后，再扩大到 5～10 万张分层样本。该数量是当前建议，按现有小湖容量和处理成本调整，不机械要求各湖等量。

覆盖五类来源，并考虑图片类型、长宽比、分辨率、年代、画师、角色、常见和稀缺题材。应包含人物插画、复杂场景、漫画页、线稿、厚涂、平涂、设计素材以及 Pinterest 的非动漫内容，防止最大来源和最常见人物构图决定结果。

Booru 标签用于抽样、解释和部分评估，不作为完整真值。未标注不能直接解释为不存在；来源标签、模型预测和人工确认分别保存。

### 困难图片对

| 方向     | 必须覆盖的对照                             | 检查的失效方式                         |
| -------- | ------------------------------------------ | -------------------------------------- |
| 复制检测 | 同作品压缩、缩放、加字、水印、边框与裁切   | 漏检转载版本                           |
| 差分保留 | 同作品不同表情、服饰、局部内容或文字       | 把有效差分当作冗余                     |
| 内容     | 相同场景但画风不同；相似画风但题材不同     | 内容与画风互相掩盖                     |
| 画风     | 不同画师但视觉风格接近                     | 画师负样本监督把近风格推远             |
| 画风     | 同画师跨时期或同一时期的不同绘画方式       | 仅按作者身份聚合                       |
| 画风     | 相同角色、姿势或构图但不同线条与上色       | 内容因素主导风格距离                   |
| 画风     | 未见画师与少见风格                         | 对已知作者词表或训练身份依赖过强       |
| 输入     | 长条图、宽幅图、透明背景、灰度图、明显签名 | 裁剪、背景或非作品线索主导结果         |
| 输入     | 同一作品的不同分辨率、放大及压缩版本       | 固定像素区域的视野变化被误当作画风差异 |

人工判断允许“相近、不同、不能确定”，并记录判断依据，如线条、上色、笔触、材质、构图或内容。画风具有多维性，不强迫所有样本存在唯一类别或唯一正确簇数。

### 分组隔离与证据等级

近重复与同作品家族尽量作为一个整体划分，避免转载版本分别落入拟合和验证集。防泄漏使用的作品家族分组与聚类拟合时的高置信度复制组用途不同；家族成员可独立归簇，不意味着可以把它们拆入训练与验证两侧。区分见过画师的新作品与未见画师的作品；对无法证明是否进入候选模型预训练或微调的数据，明确标为训练覆盖未知。

从数据湖抽到的图片能用于评价本地使用价值，但不能因此声称证明了模型的独立泛化能力。Kaloscope 等领域模型可能已接触部分 Danbooru 内容，需要特别记录这一点。

## 实验配方

### 通用内容

- NaFlex 从 784 patch 建立基线；如有明确细节损失，再评价 1024。14-384 仅用于小样本诊断，避免拿 NaFlex 默认 256 patch 直接比较。
- EmbeddingGemma 2 使用完整 768 维，从默认 280 soft token 建立基线，记录 BF16/FP32 前向精度。当前 3×3 池化对应最多 2520 个输入 patch 的预算，有效数量受比例和网格取整影响，不能直接与 NaFlex 784 patch 按 token 数比较或宣称信息量相近；配置与源码依据见[模型选型](model-selection.md)。
- 两类模型均记录实际输入宽高、有效 patch／token 数、填充量、输入覆盖范围、检索质量和端到端耗时。EmbeddingGemma 2 的保比例缩放已由源码确认，实验核对实际输入；有明确细节损失时再测试更高预算，不为数值接近而强制升至 560／1120。
- 第一轮所有模型只消费图像。图像与标题、标签、说明的联合表示作为独立实验，不能把文字信息增益混入纯视觉比较。
- 分别观察内容、构图、角色和画风邻居，不以单一综合分数掩盖差异。

### 画风

以 Kaloscope 3.0 与原版 DINOv3 建立首轮小样本画风对照，Kaloscope 2.0 保留为领域对照。Kaloscope 各版本先使用发布的预处理和完整特征输出，形成可复现基线；3.0 默认采用其训练过的 256 维检索向量，这不是为了节省空间而截断主干向量。

单独研究 3.0 中心裁剪造成的影响：以长宽比和被裁区域是否包含有效风格信息分层，必要时比较整图保比例、局部区域与组合表示。所有变更记录为新输入配方，避免训练配方差异与模型能力混在一起。

保留发布配方基线，再比较整图保比例表示和保留整图参照的多尺度局部组合。多个 512×512 区域只是可选设置，记录区域数量、相对全图范围、缩放尺度、选取规则、聚合方式与额外推理成本。区域均值后重新归一化可作简单起点，不预设优于整图。单独检查留白、签名与边框，以及同一作品不同分辨率和压缩版本的结果；高分辨率原图与小图分开统计，避免把原生像素误当作一致的观察尺度。

原版 DINOv3 ViT-B/16 使用 CLS 与平均 patch 特征，与 3.0 同基座、无画师监督；CSD 作为后续通用画风补充，固定实际权重版本并以本地结果为准，其公开权重与论文数值的差异不阻塞首轮实验。各模型使用同一批困难图片对和可比的画面覆盖，各自输入尺寸、归一化及区域配方分别记录。重点比较“不同画师但视觉风格接近”与“相同角色或构图但不同线条与上色”。

画风评估重点是跨内容和跨画师的关系。作者识别、角色识别和发布时间只作为辅助指标；高画师纯度不能单独验收画风聚类。

### 近重复

先建立带人工关系标签的候选图片对，再校准哈希距离和 SSCD 相似度。复制、裁切、差分和独立作品分开统计。不存在可直接从外部模型报告复制到本湖的统一阈值。

感知哈希与 SSCD 各自的召回贡献需要可见；候选产生与最终关系判断分别评价。近似检索增加后，在有界子集上对照精确检索，避免索引漏召回被误认为模型判断正确。

### 聚类

聚类拟合前按校准后的高置信度复制组选择代表或降权，并保留一组不做复制组去重／降权的对照拟合，观察转载副本对簇结构和簇中心的实际影响。记录关系确认依据、代表选择或权重规则，不把广义作品家族直接压成一个样本。

归簇时允许成员按自身特征独立分配，仅在相应任务下高置信度、视觉等价的副本可继承代表归属。完整图与局部裁切、线稿版与上色版、有效差分重点检查；作品家族关系与内容／画风簇归属分别保留。

球面或分层 K-means 可作为初始实现。统一有效样本、归一化口径和可比的粒度，检查多个随机种子的稳定性；同时保留代表图、边界成员和离群成员供人工审阅。

不把外部报告里的 512 或 1024 簇照搬到全湖。不单靠纯度、轮廓系数或二维图选择算法；二维投影可能改变密度和局部结构，应在实际特征空间建立关系。[UMAP 官方讨论](https://umap-learn.readthedocs.io/en/latest/clustering.html)

检索和分组要避免全量两两距离矩阵。FAISS 等近似检索后端是实现候选，不预先锁定索引类型、训练量或内存预算。

### 来源标签探针

在 NaFlex 等内容特征上为每个属性训练线性或浅层分类器，先验证漫画、线稿、截图、照片等属性。弱标签来自 Booru、Pixiv 元数据，并可纳入 Pinterest 的 `is_ai_generated`、`gen_ai_topics` 等辅助信号。首先统计各字段的覆盖、缺失与显式值，抽查标签可靠性及来源间语义；现有读取支持不构成完整标注的证据。训练与验证按作品家族划分；未标注不当作负例的确定证据，必要时只取有明确对立标签的样本作负例。

AI 生成识别单独设人工验证集与验收结果，检查不同生成模型、画风、缩放、压缩和其他后处理条件下的迁移。生成来源或版本可确认时分层记录，未知时单列，不把推测写成来源事实。漫画、线稿等属性的成绩不能替代 AI 检测成绩；AI 生成标记也不直接充当低质量或自动排除依据。

分别报告来源内验证成绩与 Pinterest 人工样本上的迁移成绩，后者才是采集用途的依据。输出保留置信度，阈值按属性与用途确定；探针预测与来源标签、人工确认分开保存。

## 指标与人工审阅

| 维度     | 建议记录                                                           | 判读要求                                   |
| -------- | ------------------------------------------------------------------ | ------------------------------------------ |
| 复制检测 | 候选召回、关系精确率、各变换类别漏检                               | 误合并与漏检分别报告                       |
| 差分     | 差分误合并数量和比例、典型误判                                     | 不能用总体重复准确率稀释差分损失           |
| 内容检索 | 人工相关的 Precision@K/Recall@K 或 Hit@K                           | 明确相关定义及分母，不能混用三个指标       |
| 画风     | 跨作者近风格命中、同作者异风格混入、内容干扰                       | 使用人工对照；作者标签指标作为辅助         |
| 聚类     | 代表图一致性、边界混杂、粒度与初始化稳定性                         | 稀有簇、离群图单独检查                     |
| 属性探针 | 各属性在来源内与 Pinterest 人工样本上的精确率、召回率              | 迁移成绩单独报告，不以来源内成绩代替       |
| AI 识别  | 不同生成来源、画风及后处理条件下的精确率、召回率与误排除案例       | 单独验收；来源未知单列，不借用其他属性成绩 |
| 覆盖     | 有效特征、失败、缺失、不支持、未计算                               | 不把失败样本静默移出分母                   |
| 成本     | 端到端 images/s、读盘/解码/推理/写入时间、峰值显存及内存、材料体积 | 冷缓存与热缓存分开，硬件与输入配方一起记录 |

数值门槛在研究面板校准后确定，不在没有人工依据时承诺精确率或误合并率。发布模型、论文与作者模型卡的分数标注为外部证据；本地结果另列。

## 容量与流水线

以下仅为 1,000 万条原始向量的算术估算，使用十进制 GB；不含 ID、索引、临时构建、关系或多视图材料。

| 特征                 | 原生维度 | FP32 原始体积 |
| -------------------- | -------- | ------------- |
| SigLIP 2 SO400M      | 1152     | 46.08 GB      |
| EmbeddingGemma 2     | 768      | 30.72 GB      |
| Kaloscope 3.0 检索头 | 256      | 10.24 GB      |
| SSCD 默认候选        | 512      | 20.48 GB      |

表中不是要求长期保留所有模型输出。研究期可保留候选结果以便比较，生产范围待选型。输出维度较小不能据此判定信息更差，较大也不自动更好。

本轮硬件只读查询显示可用 RTX 5090 D、约 32 GiB 显存；尚无该任务的实测吞吐。正式实验重新记录硬件、并发负载和软件版本。

测量应覆盖归档读取、图片解码、预处理、设备传输、推理、向量写入和索引构建。当前工作假设是瓶颈更可能出现在归档读取与 JPEG 等图片解码，而非 GPU 推理；流水线应允许独立扩展解码并发，并评估 GPU 解码等方案。该假设须由分段计时证实。读取批次与 GPU batch 可独立组织，采用有界队列；长任务将逐项日志写入本地目录，控制台只保留阶段进度。

## 证据保存与收尾

每次实验记录：成员与来源版本、权重修订及哈希、预处理、特征输出位置、维度与精度、参数、随机种子、覆盖统计和耗时。失败与重试保留关联，不用后续成功覆盖最初失败原因。

真实图片、向量、索引、逐项结果和运行日志不提交 Git。本地实验可使用 `.local/` 专用研究目录；正式报告只提交可复核的方法、汇总与必要边界，并注明逐项材料不随仓库分发。

本次文档整理仅检查文档内容、相对链接与 Git 差异，不运行模型、全湖扫描或后端测试。后续实施的测试范围遵循仓库 [AGENTS.md](../../../AGENTS.md)，按实际行为和风险选择。
