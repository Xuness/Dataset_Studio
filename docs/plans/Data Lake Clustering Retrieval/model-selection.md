## 从 PixAI 报告获得的启发

[Tsubaki.3 报告](https://pixai.art/en/tsubaki-3/report)将复制检测与概念聚类分开：采用 SSCD/FAISS 查找重复，使用动漫领域适配后的 SigLIP 表示概念，并让质量分类与概念采样各自承担职责。

本项目据此保留三个独立问题：作品版本关系、内容或画风组织、任务适用性。报告中的数据比例、相似阈值和模型效果不作为本地默认参数。

本次在报告与 PixAI 公开 Hugging Face 模型列表中没有找到 SigLip-Anime 权重入口；不能把它列作已可直接运行的组件。公开 Tagger 与该内部表示模型的职责不同。

## SigLIP 2：固定版与 NaFlex

候选：[SO400M/14-384](https://huggingface.co/google/siglip2-so400m-patch14-384)、[SO400M/16-NaFlex](https://huggingface.co/google/siglip2-so400m-patch16-naflex)。

两者视觉主干配置均为 27 层、隐藏宽度 1152、16 个注意力头，最终图像表示为 1152 维；规模约 400M 指视觉塔，不是含文本塔的整套权重。核对来源：[固定版配置](https://huggingface.co/google/siglip2-so400m-patch14-384/blob/main/config.json)、[NaFlex 配置](https://huggingface.co/google/siglip2-so400m-patch16-naflex/blob/main/config.json)。

| 比较项           | SO400M/14-384        | SO400M/16-NaFlex                 |
| ---------------- | -------------------- | -------------------------------- |
| Patch 边长       | 14                   | 16                               |
| 图像输入         | 固定方形缩放         | 在 patch 预算内尽量保留整图比例  |
| 图像序列         | 729 个 patch，27×27  | 由图像形状与预算决定，带填充掩码 |
| 位置嵌入         | 对应固定网格         | 调整到实际二维网格               |
| 适配训练         | 分辨率对应独立检查点 | 同一检查点覆盖多个序列长度       |
| 自蒸馏与掩码预测 | 使用                 | NaFlex 路线未采用                |

NaFlex 的训练长度包含 128、256、576、784、1024；论文报告其在训练范围内插值较好，不支持无限提高分辨率仍保持效果的推断。它与固定版的差异包含训练配方，不能通过更换一个缩放选项等同。SO400M 在自然图像基准上两版总体接近，NaFlex 在多种文档和屏幕检索任务上有优势。[SigLIP 2 论文 §2.4、§3.1.1](https://arxiv.org/html/2502.14786v1)

### 本项目取舍

NaFlex 升为通用视觉默认候选，固定版仅保留小样本诊断用途。对于插画、宽幅图和漫画，优先避免方形拉伸；但保比例输入仍会缩放并按 patch 网格取整，不等于保留原始像素细节。

[官方处理器](https://huggingface.co/google/siglip2-so400m-patch16-naflex/blob/main/preprocessor_config.json)默认 `max_num_patches=256`。不使用这个默认值与固定版的 729 patch 直接作等成本质量比较。建议先使用 784 patch，必要时再研究 1024；这些是输入信息量选择，与向量维度压缩无关。

极长图即使整体比例正确，也可能因预算不足而丢失局部纹理。是否需要整图与局部区域共同表示，属于输入配方研究，不能以单一分辨率结果代替。

## EmbeddingGemma 2

候选：[google/embeddinggemma-2](https://huggingface.co/google/embeddinggemma-2)。它支持图像与文本等模态组合，图文路径约 440M 参数（视觉编码器约 170M，文本部分约 270M），原生向量 768 维；当前只需图文能力，可关闭音频模块。官方上下文窗口为 8192 token，所有模态共享该窗口。[Google 模型卡](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2)

每张图片在共享序列中占用的软 token 数可配置，默认 280，可在 70～1120 之间调整；预算越高，细节越多，延迟也越高。它与 NaFlex 的 patch 预算同属输入信息量选择，比较时不应以 EmbeddingGemma 2 的默认 280 对照 NaFlex 784 patch。模型卡未说明视觉编码器名称及长宽比处理方式，保比例行为需在实验中按实际预处理确认。

### 与标准双塔路径的区别

SigLIP 标准路径分别编码图像和文本，再通过对齐后的向量比较。EmbeddingGemma 2 将视觉特征映射为可进入共享主干的 token，与文本共同编码。

本次核对的 [Transformers 实现](https://github.com/huggingface/transformers/blob/main/src/transformers/models/embedding_gemma2/modeling_embedding_gemma2.py)使用双向注意力；共享主干采用 Gemma 系列的旋转位置表示、门控前馈等结构，输出供池化和归一化使用的特征。不能据此声称具备生成式模型逐步推理或任意指令控制画风距离的能力。

LLM 系主干带来的优势主要在文字一侧：多语言（预训练覆盖 140 余种语言，适合日文标题与 tag）、较长且带组合条件的自然语言查询，以及图文交错的联合输入。视觉感知能力受约 170M 的视觉编码器约束，规模小于 SigLIP 2 SO400M 的视觉塔，不宜预期它在纯图像相似度和画风上占优。

### 预期价值与未验证部分

本项目优先考察以下应用假设：

- 处理 Pinterest 中混合题材和复杂场景，比较自然语言检索是否更符合人的内容需求。
- 在单独的实验中结合图像、标题和说明，研究文字上下文能否改善相关性。
- 将代表图与说明组合为图版或作品系列的摘要表示，研究集合之间的检索。

据此，当前倾向的职责分工是：NaFlex 作为纯视觉内容与构图空间，EmbeddingGemma 2 作为结合标题、说明与标签的图文语义检索空间，主要服务 Pinterest 与 Pixiv。两者并存时分别建索引，不混用向量。该分工随比较结果修订。

这些是由输入能力推导的应用方向，不是已验证的动漫效果。更多语义能力可能强化题材聚合，并不保证对笔触、线条、材质或细微上色差异更敏感。首轮统一使用纯图像输入；混合元数据的实验另行记录，避免不同来源的标签丰富度成为混淆因素。

### 精度与维度

保留完整 768 维，FP32 归一化与存储可作为研究默认。不安排 MRL 截断、PCA 降维或量化对比。推理仍遵守模型要求：使用 BF16 或 FP32，避免 FP16 前向；结果存储精度与前向精度分别记录。官方任务前缀用于文本，图像输入不加 `Clustering` 前缀。[使用要求](https://huggingface.co/google/embeddinggemma-2#best-practices)

## Kaloscope：画师识别与画风表示

候选：[Kaloscope 2.0](https://huggingface.co/heathcliff01/Kaloscope2.0)、[Kaloscope 3.0 Preview](https://huggingface.co/heathcliff01/Kaloscope3.0-preview)。用户转述过作者的判断：2.0 虽然聚焦画师识别，也可以承担一定程度的画风聚类。该意见记录为研究线索，不代替本项目评估。

### 两种基座

[LSNet](https://arxiv.org/abs/2503.23135)是网络结构，组合较大范围的感知与较小范围的动态聚合，强调视觉处理效率。Kaloscope 2.0 使用扩展后的版本，模型卡给出的整模规模约 183M，输入 448×448，主要任务为画师分类。

[DINOv3](https://github.com/facebookresearch/dinov3)是视觉预训练方法与模型家族，ViT-B/16 是其中一个具体结构：Base 规模、16×16 patch，官方主干约 86M，经历大规模自监督预训练与蒸馏。两条路线的比较同时涉及结构、预训练基础和下游目标，不能仅用参数量判断谁更擅长画风。

ViT-B/16 约 86M 的规模不构成首要顾虑。DINOv3 属自监督路线，相比 CLIP、SigLIP 这类图文对齐训练，更少主动舍弃与文字描述无关的纹理和低层视觉信息，而这部分恰与笔触、上色质感相关；公开资料说明 ViT-B 等较小版本经由大规模教师模型蒸馏得到。另一方面，2.0 以画师分类为目标，特征保证的是对画师的可分性，向量距离不一定适合直接聚类；3.0 采用相似度学习，直接约束距离，更接近聚类需求。

2.0 配套 [LSNetArtist 代码](https://github.com/spawner1145/lsnet-test/blob/main/model/lsnet_artist.py)确实提供跳过分类头的特征提取路径。用于聚类时读取特征，不预设固定画师类别的概率向量就是通用风格距离。

### 3.0 更接近当前任务的部分

3.0 将 DINOv3 的 CLS 与平均 patch 特征组合，再通过投影头学习 256 维相似度表示。其正样本使用同画师、近时间的不同作品族图片，负样本使用不同画师的图片；原始表征模型约 88.4M。现有分类扩展增加约 67.8M 参数，整模约 156.3M，而原检索表示不变。[3.0 配方与参数](https://huggingface.co/heathcliff01/Kaloscope3.0-preview)

因此，256 维是该模型完整的任务输出，属于学到的相似度空间；采用它不等于开展本项目已取消的存储压缩实验。较高维的主干表示也不能仅凭维数认定更好。

### 重点风险与验证口径

相似度学习比单纯分类更直接约束向量距离，但画师身份是画风的弱监督：不同作者可能画风相近，同一作者也可能同时或先后采用多种风格。不同画师作为负样本，可能把希望聚合的风格推远。

3.0 已公开画师相关检索与聚类结果，评估主要位于训练见过画师的开发面板；跨内容过滤不能证明所有内容因素均已排除，也不能代替人工跨画师画风判断。2.0 的分类指标与 3.0 的检索指标不作直接优劣比较。[公开评估边界](https://huggingface.co/heathcliff01/Kaloscope3.0-preview)

当前优先验证 3.0，并保留 2.0 作为领域对照，不提前宣称版本胜负。本次可读取 3.0 的模型卡和配置，其引用的训练仓库未能公开访问，尚未完成训练实现复核。

### 原始长宽比与裁剪

3.0 的标准配方是等比例缩放短边后中心裁剪到 512×512。它不拉伸局部几何，但会丢掉长图边缘。先按发布配方建立可复现基线，再独立评价整图保比例或多区域表示。更改预处理属于新的输入配方，不能继续直接引用原评估结果。

保留原生长宽比的偏好主要服务内容与构图。画风更多体现在线条粗细、笔触和上色质感等局部统计上；把大图整体缩放进有限输入预算，恰会削弱这些细节。因此画风方向的首个改进配方建议为：在接近原始分辨率下按网格或信息量选取多个 512×512 区域，分别编码后聚合（如均值后重新归一化）。它同时避免中心裁剪丢失边缘，和整图保比例输入作为两个独立配方比较。区域数量、选取规则（避开留白、签名与边框）和聚合方式均需实验确定。

### 画风对照基线

| 候选 | 作用 | 说明 |
| ---- | ---- | ---- |
| 原版 [DINOv3](https://github.com/facebookresearch/dinov3) ViT-B/16 | 与 Kaloscope 3.0 同基座、无画师监督 | 使用 CLS 与平均 patch 特征；检验画师监督对跨画师画风聚合是帮助还是把相近画风推远。权重按官方页面获取许可 |
| [CSD](https://github.com/learn2phoenix/CSD)（Contrastive Style Descriptors） | 通用画风相似度参照 | 论文 [Measuring Style Similarity in Diffusion Models](https://arxiv.org/abs/2404.01292)，ViT-L 主干，以 LAION-Styles 训练的非动漫专用模型，兼作 Pinterest 非动漫内容的画风参照；动漫效果未知。仓库声明已上传权重与论文数值存在差异、仍在调查，使用时固定权重版本并以本地结果为准 |

两者只用于对照与诊断，不扩大为首轮生产候选；若原版 DINOv3 在跨画师近风格上不逊于 Kaloscope 3.0，应重新审视画师监督的必要性。

## 近重复与版本检测

使用现有 SHA-256 处理保存字节相同的对象；感知哈希承担廉价近似检测；[SSCD](https://github.com/facebookresearch/sscd-copy-detection)作为专门复制检测候选。SSCD 官方默认候选为 `sscd_disc_mixup`，输出 512 维归一化描述符。

感知哈希与 SSCD 可互补产生候选，不把通过 pHash 设为 SSCD 的唯一入口，否则前一阶段漏掉的裁切等变化无法得到补充。语义相近的独立作品与同一作品的版本分别判断。

保留图片对证据，不预设相似关系具有传递性。若 A 近似 B、B 近似 C，仍需防止链式合并把 A 与 C 的有效差分折叠。近似检索未找到匹配也不等于证明不存在重复。

近重复检测在流程上先于内容与画风聚类：由此形成的作品家族以代表参与聚类拟合，避免跨站转载副本放大热门作品的权重。

## 来源标签探针

在已计算的内容特征（首选 NaFlex）上训练线性或浅层分类器，以 Booru、Pixiv 的元数据为弱标签，对 Pinterest 等缺少结构化分类的来源给出属性估计。候选属性包括 AI 生成、漫画页、线稿、截图、照片与低质量相关标签；Pixiv 的 AI 标记与 Booru 的 `ai_generated` 类标签可作为 AI 生成识别的起点。

探针训练成本低，可随特征版本重建；训练集按作品家族划分以免转载泄漏。来源标签存在缺标与误标，探针迁移到其他来源的效果必须在该来源的人工样本上评价。
