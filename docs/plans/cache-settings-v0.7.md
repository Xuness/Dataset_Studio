# 缓存分层与设置窗口 0.7 实施计划

状态：实施与验收完成。设计确认日期：2026-09-09。

## 已确认的目标

- 默认总缓存预算 64 GiB，允许配置至少 100 GiB；用户可接受约 50–100 GiB 的总缓存占用。
- 长期缓存默认不按闲置时间过期，也可设置闲置清理期限；临时缓存默认最后使用后 24 小时清理，并提供“仅本次会话”。
- G、S、Q、E 纯分级查询默认长期；Tag 和其他组合查询默认临时。允许手动调整类别及固定保留，不复制原有结果。
- 分级基础缓存按数据湖共享、按需建立，提供建立全部四种分级的入口。组合查询实际利用基础缓存缩小候选范围。
- 总预算与分类预算同时生效；统计包含长期、临时、缩略图和基础浏览索引。正式项目数据与运行暂存空间分别展示。
- 顶部新增“设置”菜单，分类入口打开同一个设置弹窗。第一版迁移现有缓存和性能设置，不添加无实际功能的空页面。

## 行为与一致性

“闲置清理期限”不是保证保存满若干天；容量回收与时间到期分别判定。固定保留、正在查看和持久业务引用具有明确保护状态。临时缓存不能通过普通容量回收挤掉固定的基础缓存。设置页显示受保护占用与实际总量，不能把保留预算描述为整个进程的磁盘硬限制。

会话由客户端项目会话和有时限的心跳识别；最后一个使用会话退出或失联后，会话缓存可以回收。浏览或工作集、选择、任务仍引用的成员继续保留。应用重启不能把旧会话缓存当作新的日缓存继续保留。

长期保留不意味着允许使用旧数据。以数据湖身份、generation、commit sequence 和 batch anchor 检查一致性；每日变更包括新对象、旧帖修改、旧新图片关联。历史缺口或 generation 更换必须回退重建。重建与增量发布保留原版本直至新版本完整提交。

分级基础缓存保存同一条有效 current-post 元数据的候选身份，组合查询仍校验全部条件。禁止将同一图片不同帖子上的 rating 和 Tag 错误拼接。历史观察查询及不满足复用前提的查询沿用原有正确执行路径。

真实基准发现只保存候选 ID 仍会重复读取来源标签列，因此基础缓存同时保存该观察的可空 Tag 字段。常用 Rating/Tag 组合直接在相应分级缓存内筛选；其他元数据条件继续按候选观察读取来源。标签载荷顺序扫描，匹配身份在有预算的原生临时关系中排序，以减少后续目录随机读取。该实现仍受已确认的总量与长期预算管理。

共享基础索引在应用拥有的目录中按 library_id 维护，来源 archive 保持只读。项目查询的固定成员版本继续由项目数据库管理，供分页、工作集、选择和任务使用。共享基础索引与项目固定结果分别计量；跨项目共享基础构建，不借用其他项目的可变输入范围。

第一版优先正确复用、增量维护和可解释的清理行为。存储压缩不作为实施前置条件；四个分级的空间和查询收益以实测为准。

## 设置结构

设置 → 缓存与存储：总预算、分类预算、长期闲置期限、临时期限/会话模式、缩略图预算、缓存条目管理、基础分级预建、分类清理。

设置 → 性能与任务：迁移查询工作内存等现有性能选项，显示本次任务与下次任务的生效范围。

一个设置弹窗、左侧分类导航、右侧页面；页面注册独立于业务面板。项目未打开时，全局设置仍可访问。主页面保留筛选条件、应用按钮、进度和简短复用状态；原“读取与缓存”入口迁移至设置，并处理已有布局的兼容恢复。
