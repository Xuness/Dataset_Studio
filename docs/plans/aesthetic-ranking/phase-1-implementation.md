# 第一阶段：持久评审链路

日期：2026-09-18。范围：首个开发阶段；统计排序和多模型复核仍待后续实现。

## 已接入的能力

侧边栏新增“美学排序”。用户从已保存工作集创建阶段，选择已配置模型和 System Prompt，设置目标曝光、调用次数上限及并发。创建后冻结候选与配置，准备完成后再开始付费调用。

运行页显示候选冻结、评级可用数、调用尝试、有效批次、无效返回、结果不明、保护候选及已知 token 用量。可以暂停派发、取消阶段、查看图片与梯队、检查归一化模型返回、明确排队重试和备份账本。所有批次和候选使用后端分页；页面卸载后后端执行继续。

当前“有效曝光”只对有效结果中进入梯队的图片累计，无法评判、读取失败、无效格式不计入。顶级提名不增加额外曝光、不提高分数。保护候选需要后续强模型或人工复核。

## 使用和故障处理

1. 在设置中配置支持图片的模型，保存审美标准和顶级标准的 System Prompt。
2. 先保存候选工作集，再创建评审阶段；创建只冻结数据，不发送模型请求。
3. 确认调用上限后开始。暂停会等待已经发送的请求；取消可能产生结果不明。
4. “结果不明”表示上游可能执行并计费。核对后才能明确重试；重试保留旧尝试，不重复接受同一批证据。
5. 本地返回已保存但未解析时，可执行本地解析，不新增调用。格式不符合业务约定时查看原文和错误，不能将其解释为低质量。

第一版沿用原始图片字节。单图超过 2 MiB 或整批请求超过 12 MiB 会明确停下，不偷偷降低画质。实际并发同时受 512 MiB 保守预留限制，通常为 4；上传控制为平均发送准入节奏。这里尚未宣称可运行上百并发或百万真实图片评审。

## 验证入口与边界

- `pnpm check`：完整类型、边界、契约、Rust 静态检查和单元回归。
- `pnpm test:integration`：保留已有集成回归，并加入 `tooling/integration-aesthetic.mjs`。
- 新存储测试覆盖已落盘返回的重放与唯一接受、结果不明恢复、无效/弃判处理、调用预算、暂停恢复、100 份结果并发返回和一致备份。
- 新集成脚本使用隔离的合成 Danbooru 图片库，经过真实 SDK、引擎、图片读取和三种协议适配器；上游为本机 mock。覆盖 16 图映射、Rating 隔离、保护提名、无效 JSON、显式重试、429、调用预算、中断恢复及暂停。

上述检查不验证模型审美能力。没有向商业模型发送真实图片，也没有运行百万图任务。历史微基准和带宽估算仍见[证据摘要](evidence-summary.json)，不能将其视为此次实现的容量成绩。
