# 现状与架构审查

状态：截至 2026-09-17 的源码审查记录与改造建议；整理于 2026-09-18。基线：`ae6fd669e543ad7558c1a739dfc1a472dd18a459`。

[返回规划入口](README.md)。该审查覆盖主要执行、存储、读取和界面链路，不是逐行无缺陷证明或百万图评审性能认证。现有任务与查询已使用的规模不能直接外推到长期付费评审。

## 已核查的工程现状

| 边界                       | 当前实现                                                | 对新功能的用途与限制                                           |
| -------------------------- | ------------------------------------------------------- | -------------------------------------------------------------- |
| 前端                       | React/TypeScript、模块注册、公开 SDK、Tauri 平台层      | 可新增侧边栏一级入口；业务执行不能依赖组件挂载                 |
| domain / application       | 无 HTTP、SQLite、Tauri 依赖的类型与端口；LLM 服务已独立 | 新增评审领域类型和应用用例，不将其塞进协议适配器               |
| studio-llm                 | 三类调用协议、完整/流式响应、取消、有限重试、并发控制   | 可承接单次 16 图调用；没有评审任务账本、业务排名校验或统计算法 |
| studio-sources / resources | 只读来源、媒体身份核验、按包和偏移读取、有界解码与缓存  | 复用物理读取与预算；评审图片规格、变换版本和内容留证需要新增   |
| project / scopes           | 固定成员、来源依据、工作集、选择、查询引用保护          | 复用输入与下游工作集；固定成员不等于已固定 Rating 和年份       |
| jobs / workers             | 本地确定性算子、独立进程、检查点、成果恢复              | 执行与恢复语义需要区分远端调用和纯计算                         |
| storage / artifacts        | SQLite、独立排名材料、成果发布、版本、引用和清理        | 可复用发布原则；评审账本和新排名材料需要自己的模式及读取接口   |
| 浏览                       | 后端范围引用、keyset 分页、持久排序索引、位置书签       | 技术可复用；当前排名列和过滤语义与 MetaRecall 耦合             |

2026-09-17 的只读目录核查发现：项目存在 11,524,857 项的固定工作集和 ready 状态排名成果；对应 project.sqlite 主文件约 10.88 GiB。另一个项目主文件约 17.05 GiB。这里只读取数据库版本、工作集目录、任务/成果目录及页统计，未枚举全量图片、未重跑排序。文件大小包含现有成员、查询和索引等，不能直接当作新功能的每图空间估算，也未核验每一个成果行。

所统计的 Rust、前端和 SDK 范围合计 260 个文件、67,001 行，含测试，不含生成的 schema.d.ts、Tauri 宿主和工具脚本。较大的职责集中点包括 api.rs（1,750 行）、App.tsx（1,678 行）、query_cache.rs（1,464 行）、RankingPanel.tsx（1,401 行）、Browser.tsx（1,305 行）。行数只是定位线索，真正的问题是新业务若继续进入这些文件，会增加任务、界面和存储之间的耦合。

## 优先处理的架构问题

下列 P1/P2 表示推进本功能前的优先级；除明确指出的当前行为外，是扩展风险，不表示已有用户数据损坏。

| 优先级 | 当前证据                                                                                                                                                                                                                                  | 新功能接入后的影响                                                                       | 建议                                                                                                                 |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| P1     | [jobs.rs:81](../../../crates/studio-engine/src/jobs.rs#L81) 的调度循环 await 完整 execute；main.rs 只启动一个该调度器                                                                                                                     | 单个长期评审阶段若直接接入，会占用计算任务队列；它不会因此阻塞所有 HTTP 或独立查询任务   | 增加明确的执行器类别和有限并发调度，区分本地计算与远端评审，支持阶段/项目公平调度                                    |
| P1     | [worker.rs:402](../../../crates/studio-engine/src/worker.rs#L402) 重新执行 operator.row 校验；population 路径直接转到现有 ranking 模块                                                                                                    | 网络评审不可通过重新调用来验证，既非确定性也可能再次计费                                 | 原始评审结果先持久保存，业务校验与统计重放仅使用本地证据；保留现有纯算子语义                                         |
| P1     | [lifecycle.rs:325](../../../crates/studio-storage/src/lifecycle.rs#L325) 将中断的 running/preparing 任务重新排队；[llm_invocations.rs:30](../../../crates/studio-engine/src/llm_invocations.rs#L30) 仅维护内存中的活动调用                | 现有恢复策略不足以判定远端是否已受理；完成的 invocation ID 可以再次发送                  | 新增批次与尝试账本，单独保存 outcome_unknown，统计应用使用持久唯一键；不能承诺上游账单 exactly-once                  |
| P1     | [ranking.rs:164](../../../crates/studio-storage/src/ranking.rs#L164) 至 298 持有项目写锁和覆盖整个保存流程的事务；[job_scopes.rs:212](../../../crates/studio-storage/src/job_scopes.rs#L212) 起也在长事务内复制任务成员                   | 百万成员工作集保存期间，评审结果、草稿、进度等项目写入可能等待；读池不能解决写者互斥     | 输入与大成员材料采用私有暂存、分批提交及短事务发布；高频评审账本与项目控制元数据隔离。必须保留中断不暴露半成品的保证 |
| P1     | [inference.rs:79](../../../crates/studio-domain/src/llm/inference.rs#L79) 的快照携带完整 messages；[validation.rs:76](../../../crates/studio-application/src/llm/validation.rs#L76) 附近限制输入 16 MiB；调用层按数量而非请求体总字节准入 | 图片 base64 反复进入快照和序列化，排队请求可能大量占内存；直接保存每次完整快照会重复存图 | 任务持久层保存规范化图片引用和哈希；发送时才物化。限制准备中、排队中、在途请求的总字节，并保留现有单请求上限         |
| P2     | [ranked_index.rs:156](../../../crates/studio-storage/src/ranked_index.rs#L156) 直接依赖 input_rows / scores / main_rank / rescue_rank 等列；RankedScope 携带 RankingFilter                                                                | 新增审美排序会牵动现有 MetaRecall 数据模式、查询与浏览，旧字段容易被复用成不同含义       | 抽取最小的“有序成果读取”能力，新美学成果用独立类型；旧成果通过适配器读取，不迁移重算历史评分                         |
| P2     | [App.tsx:493](../../../apps/desktop/src/app/App.tsx#L493) 负责项目事件与多类缓存刷新；[modules.tsx](../../../apps/desktop/src/app/modules.tsx) 已有模块入口                                                                               | 若每次 API 调用都变成顶层 Job 和全局刷新，任务列表与状态传播会膨胀                       | 用户看到评审计划和阶段；内部批次用专门分页。进度合并推送，局部查询失效，新模块自持运行页与结果页                     |

上述重构应围绕具体接口和风险展开。保留 Rust/Tauri/SQLite、来源适配器、SDK 和现有契约生成。当前没有证据要求换语言、整体改数据库或先建设分布式平台。
