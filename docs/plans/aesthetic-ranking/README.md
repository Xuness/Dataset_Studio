## 已确认的需求与约束

- 利用多模态大模型同时比较多张图片，返回结构化相对排序；16 图是用户已有测试中的成本与表现折中点，作为常规批量目标。
- 允许 A=B>C=D 这样的并列梯队，不强制每批给出全部严格先后关系。
- 第一版优先让**全量图片具有尽量稳定的相对名次**，预算不能只服务 Top-K 淘汰线。Rating 之间独立排名。
- Rating 是硬隔离；年份是弱分组，同年比较较多，同时允许跨年比较。
- 支持多阶段和多模型。例如全量平均曝光 4 次后，Top 20% 额外曝光 2 次；或将 Top 25% 交给更强模型。数字是流程示例，不是已确定的默认值或可靠性保证。
- 支持从排名结果灵活生成下一阶段工作集，并针对信息不足、判断冲突等情况追加评审或进入人工复核。
- 模型可单独提名达到顶级标准的图片，提名图片仍参与普通排名；默认进入**保护候选池，等待强模型或人工复核**，不直接成为最终精选。
- 允许先用强模型遍历候选集，保存独立评审依据与顶级提名，再进入后续筛选。
- 需要评估百万图、几十到上百个 API 在途请求，以及每请求十几张图片的传输压力。必要时新增独立评审数据库是可接受的方向。
- 本机上行约 40 Mbps，由用户提供，未进行测速；数据湖采用 WebP。采样大小和由此推导的传输预算见存储文档。

## 当前建议与未定事项

以下为审查时的整体建议；第一阶段已采用独立评审库和执行器，具体边界以 ADR 0025 为准。

原建议保留已有分层，新增独立评审执行器、持久批次/尝试账本、可重放统计状态、不可变排名快照和受字节预算控制的图片管线。第一阶段已使用 SQLite + 专用写入线程；是否分区、何时引入 PostgreSQL，仍由实际负载验收确定。

以下内容仍需试验：最终 System Prompt、审美与顶级标准、生产估计器选择、名次稳定性目标、主动采样比例、图片规格、商业模型与预算、远端文件复用。同梯队的 v1 语义已采用“无有意义差异”，输入采用有大小上限的原始图片；第二阶段 Top 边界保留整个计算同分组。这些实现选择不代表已经完成质量校准。

历史正文中的曝光次数和算法选择仍是示例或建议；当前已实施的部分及限制，以两份阶段说明和 ADR 为准。

## 现有基础与证据边界

截至 2026-09-17 审查时，LLM 协议层与 System Prompt 预设已实现，业务排序解析、评审调度、统计排名和复核功能尚未实现。2026-09-17 通过了 149 项 Rust 测试、17 组集成脚本及 6 种供应商/协议组合的 16 图报文探针；上游均为本机 mock，未验证商业模型的审美质量。

独立 SQLite 微基准在百万候选表上取得约 364–619 份模拟结果/秒，但每场景只写入 1 万份结果，省略了图片、HTTP、完整状态机和统计拟合。WebP 索引分散样本平均约 251 KiB，按 28 Mbps 规划预算推导的传输能力不是网络实测。完整条件和原始精度保留在证据摘要中。
