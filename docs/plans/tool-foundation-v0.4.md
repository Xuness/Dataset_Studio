## 目标与优先级

让新工具通过标准接口进入应用，把成果作为有身份、有版本、可复用的项目数据留下来；工具切换与重启能够恢复编辑上下文，读取服务能在交互与后台工作之间安排资源。

四项均纳入下一阶段方向，按工程依赖分批实现和验收。前三项保持 P1，读取调度与持久缓存保持 P2；资源与取消接口需要在算子执行接口设计时一起明确，持久缓存和物理读取优化随后接续。

项目仍是持久化工作空间，工作集是项目内数据对象，工作区布局负责呈现。工具入口、中央视图与上下文面板可以自由组合，工程实施顺序不规定用户使用工具的顺序。

## A. 功能模块与算子注册

### 前端模块协议

- 模块声明稳定 ID、版本及可贡献的入口、中央视图、上下文面板、命令和草稿模式。
- 应用框架负责组装与共享项目上下文；模块通过公开 SDK、对象引用和命令协作，不直接修改其他模块的私有状态。
- 界面模块与计算算子分别注册。多个入口可以使用同一算子，一个视图也可以组合多个服务。
- 首轮采用应用内的显式注册，检查重复 ID、未知贡献类型及版本兼容；按需加载视图。不以运行时第三方插件系统为前提。

### 后端算子协议

- 算子声明稳定 ID、实现版本、参数结构版本、支持的输入类型与范围、必需字段、输出类型与结构版本。
- 声明取消、检查点恢复、重试、局部失败和确定性能力，以及 CPU、内存、磁盘、GPU 等资源需求。界面只呈现执行器实际支持的能力。
- 建立统一的参数校验、输入准备、执行分派、进度、错误和成果交付端口。小型控制消息带协议版本，大型输入输出使用有界流或受项目管理的文件引用。
- 提交时固定规范化参数和实际输入。涉及元数据时，同时冻结所需字段值、对象粒度、所用观察及版本依据；不能只保存 AssetKey 和来源水位并声称可复现历史字段。
- 逻辑任务、执行尝试、算子版本与输入版本分别记录。幂等重试继续使用已固定输入；算子升级后不能静默更换旧任务的实现或参数语义。
- 将现有 core.manifest 接到通用接口，保留其成果校验、检查点、取消和旧任务恢复能力。通过第二个轻量算子验证扩展接口，而非仅为清单任务更换名称。

## B. 成果与派生数据管理

### 项目成果目录

- 成果具有项目所属身份、类型、结构版本、发布状态、成员或行数、文件清单与内容校验；支持一个任务产生多个成果。
- 保存算子及版本、规范化参数、实际输入引用与内容校验、字段与观察依据、执行尝试，以及适用时的模型标识。缺失的旧依据明确标记，不能补造。
- 成果版本发布后保持可辨认，重新运行生成新版本。保留现有查询结果的成员、来源版本和释放语义，明确查询成员材料与计算成果之间的关联。
- 暂存、验证、文件落位和数据库登记采用可恢复的发布协议；处理发布中断、未登记文件和失败暂存，不把部分输出标为完整成功。
- 提供经 SDK 访问的成果列表、详情、类型化分页读取和输入解析能力。成果可供其他工具继续使用，无需用户在功能页间手动导出导入。

### 派生字段与数据关联

- 区分资产、来源记录和观察粒度；派生字段声明其附着身份、类型、单位、缺失语义、版本与来源。多观察字段必须先定义判定或归约规则。
- 原湖字段与项目派生字段使用明确命名空间。标注、评分和人工修正写入项目成果或覆盖层，保留原数据湖只读边界。
- 大型列式结果使用有模式的批量材料，项目数据库保存索引和关联；具体格式按读取需求验证后确定，前端不加载全部行。
- 让受支持的派生字段接入字段目录、查看、查询和任务输入。输入协议分别表达成员范围和所需成果版本，延续现有 ScopeRef 的项目隔离及固定成员语义。
- 区分未计算、字段缺失、单项失败、范围外对象与实际零值；部分成果如允许消费，必须显式声明覆盖范围和使用规则。
- 对成果的删除和清理检查工作集、任务、派生字段及其他成果的引用。可重建缓存与项目权威成果采用不同生命周期，缓存清理不能删除成果。

首轮先打通清单成果和一种确定性标量成果。向量、派生图片、完整模型运行环境及复杂人工合并策略按实际工具需求继续扩展。

## C. 工具草稿与会话恢复

| 状态 | 计划归属与恢复语义 |
| --- | --- |
| 项目来源、选择、工作集、已保存查询、任务与成果 | 引擎权威状态，沿用各自版本规则 |
| 尚未提交的工具参数与输入配置 | 项目内草稿；按模块和草稿/实例身份隔离，带模式版本与并发修订 |
| 当前功能、查看范围、焦点和浏览位置 | 项目及工具会话状态；恢复前验证引用是否仍有效 |
| 面板布局、密度、主题等个人偏好 | 应用偏好/布局服务；不写成数据湖事实或任务输入 |

- 为已有 drafts 表接通应用端口、版本化持久化、DTO、SDK 和前端恢复流程。新增格式时迁移保留旧内容，不直接覆盖无法理解的草稿。
- 有界、合并的自动保存应反馈保存中、失败和冲突；项目切换时正确处理在途写入，晚到响应不能覆盖其他项目或较新的编辑。
- 区分未提交编辑、已保存查询定义和已提交任务参数。恢复草稿不自动运行任务，也不改变历史任务输入。
- 保存输入引用及其版本，明确“使用当前选择”和“已经固定的范围”的区别。原选择修订、结果或成果已失效时，提示重新绑定，不能悄悄换成当前成员。
- 持久化浏览位置采用有界状态和稳定锚点；失效游标、已释放结果、未知模块、缺失对象和离线来源都有可解释的回退方式。
- 显式打开项目后恢复该项目会话，保持 0.3 的项目租约规则；读取最近项目摘要不触发全部项目的会话加载或持锁。
- 验证正常关闭、页面重载、引擎重启和异常退出后的恢复边界。重启恢复已保存草稿，正常切换或关闭应完成已接受的保存；无法保留的未落盘编辑必须如实说明。

首轮接通查询编辑和清单工具的参数/输入草稿，并恢复已有浏览方式、范围、焦点和面板状态。完整工作区布局编辑器留给实际界面需求。

## D. 读取调度与持久缓存

### 统一读取调度

- 将前台浏览、单图预览、元数据、查询、后台任务和预取纳入可观测的资源协调接口；算子通过资源端口读取来源。
- 定义请求取消、优先级、队列长度、并发、字节和解码预算。高优先级交互可以更快获得资源，同时保证后台工作不会长期饥饿。
- 同一资源的请求可以合并；某个使用者取消时只撤销其订阅，最后一个使用者离开后再取消可中断的共享工作。
- 页面或范围切换时取消失效的等待和预取。前端停止显示结果与后端停止实际读取分别验证，保留操作系统 I/O 不能硬中断的边界。
- 按实际资源区分 SSD 索引、机械盘媒体、CPU 解码和原生查询预算。批处理在有界窗口内按包路径/偏移组织物理读取，保持逻辑成员、结果顺序和检查点语义。
- 不在机械盘上默认递归扫描媒体目录或预热全湖；读取计划使用既有索引与明确范围。

### SSD 持久缩略图缓存

- 使用应用管理、可配置的 SSD 缓存目录，保存可重建的预览材料和索引；与项目成果、原湖和升级备份区分。
- 缓存键包含可靠的来源/内容身份、尺寸与变换参数、渲染和编码版本。按来源能力处理更新与重新关联，不能只凭本机文件路径复用旧预览。
- 命中缓存仍验证当前项目的访问范围；共享缓存不能绕过项目归属校验。明确离线时可用缓存和无法验证的新鲜度信息。
- 原子写入并校验材料，恢复未完成写入，识别损坏条目；同一键并发生成应合并。
- 配置磁盘配额、淘汰策略、在用条目保护及失效清理，启动维护按批执行。缓存被清空后可以重建，不影响项目内容。
- 建立与可见范围相匹配的有界预取，记录命中、未命中、磁盘读取和解码开销，依证据调整策略。

## 建议实施顺序

1. 明确模块、算子、输入、成果、草稿和资源请求的公共协议及版本规则；定义兼容迁移与验证夹具，保持现有分层。
2. 建立模块与算子注册，迁移现有清单任务；接通最小成果目录和可恢复发布，使执行与成果协议形成完整链路。
3. 增加一个不依赖模型的确定性标量算子，验证必需字段冻结、派生字段读取/查询和成果再次作为工具输入。
4. 接通查询与清单草稿、项目会话和布局偏好的恢复，验证与实时项目版本、已提交任务的边界。
5. 在前述资源接口上实现统一读取调度与 SSD 持久缓存，针对并发交互和批处理验证公平性、取消和物理读取策略。
6. 完成异常恢复、旧项目迁移、原生窗口与分级规模验证，更新实际实现状态和使用说明。

步骤 2–3 的演示链路只用于验收共享接口。用户仍可独立使用各工具；一个新功能不需要被嵌入预设的数据处理流程。

## 验收标准

1. 至少两个算子通过同一注册和执行协议工作；未知版本、重复身份、非法参数和缺少必需字段被明确拒绝，能力声明与实际行为一致。
2. 原清单任务的输入固定、幂等、取消、检查点与成果校验继续通过；所需元数据字段在来源更新后仍使用冻结值和观察依据。
3. 成果经过统一目录发布、按类型分页读取，并能被第二个工具或查询服务引用；字段粒度、覆盖范围、版本和缺失/失败语义清楚。
4. 发布各阶段中断可恢复，不能出现“成功但成果不可读”或重复发布；成果引用检查和缓存清理不会破坏持久数据。
5. 两个项目的草稿、输入范围和查看状态互不污染；正常关闭、重载、异常退出及版本升级后恢复符合声明，冲突与失效引用可见，恢复不自动提交任务。
6. 请求合并、取消、交互优先级和后台公平性有可重复的并发夹具；记录实际后台读取是否停止，不能只以界面不再更新作为取消证据。
7. 缩略图跨窗口和引擎重启能够命中持久缓存；参数或内容版本改变、缓存损坏、超配额、来源离线及清空缓存均有验证；跨项目权限校验始终执行。
8. 延续项目 v1/v2/v3 和注册表的兼容策略，模式升级前隔离运行目录并保留一致备份；旧选择、工作集、任务、查询、事件及成果引用逐项核对。具体新模式号随迁移设计确定。
9. 合成大范围测试与真实湖指定样本分别记录队列等待、读取/解码耗时、内存、缓存命中率、磁盘读取量和取消延迟。真实规模按小样本到明确预算逐级扩大，区分冷暖缓存、合成与物理磁盘证据。
10. 公共协议变更生成契约；相应阶段运行 pnpm check、pnpm test:integration 和前端构建，在实际 Tauri 开发窗口验证新增能力。每批实施有清晰的本地提交与验证记录。

## 实施约束与后续扩展

保持 domain/application 与 HTTP、数据库和 Tauri 的边界；前端功能依赖公开 SDK。按实际职责提取模块，避免先创建大量空包或把通用能力继续堆入 App、单一路由及单一执行器。

继续使用开发脚本、Debug 编译和热更新。原数据湖只读，项目材料和可重建缓存各自管理；日志、测试材料和报告位于 `.local`，不提交真实项目或二进制。

运行时第三方插件、完整 Python/GPU/模型依赖管理、分布式执行、任意成果格式、复杂布局编辑和全湖长期压测不作为本阶段首批验收的前置条件；相关接口仅声明实际支持的能力。后续工具可以在本阶段协议上继续扩展。
