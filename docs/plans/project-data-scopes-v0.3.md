# 0.3 开发计划：项目数据范围层

状态：已完成（2026-09-08，0.3.0）。四项 P0 能力、最小交互、兼容迁移和验收均已实现。实际证据、当前限制和日常项目升级核对见 [0.3 验证记录](../verification/verification-project-data-scopes-v0.3.md)，持久化与接口语义见 [设计决策 0003](../decisions/0003-project-data-scopes.md)。

基线：0.2.0，项目清单 v1、项目数据库 v2。上一阶段交付见 [0.2 验证记录](../verification/verification-project-data-layer-v0.2.md)。

## 目标

让查询、选择、工作集和任务通过明确的数据范围协作，避免把大型数据集的全部成员交给前端管理。同时完善项目生命周期，使单个项目的故障不会阻断其他项目。

工程建设按依赖安排顺序。用户仍可以自由选择工具与组织工作，不预设固定处理流程。

## 本轮范围

本轮逐项实现四项 P0 基础能力，并提供一个小型查询入口，接通现有清单任务进行验收。

### A. 字段目录与查询协议

- 建立可由 SDK 获取的字段目录，声明字段身份、名称、类型、单位、缺失语义及来源依据。
- 适配器明确声明可查询、可排序的字段与操作；显示能力和查询能力分别表达，不把可以展示的字段自动当作可高效查询的字段。
- 建立带版本的查询定义，包含来源范围、条件、排序和观察判定规则；后端验证参数、类型、操作及复杂度。
- 首轮支持一组有实际用途的字段与条件，以存储属性及已接入的常用元数据为基础；具体支持集合由能力目录如实返回。
- 查询条件通过受控表达式编译，前端不提交任意 SQL，功能模块不读取数据库文件。
- 多条来源记录或历史观察参与查询时，判定策略必须明确；合取条件不能无意间从不同观察各取一个字段而拼出匹配。
- 空值、空字符串、空标签、false 与条件不匹配保持区别；来源不支持某字段时明确报告，不能静默当作零结果。
- 排序必须稳定并有身份作为最终比较依据。多值字段没有已定义的归约语义时，不声明支持其排序。

### B. 查询结果引用

- 后端建立项目所属的结果身份，保存规范化查询定义、来源身份与版本、排序、进度和完成状态。
- 前端使用结果引用与有界游标分页，不拉取全部对象 ID，也不使用大 OFFSET。
- 查询结果统一以现有 AssetKey 表达存储对象，关联到多条观察时不重复计数成多张图片。
- 区分可重新求值的查询定义、已经产生的结果及冻结的成员范围。来源版本变化时，给出失效或重新计算规则，不把版本水位称为历史快照。
- 较长的结果构建在后台进行，支持取消和有界内存；明确中断后的恢复或重建行为，不把部分结果发布为完整结果。
- 数量区分准确值、计算中和未知；任何结果限制或截断必须可见，不能把有上限的子集称为全部匹配结果。
- 应用自己的结果材料具有受控位置和生命周期，支持显式释放与引用检查；正在被工作集或任务使用的内容不能被误清理。

### C. 统一作用范围与选择模型

- 定义公开的范围引用，使工具可以显式使用数据湖、工作集、查询结果或当前项目选择。
- 焦点对象、项目选择和工具输入范围分别管理；查看图片、切换元数据观察或翻页不改变选择。
- 支持选择全部查询结果并排除少量对象，成员判定和计数由后端完成，不要求前端枚举所有成员。
- 增加范围的替换、添加、移除和必要集合运算，明确去重、来源身份、版本冲突及跨项目访问边界。
- 保留旧选择和工作集成员。保存固定工作集时冻结实际成员；保存查询定义的语义与固定成员分开。
- 任务提交显式绑定输入范围与版本。执行前冻结真实成员，后续修改选择或刷新查询不改变已提交任务的输入。
- 需要查询依据时保存相应定义、来源版本及观察规则。当前清单任务继续使用其实际需要的输入；涉及元数据的后续算子还需冻结必要字段，不能仅依靠水位追溯。
- 接入现有浏览、工作集与清单工具，保留原有显式成员选择的使用方式。

### D. 项目生命周期与故障隔离

- 分离最近项目摘要、显式打开、当前已打开状态和后台工作状态。列出项目不取得全部项目的写锁，也不触发所有项目升级。
- 完善关闭与释放规则。关闭视图和终止后台任务分开；有在途请求、结果构建或任务时，不默默取消任务或丢弃状态。
- 处理文件锁与并发请求的边界，避免关闭后在途请求继续无主写入，或调度器立即把已关闭的空闲项目重新打开。
- 恢复和调度逐项目隔离错误；某个项目离线、损坏、被占用或版本过新，不阻断引擎启动、其他项目列表或健康项目的任务。
- 避免每一轮调度无差别打开全部最近项目；保留已确认后台任务的恢复能力。
- 提供明确的来源重新关联入口，校验新位置仍是同一个逻辑数据湖，保留项目引用及成员身份。
- 区分本机共享来源位置与项目引用；位置调整的影响范围在界面中说明。

## 最小交互验收

在已有应用框架中增加查询入口与结果范围展示。用户可以设置受支持条件、看到构建状态、跨页查看结果、选择全部结果并排除个别对象，再保存工作集或把范围交给现有清单任务。

这个场景用于串联验证基础接口，不规定用户以后必须按该顺序工作。查询界面只呈现已实现的能力。

## 代码组织与兼容性

- domain 放置字段、查询、范围和生命周期语义；application 定义用例与端口；存储和来源实现分别承担项目持久化与只读读取。
- HTTP 路由负责校验与组装，避免继续把查询规划、集合运算和任务准备堆入单个路由文件。
- 前端查询状态、数据访问和显示组件分开；功能模块使用公开 SDK，不直接访问 Tauri 或数据库。
- 公共 DTO 由 Rust/Utoipa 生成 OpenAPI 与 TypeScript；不手工修改生成文件。
- 项目及注册表的模式变更使用明确升级步骤，保留一致备份、回滚材料和旧版本夹具；旧项目 ID、来源、选择、工作集、任务、事件及成果关联保持兼容。
- 开始模式变更前隔离开发运行目录，防止未验证的热更新自动升级日常项目。
- 保留 Windows 开发启动脚本及热更新。此阶段继续使用 Debug 开发模式，不构建发布包或安装器。
- 所有临时日志放在 .local/logs，截图和报告放在 .local 的专用目录。原数据湖只读；不提交真实项目、缓存、日志、运行库或二进制。

## 验收清单

1. 字段类型、查询操作、空值和不支持能力均有已知答案的夹具；明确验证多观察判定和同一内容去重。
2. 覆盖稳定分页、结果版本变化、取消/中断、不完整结果拒绝发布和跨项目引用拒绝。
3. 覆盖多页及较大量成员，证明全选/排除通过引用完成，前端请求不随总成员数携带全量 ID。
4. 验证集合运算、计数、旧显式选择、固定工作集以及任务冻结输入的一致性。
5. 在修改选择、刷新查询或重启引擎后，已提交清单任务仍使用固定成员并产生无重复、无遗漏的成果。
6. 夹具覆盖健康项目旁存在离线、损坏、被占用与未知版本项目；健康项目可以打开、运行和恢复任务。
7. 验证列出项目不隐式持锁/升级，关闭释放与在途任务的行为符合已定义语义，来源重关联拒绝错误的数据湖身份。
8. 验证旧项目升级和重复打开，逐项核对已有选择、工作集、任务与成果。
9. 真实 Danbooru 查询先检查计划与小样本成本；记录耗时、资源限制和实际版本边界，不把小样本通过描述成千万级压测通过。
10. 在真实 Tauri 开发窗口中验证查询、范围选择、工作集、任务与错误状态；说明实际后端验证与受控 UI 状态测试各自证明的内容。
11. pnpm contracts、pnpm check、pnpm test:integration 及相关前端构建检查通过；更新实现状态、使用说明与验收记录。
12. 完成范围清晰的本地 Git 提交，保留可直接继续使用的日常开发环境。

## 建议实施顺序

1. 隔离运行环境，建立旧项目与异常项目夹具，落实必要的模式升级。
2. 先完善项目列表、打开/关闭和恢复调度的故障隔离，确保后续开发与迁移不会相互阻断。
3. 实现字段目录与查询定义，审计受支持查询在真实来源上的读取计划。
4. 实现结果引用、后台构建、分页、版本处理及生命周期。
5. 实现选择与工具范围，接通工作集、清单任务与查询界面。
6. 完成真实样本、原生窗口与回归验证，恢复日常开发入口，更新文档并本地提交。

## 后续范围

通用模块/算子注册、完整成果与派生列目录、完整工具草稿服务、持久预览缓存及更复杂资源调度继续作为后续基础工作。仅在本轮四项能力确实需要时提取最小共享接口，不将这些后续方向描述为已经实现。

四项剩余基础层的代码现状、开发边界、实施顺序和验收标准已整理为 [下一阶段 0.4 开发方向](tool-foundation-v0.4.md)。前三项保持 P1，读取调度与持久缓存保持 P2，按依赖分批推进。

## 本轮交付边界

查询界面当前支持单湖条件编辑，SDK 协议支持最多 8 个来源；只声明已经实现的字段和身份排序。原生查询按批输出，较大元数据连接可能在资源预算内明确失败。真实数据验证使用指定身份和帖子的小范围条件，未进行千万级全量或冷缓存压测。这些边界保留在能力目录、使用说明和验证记录中。

日常项目由正常打开链路从数据库 v2 升级为 v3；旧选择、工作集、任务、事件及成果逐项核对一致。默认开发启动脚本已恢复并验证，继续使用 Debug 开发环境。
