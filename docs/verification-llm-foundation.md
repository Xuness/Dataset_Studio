# LLM 基础层实施与验收

日期：2026-09-16。

## 交付

“设置 → API 与模型”已接入现有设置窗口，包含：

- 供应商连接新增、编辑、停用、删除与 API Key 设置/清除。
- OpenAI 兼容、OpenAI、OpenRouter、Gemini 四类服务配置。
- 每个连接独立的模型配置；Chat Completions、Responses、Gemini 原生协议。
- 显式获取和搜索远端模型、手动添加模型；目录刷新不覆盖已有参数。
- 后端参数描述驱动的逐模型参数编辑，以及命名参数预设。
- 网络超时、并发、请求间隔、有限 429 重试、HTTP(S) 代理及非敏感附加请求头。
- 显式发送固定消息的流式调用检查，显示结果、结束原因、用量和诊断。

后台提供调用准备、完整响应、流式响应和取消接口。应用服务、远端协议实现、存储、本机 DTO、SDK 和设置组件分开组织。Prompt 保存、管理、变量替换、拼接及具体业务处理均未纳入本阶段。

架构决定见 [0023](decisions/0023-llm-foundation.md)，后续功能模块的使用方式见 [接入说明](architecture/llm-integration.md)。

| --- | --- |
| `pnpm contracts` / `contracts:check` | Rust DTO、OpenAPI 与 TypeScript 一致 |

| `git diff --check` | 通过 |

专项覆盖四类连接的目录读取、完整与流式推理、独立参数、覆盖与显式省略、错误命名空间、版本冲突、刷新失败保留旧目录、断流与流内错误、并发控制、注册前/执行中取消、有限 429 重试、不重发 500、晚到刷新保护，以及引擎重启后的配置和凭据恢复。

Rust 检查覆盖精确协议字段映射、Responses assistant 历史输入、纯工具消息、null error 与未知用量、工具参数分片拼接、Gemini 函数签名、UTF-8/SSE 分片与截断、凭据损坏和旧注册表迁移。显式省略 `store` 不会被适配器默认值重新加入。

界面检查验证设置页面切换时保留连接草稿、连接/目录管理、0 值与独立模型参数、命名预设、调用检查，以及关闭并重新打开设置后读取已保存配置。

## 证据与边界

本机长期验收目录：`.local/reports/llm-foundation-20260916/`。包含 verification.json、命令日志、各次验收报告及设置界面截图。

- LLM 最终集成报告：`integration-llm-1789555153515/report.json`。
- 界面报告与截图：`smoke-llm-ui-1789554355909/`。
- 初次 UI 检查遇到两个“关闭”按钮匹配的夹具问题，调整为定位设置页脚按钮后通过；早期失败报告保留用于追踪。

所有外部供应商请求均发往隔离的本机 mock 服务器，没有使用真实商业 API Key 或产生商业 API 调用。验收证明本地调用链与模拟协议行为；不证明特定账号的权限、额度、在线可用性或任意供应商参数组合。

Windows DPAPI 凭据实际执行加密、重开解密和损坏检测；注册表及凭据文件检查未包含夹具明文密钥。其他平台没有凭据明文回退。

应用注册表升级至 v3 并生成一致备份；项目数据库和原始数据湖格式保持不变。上述工作树验收包含既有的排名改动；本次基础层提交范围独立于这些排名改动。

提交前从暂存源码导出隔离目录，单独通过引擎编译、契约生成和 12 项 LLM 集成检查。提交中的契约由该源码生成；与工作树契约的差异仅为原有排名位置参数及说明。相关证据位于验收目录的 `commit-scope` 子目录。

已归档必要证据并逐文件、逐空目录清理本轮 23 个测试目录，释放约 975 MiB；没有使用递归删除命令。清理结果记录在验收目录的 verification.json。
