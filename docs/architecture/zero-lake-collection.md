# 从零建湖与按需采集

更新日期：2026-10-07。支持 Danbooru、Gelbooru、Yandere 和 Pixiv。无需已有数据湖、全站元数据或发行归档。运行环境配置见[更新服务](../../services/lake-worker/README.md)。

## 创建与浏览

1. 打开或创建项目，在“工具 → 数据湖”进入工作台。
2. 点击“创建 / 登记数据湖”，选择站点并勾选“创建新的空湖”。填写两个独立的空目录：图片归档通常放容量盘，在线索引通常放 SSD。默认勾选“添加到当前项目”。创建本身不访问源站。
3. 选择左侧的湖，点击“新建更新”，设置范围、保存策略和本轮预算，预览后提交。只需要元数据时选择“仅元数据”。
4. 已发布图片可在项目资料浏览中查看；Booru 的“帖子元数据”视图同时列出只有元数据、尚未下载图片的帖子。

已有湖取消“创建新的空湖”后核验登记，也可在详情点击“添加到当前项目”。创建被中断时，用原表单重试即可接续；如果路径已经包含其他数据，程序会拒绝覆盖。

## Booru 标签与重复采集

“全部包含 Tag”“任一包含 Tag”“排除 Tag”分别表达 AND、OR、NOT，Booru 标签按空格或逗号分隔。作者和角色使用站点实际标签名，例如全部包含 `artist_name character_name`，排除 `comic`。界面结束 ID 包含该帖子。

远端发现至少填写一个正向标签；程序按单个正向标签请求候选，在同一条返回元数据上判断完整组合条件。OR 可以分支请求并去重。有效候选元数据都会保留，只有满足完整条件的条目进入图片处理。无需先扫描全站。

默认允许复用 24 小时内相容的查询覆盖，可调整有效期或选择全部重新请求。例如完成 `A AND B` 后改为 `A AND C`，已覆盖的 A 范围可以复用。只有零散 B 帖子不能证明 B 范围完整，必要的缺口仍会请求。复用显示原获取时间；接受旧扫描也意味着该窗口内的远端改标签可能尚未反映，需重新请求时使用全部刷新。

任务的元数据扫描、媒体处理和全站追新各自记录进度。稀疏 ID、不同批次和不同采集时间可以共存；限定查询不推进“补充新帖”的全站水位。预算耗尽表示本轮停靠，在原任务继续即可接续。

## 从已有元数据补图片

在工作台视图切换到“帖子元数据”，按标签、ID 或“只看尚无图片的帖子”查询，选择若干帖子后点击“为已选帖子新建任务”；也可对整个匹配条件新建任务。表格按固定读取版本分页，选择会带入该版本、筛选条件和帖子 ID。

在任务中选择原文件或所需编码配方后提交。此路径优先使用已入湖的元数据与媒体地址；导入记录缺少下载输入或地址已失效时，才按需刷新对应帖子。单纯重用元数据不会改写原观察时间。

“尚无图片”表示当前帖子没有已关联图片。需要为已有图片生成另一配方时，取消该条件并选择相应保存策略。目录版本过期时刷新目录、重新选择；周期任务按每次运行时的本地版本求值，不长期引用一次目录浏览的临时版本。

## Pixiv 作者与作品

Pixiv 从作者或作品 ID/链接开始，可选关系扩展；本次标签条件只筛选该范围中的作品。每行填写一个完整标签，名称中的空格保留。标签不明确的响应保留原文并显示需要检查。

先运行仅元数据任务，再以作品 ID 新建图片任务并允许复用近期元数据，可以直接使用仍然相容、完整的逐页/动画清单补图。详情新鲜但清单缺失时只请求清单；过期或访问条件变化时重新核验。作者目录仍会根据采集定义复查，已排除作品的元数据也保留，便于后续修改条件。

作者目录覆盖、作品详情、媒体清单和文件完成度分别记录。Pixiv 入口与 Booru 元数据目录各自遵循来源语义；更多账号、周期和 Ugoira 行为见[来源采集接入](source-collections.md)。

## 验证边界

本轮使用隔离引擎、真实归档/在线读写和模拟源站验证四源空湖、选择与补图、缓存复用、预算接续和故障恢复。没有执行真实全站采集或容量压测。结果见[阶段验收](../verification/2026-10-07-zero-lake-collection.md)。
