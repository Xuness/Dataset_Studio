## 已形成的运行链路

React 功能模块 → 统一 SDK → 回环 HTTP / 事件 / 二进制媒体 → Rust 本机引擎 → 项目仓储与来源适配器。

数据清单任务由独立的 Rust 执行器进程运行。Windows Job Object 保证引擎退出时其工作进程不会成为无人管理的写入者。任务通过已落盘的输入与检查点恢复。

## 实际数据模型

基础版本枚举 Danbooru catalog.sqlite 中的储存对象，其身份是数据湖 ID 与内容 SHA-256 的组合。通过该库的只读事务读取对象行和水位。跨页使用版本游标，发现来源变化则要求重新查询。

该能力没有把 DuckDB current_posts 当作完整归档，也没有声称实现了跨 SQLite / DuckDB 的历史元数据快照。后续条目与观察层接入时必须另行建立一致读取契约。

数据清单任务在项目事务中固定选择成员，分批读取对象投影并记录来源版本。输入以 JSONL 保存，使用 SHA-256 校验；工作计划仅保存受控相对路径。结果逐行验证后发布，发布中断可以从最终文件与任务状态协调恢复。

## 验证边界

Rust 测试覆盖来源读取与项目持久化边界。进程集成测试主动终止引擎，在中文目录中移动项目后重新打开，验证任务从检查点恢复且无重复或遗漏。

前端与真实本机引擎已完成项目创建、添加来源、选择、保存工作集、运行任务与查看成果的操作验证。真实 Danbooru 以 48 项单页读取验证媒体通路；这不等价于千万级完整压测。

## 后续扩展接口

当前核心保留 SourceAdapter 和 ProjectRepository 端口。前端的浏览、项目表单与任务面板分模块组织，均依赖公开 SDK。执行器的 version、固定输入、参数、输出与恢复状态形成了首个运行协议。

尚待扩展的能力包括算子注册体系、多类型成果与派生列、复杂元数据查询、基于结果引用的批量选择、持久预览缓存、更多调度策略和完整工具草稿服务。
