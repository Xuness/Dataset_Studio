# 0.8 UI / UX 检查：任务可见性与后续操作

2026-09-09。触发场景：用户对完整 Danbooru 数据湖提交 MetaRecall 评分后，难以判断任务是否已提交、是否仍在运行，以及何时可以查看结果。

## 现场核实

在用户的原生 Dataset Studio 窗口与引擎 API 中核实到同一项任务。固定输入为 11,493,687 项；初次查询时处于 `metadata_snapshot`，已读取 7,629,312 项（该步骤约 66.4%）。随后观察到元数据读取继续增长并进入分级评分。这些百分比仅代表对应步骤，不代表全程完成比例。

原界面的问题：

1. 提交后只出现 33 px 高的一行普通文字，没有明显的运行区与进度条。
2. “计算排名”仍可再次点击，当前配置也可继续修改，反馈与实际固定输入不一致。
3. 项目任务用 `job.completed / job.total` 画条；这两个数会在元数据准备、分级评分之间改变含义，不能用于多阶段任务的总进度。
4. 输入已固定后，范围选项与属性区仍显示“待计算”。
5. 结果加载、尚未运行和运行中共用空状态；结果按钮可能在成果引用加载前可点。
6. 切换页面后只剩一个运行任务数量，完成后的入口也缺乏状态说明。任务读取失败会与没有任务混淆。

## 本次改动

- 排名视图顶部固定显示任务区：提交反馈、状态、输入数量、提交时间、从提交至今的时间、四个处理阶段、当前步骤进度和后续操作。阶段内的数据条使用后端 `stage` 的真实计数。
- 热度分布、分数计算、索引、校验与成果保存等没有可用处理比例的步骤显示活动条。只有 `succeeded` 才显示整项任务完成；工作进程的 `complete` 消息显示为等待成果校验。
- 运行期间禁用重复提交并锁定配置；提交被接受后立即放入任务缓存，同时保存任务关联。重新打开视图时可重新关联项目中正在运行的排名任务。
- 已固定且范围版本一致时，输入选项和属性区使用任务的实际输入数量。
- 结果页区分运行中、加载中、失败、取消和空白状态。完成后自动加载成果；“查看结果”在成果可用时启用，读取失败可重新加载。
- 项目任务优先显示执行中的条目，并复用相同的步骤进度口径。取消、重试与保存按钮有操作反馈；从任务打开排名后关闭遮挡内容的任务面板。
- 底部状态栏持续显示当前步骤，切换功能后仍可看到进度；没有活动任务时保留最近一项任务的完成、失败或取消状态。
- 状态读取中断时保留上次数据，并明确提示当前为旧记录，恢复连接后自动更新。

本次使用现有任务协议，项目格式、公式与引擎执行流程均未改变。公共 UI 层提供任务展示语义与进度组件，排名模块、项目任务与全局状态栏共用这些展示规则。

## 仍需完善的内容

后续真实使用已复现大工作集排序超时与保存入口范围混淆；性能与数据来源证据详见 `performance-metarecall-workset-v0.8.md`。

| 优先级 | 问题与依据 | 下一步 |
| --- | --- | --- |
| P1 | 分级评分会多次进入同一个步骤；当前 `JobStage` 没有分级、轮次、阶段开始时间或最后进度时间。界面不能可靠说明“当前是哪个分级”，也不能区分长计算与执行器失去响应。 | 扩充引擎任务观测信息，再展示具体分级、轮次和真实心跳；保持旧引擎兼容。 |
| P1 | 当前任务协议只有提交时间，没有开始、结束时间。 | 增加持久化执行时间与阶段耗时，再显示精确总耗时和基于实测的剩余时间；当前只显示“已提交多久”。 |
| P2 | 成果选择器仅用时间和数量命名，相同范围的不同公式设置不容易区分。 | 增加用户可命名的运行记录，以及固定参数摘要、来源版本与历史成果比较入口。 |
| P2 | 全局工具栏的“存为工作集”“生成清单”依赖当前范围；在排名页面上，其作用对象不如局部“存为工作集”直观。 | 为全局动作显式显示目标范围，并检查浏览、查询、排名三个视图的操作上下文。 |
| P2 | 百万级榜单主要依靠分级、排序与前 N 名筛选；完成后如何缩小候选、对照分数和保存工作集，仍需要用户自己探索。 | 设计结果阅读流程，在榜单与统计诊断间提供有范围说明的联动入口。 |
