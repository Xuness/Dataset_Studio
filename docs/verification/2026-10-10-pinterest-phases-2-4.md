# Pinterest 第二至四批交付与验证

日期：2026-10-10。实现范围是匿名可访问的静态原图，包括已支持的单图故事封装。采集、下载、归档、重建、原文件读取与工作台使用同一套正式模块；没有另建抓取原型，也没有改动真实生产湖或启用生产周期计划。

## 已交付

| 批次 | 当前能力 |
| --- | --- |
| 第二批 | 图版和分区链接解析、成员分页、分区列表、独立发现快照、逐项列表清单、`none/sample/all` 元数据补取、候选与下载积压限制、追加预算接续、流诊断 |
| 第三批 | 图版 More ideas、单 Pin 推荐、Pin/图版搜索、Ideas 主题；固定优先级和有界扩展深度；重复游标、未知空结果和结构变化保留证据；按入口分别统计 Pin、签名、文件与成本 |
| 第四批 | 新轮次复查、相容历史文件复用、条件 GET 的 304/200 分支、周期计划防重叠、既有湖登记、归档维护工具、长任务暂存回收与计数优化 |

工作台可选择 Pin、图版、分区、Pin 搜索、图版搜索和 Ideas 主题种子，设置详情补取、发现扩展、各项预算、复用期限及周期复查。任务详情显示预算轮次、媒体与补取状态、流的分页与结束依据、来源成本和文件复用依据。浏览器区分 Pin 列表观察与详情，显示聚合收藏、AI 类别、自动描述、取得依据和文件最近核验时间。

## 不变量与兼容性

- 原始响应、列表观察、详情观察、各 Pin/媒体出现、下载取得与字节对象分别保存。列表字段缺失、null、false 和零仍有区别。
- 只有成员接口产生图版/分区成员关系。推荐、搜索和主题证据不会改写为成员关系。
- 页响应先归档，再推进候选与游标；预算不足的候选不丢失。重复游标或已知访问条件改变会留下可检查状态。固定匿名 CSRF 范围不会带入响应中的其他会话 Cookie。
- 抽样仅针对已准入 Pin；有预算时先核对抽样 Pin，再下载。补取预算不足不阻止已有清单的下载；后续核对发现差异时，范围保留缺口和复核提示，不标为完整媒体成功。
- 跨运行复用核对 URL、媒体角色、内容修订、保存方式、访问条件、期限和已存字节。`http_validated` 与 `historical_reuse` 分开记录；历史沿用不会延长上次核验时间。条件 GET 返回 200 时直接消费该响应，不再多发一次 GET。
- 周期计划使用冻结定义和幂等发生键。同一湖有未结束任务时等待；漏跑周期合并。暂停、预算不足和待检查均不会被自动当作结束。
- 控制库为 v18，v16/v17/v18 分别增加发现、入口统计、持续运行及计数索引；旧库先备份再事务升级。旧任务定义和旧来源计划保留。Pinterest 归档仍为格式 3 / `pinterest-media-v1`，在线仍为格式 4，原有 Booru 和 Pixiv 湖无需迁移。
- Worker 的 Pinterest 能力版本为 3。统一湖、任务、计划列表均通过 `include_pinterest=true` 显式纳入新来源，旧默认列表保持原有来源范围。
- 每次发布后回收该回执的暂存文件；持续作业无需等到终态才释放 SSD。准入计数和发布计数增量维护，不在每个任务上重新遍历全部历史记录。

## 验证结果

自动测试使用隔离目录与构造响应。Pinterest 全部 71 项专项通过，覆盖解析、解码、幂等、预算、迁移、恢复、发现、复用、周期和维护，以及迟到抽样差异、访问条件变化和匿名 Cookie 范围。之后增加 1 项调度公平性回归，连同其所属 9 项持续运行测试全部通过：101 个阻塞计划不会挤出其他可运行的湖。共覆盖 72 项 Pinterest 用例。共享控制迁移、Pixiv 恢复/周期及归档重建另有 52 项针对性回归通过，其中包含部分 Pinterest 持续运行用例。Pinterest/Pixiv HTTP/SDK 集成、Rust 来源格式检查、Clippy、前端类型、修改文件的 Lint 和依赖边界检查通过。

2560×1440 界面验证覆盖创建空湖并挂接项目、Pin 来源与历史观察、丢失创建响应后复用原提交键、暂停/取消、图版流诊断、图版与推荐表单、创建未启用的周期计划及保存间隔。该界面验证没有向 Pinterest 发送请求。

一项有界持续运行验证通过正式 Service/Runner 处理了 4 页、100 个不同 Pin，分 5 轮预算完成：100 条资产关联、1 个字节对象、206 个归档批次，归档与发布水位一致；仅调用 1 次构造图片下载，结束时无剩余暂存文件，独立重建与固定参考版本一致。执行约 19.7 秒；这是恢复与持续状态验证，不代表真实网络吞吐或大规模容量上限。

浏览器连接器在读取登录标签页前持续报 `Unable to load browser request-header policy`，重试和重置后仍未恢复。因此未使用用户账号、Cookie 或私人图版；登录/私人范围、轮播、复杂故事、视频、动画、跨湖文件共享及视觉预筛仍不在已开放能力内。已选范围中的未支持媒体明确保留缺口。

## 复跑入口

```powershell
pnpm test:lake tests/test_pinterest_manifest.py tests/test_pinterest_pipeline.py tests/test_pinterest_discovery.py tests/test_pinterest_expansion.py tests/test_pinterest_continuous.py
pnpm test:integration pinterest collections

node tooling/lake-storage.mjs build --site pinterest --media <归档目录> --output <独立准备目录> --reference-index <当前在线目录>
node tooling/lake-storage.mjs verify --output <独立准备目录>
node tooling/lake-storage.mjs compare --output <独立准备目录>
```

维护构建固定归档水位且可接续；比较使用参考快照租约。不会替换仍在使用的在线代次。`verify` 核对重建数据库与原文，不声称重新哈希所有媒体包。

真实验证必须显式使用 `tooling/pinterest-live.py --allow-network`，输出为仓库 `.local/test-runs/` 下的新目录，默认最多 3 次元数据请求、2 个准入 Pin。指定 Pin 可加 `--verify-reuse`，执行额外一轮条件复查。脚本只驱动正式 Service/Runner。
