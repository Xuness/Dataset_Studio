# Pinterest 生产审查修复验收

日期：2026-10-10。基线：`23d7b6d`。审查输入：[审查 Pinterest 链路规律](chatgpt-conversation://6aca1a0b-8b00-83e9-b6c9-5283e11c60f7)。已阅读聊天中的完整结论；远端 HTML 与复现脚本附件未取得，本轮依据当前源码独立构造回归用例。

## 处理结果

| 项目 | 修正与证据 |
| --- | --- |
| F1：时间片打断慢请求 | 15 秒仅关闭新任务/新请求准入，传输取消独立响应用户暂停、取消和服务停止。元数据保留有界传输超时，Pinterest 图片传输增加 300 秒操作上限。16 秒首块延迟和无 ETag 慢图片均可完成，恢复不重复获取已保存响应。 |
| F2：固定资源超限占队首 | 固定字节、像素、解码内存或单项暂存限制结算为明确单项缺口，其他候选继续；暂时资源竞争仍等待。调整设置后可显式重试。 |
| F3：失败下载积累 | 成功、失败回执均保存 acquisition generation 的清理范围；接受回放与清理意图同事务提交。无待处理绑定引用的文件及时回收；显式重试先持久化旧代清理，再推进 generation。覆盖 8 份各 8 MiB 无效媒体、旧代 60 MiB 遗留，以及接受后崩溃再恢复。 |
| F4：分区漏采误报完成 | 分区流记录去重分区数；列表中合法的 `pin_count` 连同 capture ID、观察时间传至成员流。数量矛盾最多自动复查三次，再保留缺口与重试入口。v21 升级也修正已有、可证明的分区数量矛盾状态。 |
| F5：发现先后影响扩展 | 准入去重与扩展去重分开；按根种子、来源实体保存最小已见深度。更浅路径会开启对应深度的有界流，能够向已结束的后代流传播；媒体仍按原身份去重。 |
| F6：限流等待误扣预算 | 请求取得 lane、准备发送时，在短事务中检查当前预算和 claim，并计入请求及尝试次数。恢复中的新 HTTP 同样经过检查；等待四次仍为零请求、零尝试。记账与网络发送之间若发生进程崩溃，保守保留一次可能已发送的计数。 |
| F7：封包预留提前释放 | 单项 Spool 预留持续到发布与相应清理。下载与关联 TAR 共同计入同一预留；恢复时原子建立分组，避免把遗留 TAR 再当作另一份未来占用。跨湖交错不能突破共享 spool 承诺。 |
| F8：非 UTF-8 原文阻断重建 | 分离有界字节解压校验与 UTF-8 展示解码。非 UTF-8 响应可按原始长度、SHA、压缩流边界通过重建验证，文本接口继续严格处理解码。 |
| TAR 复制完整性 | 目标 TAR 的 SHA 必须等于写入器记录的摘要，并检查暂存源包；注入复制后位翻转时拒绝 journal 接受。修正完整性异常被一般 RuntimeError 分支提前截获的问题，正确进入待检查状态。 |

覆盖诊断不将“来源报告总数与本次可见集合不同”自动改写成“匿名不可见”，也不根据游标位置推断缺失 Pin 的身份。原始响应和数量矛盾继续保留。

## 兼容与接口

控制库升级为 **21**：增加分区去重表/计数、最小扩展深度表和下载清理队列。先备份，再在运行器与执行锁下事务迁移；冻结定义、已有 claim、幂等键及其他来源任务不重写。归档格式仍为 3，在线格式仍为 4，现有归档不迁移。

公开流 DTO 增加 `unique_sections`，OpenAPI 与 TypeScript 由 `pnpm contracts` 生成。工作台区分不同分区数与来源报告数量，并说明固定资源超限的单项缺口与重试条件。

## 尚未完成的规模工作

物理碎片化仍然存在：上述 100 Pin 样本产生 **201 个目录、1,403 个文件、100 个 TAR**。本轮修复没有把这些文件原地合并；已确定[有界物理组批方案](../plans/Dataset%20Scraping/pinterest-bounded-packing-plan.md)，其 durable outbox、格式兼容、跨时间片组批和故障恢复属于下一阶段。

本轮不包含百万级吞吐、目标容量盘持续压测、登录态覆盖、缺失 Pin 身份核对或 HEIC 解码支持。此前阶段的“功能已接入”与本轮的回归通过，均不等同于大规模无人值守投产验收。
