新增传输集成使用真实 SDK、引擎、SQLite 和本机 HTTP 模拟供应商，覆盖大图拆批与 ID/SHA-256 对照、32/48 MiB 配置、原始/部分/超限响应、本地重解析、坏图隔离，以及项目恢复包和成果文件校验。恢复集成增加原始 HTTP 已提交、供应商解析尚未开始时的进程中断用例。

指定的真实工作集“审美排序-Test-1”共 145 张 G Rating 图片。只读来源元数据表示上传年份为 2025 年 117 张、2026 年 28 张，不能据此推断绘制年代。登记文件总量 57,308,838 字节，最大单张 1,188,656 字节；最大的 16 张 Base64 总计 19,391,740 字节，是假设同批的上界，并非实际派发批次。

隔离项目复制工作集身份与“审美排序-V1.0”文本，实际读取这 145 张图片，通过 loopback mock 验证冻结、派发、原始回执与接受路径。结果全部覆盖，10 次本机请求，每次 16 图，最大完整请求为 10,086,198 字节。尾图借用同 Rating 对手，因此总曝光为 160，唯一图片仍为 145。逐批核对原生消息顺序、标签、图片 SHA-256 与账本身份。

真实数据探针使用 node tooling/probe-aesthetic-workset.mjs，显式传入本机元数据审计文件、应用数据目录、Prompt 名称；只连接临时 loopback 供应商。本轮商业 API 调用为零，未修改原工作集和已保存的 System Prompt。此结果不证明远端模型正确识别图片、更不证明排序质量或生产容量。

本机报告和日志归档于 .local/reports/aesthetic-transport-20260923/，真实工作集审计保留于 .local/reports/aesthetic-test-1-20260923/。这些目录被 Git 忽略，不随仓库分发。
