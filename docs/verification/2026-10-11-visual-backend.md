日期：2026-10-11。范围为后端接入、独立运行环境、真实图片提取与查询，不包含前端、项目工作集引用或全湖运行。

## 真实链路

## 恢复与 Windows 运行修正

首次真实任务在后台线程首次加载 SciPy 扩展时阻塞。将相关扩展移至进程主线程预加载后，从原任务和同一未确认批次继续完成。保留了故障日志与堆栈，用于界定此次恢复证据；没有把首次失败试验描述为通过。

Windows 虚拟环境的 `python.exe` 是重定向启动器，实际解释器是其子进程。引擎先以挂起方式创建启动器，将其放入自身 Job Object，再恢复主线程，使实际 Python 正确继承托管关系；握手时再次核实关系。停止服务时终止并等待实际解释器退出，避免仅停止启动器而遗留写入者。

## 自动检查

- 视觉控制库 4 项测试：跨来源身份与物理顺序、部分模型失败、覆盖计数、回执重复确认、未确认批次恢复、完整结果规划阶段复用、半径 7 的 pHash 分页完整性。
- 来源投影测试：有界行键分页、发布后继续读取原固定版本、不读取图片包、拒绝越界物理路径。
- Python 10 项测试：共享读图、动画／损坏图片显式失败、模型失败隔离、像素预算分组、Lance 已提交但回执丢失的恢复、来源关联更新、已发布版本隔离、三种完整维度的 FP32 存储与流式读取、IVF_FLAT、重复写入和碎片整理后保留旧版本。
- 引擎构建、受影响 crate 的 Clippy、SDK 类型检查、修改脚本的 ESLint、生成契约和依赖一致性检查按本次范围执行。
