# 2026-10-04 Danbooru 全湖元数据排名性能验收

本轮达到用户允许的「同一数据湖版本复跑不超过 300 秒」口径。实际项目使用原有 12 GiB 查询预算，首轮为 **637.610 秒**，同版本复跑为 **286.593 秒**。首轮仍未达到 300 秒；本记录不把复用成本计成首次构建成本，也不声称已证明硬件的绝对性能极限。

实现与兼容边界见 [ADR 0057](../decisions/0057-bulk-ranking-and-snapshot-reuse.md)。

## 数据与计时口径

- Windows 本机，Ryzen 9 9950X、96 GiB 内存、NVMe 存储，Release 引擎。
- Danbooru 在线湖固定版本 15720，共 **11,624,906** 个图片身份；来源归档、图片和业务元数据没有改写。
- 使用用户保存的 MetaRecall V2 参数：G/S/Q/E 全部分级、重复帖热度求和、最小存储边长 384、保留比例 333‰、作者项关闭。完整参数随本机报告归档。
- 从提交排名任务前开始计时，直到成果持久化且接口返回首批 48 条排名记录；包含复制或读取输入、摘要核验、计算、索引、全量校验和发布。
- 操作系统文件缓存没有强制清空；首轮没有命中排名输入复用。首屏指排名记录接口，不包括图片缩略图解码、绘制或整个应用启动时间。
- 仅验收该完整来源、版本、参数和机器条件，不保证其他大小、参数、混合来源或过滤范围也在 300 秒内完成。

## 最终实测

| 场景               | 查询预算 | 端到端时间 | 输入复用 | 结果                    |
| ------------------ | -------: | ---------: | -------- | ----------------------- |
| 实际项目首次构建   |   12 GiB | 637.610 秒 | 否       | 完整成功，未达到 300 秒 |
| 实际项目同版本复跑 |   12 GiB | 286.593 秒 | 是       | 完整成功，达到 300 秒   |
| 先前隔离项目复跑   |   16 GiB | 294.614 秒 | 是       | 完整成功，达到 300 秒   |

最终两轮使用相同 Release 二进制，SHA-256 为 `58313b8e0a1a0c1003ebab824d12b74d27be6b85558fb26636b3a5fb0fb50984`。没有为了最终验收修改实际项目的资源设置。

首轮元数据构建为 314.367 秒，输入索引为 45.076 秒。同版本复跑的主要阶段如下；阶段遥测与包含提交、轮询、发布和首屏的端到端时间存在少量边界开销。

| 复跑阶段                           |       用时 |
| ---------------------------------- | ---------: |
| 复制固定输入并核验原摘要           |   9.699 秒 |
| 本次输入摘要及执行器读取核验       |  12.101 秒 |
| 资格分类、候选加载、计算和结果写入 | 144.899 秒 |
| 结果索引                           |  68.653 秒 |
| 发布前输入摘要复核与逐行校验       |  44.543 秒 |
| 输出摘要                           |   4.810 秒 |

资格分类与读写仍占大头，纯数值计算约 16 秒。首轮若要继续压到 300 秒，需要继续改变输入材料和查询索引的组织方式，或在湖更新时维护可直接消费的类型化投影；当前实现没有将这部分成本隐去。

## 完整性与兼容验证

所有 11,624,906 条输入均有结果记录；符合当前参数的可排序候选为 **3,628,869** 条。其余包括尺寸未知 7,981,483 条、尺寸不足 14,202 条、元数据不可用 346 条、分级未知 6 条。完整处理不等于把不符合筛选条件的图片强行赋予候选名次。

最终实际项目复跑与早先完整成功的基准成果进行只读 SQL 全量对照：11,624,906 个序号全部匹配，26 个结果字段（包括 V2 分数、名次和标志）零差异；除任务创建时间和本次输入摘要外，汇总统计一致。对照在计时结束后运行，用时 32.791 秒。小型来源回归另将直接全湖路径与原物化成员路径逐行比较，覆盖 V1/V2 与重复帖策略。

已通过：

- `pnpm check`：类型、边界、契约、格式、Clippy、Rust/客户端检查，以及 424 项数据湖测试。
- `pnpm test:integration`：全部 27 个集成入口，包括固定范围、任务、排名、浏览、缓存、生命周期、来源与数据湖恢复。
- 输入复用回归：兼容参数变化可以复用；观察策略变化重新捕获；篡改旧输入不会成为可信副本；旧成果文件保持原字节。
- 恢复回归：取消、重试、进程重启及缺少新增统计字段的旧检查点均保持结果一致。

输出仍执行输入摘要、完整覆盖、资格、特征范围、分数组成、名次排列、分级名额和输出摘要校验。没有以抽样代替全量检查。

## 本机证据与复现

证据目录为 `.local/reports/metarecall-300s-2026-10-04/`，不随仓库分发。目录保存完整参数、各轮报告、阶段日志、测试摘要、`live-semantic-comparison.json` 和清理收据。实际项目首轮报告目录后缀为 `1791062963590`，复跑为 `1791063601378`。实际项目的两份成果保留；隔离测试成果在归档证据后通过正常对象/任务 API 释放。

使用 [benchmark-ranking.mjs](../../tooling/benchmark-ranking.mjs) 复现。先构建 Release 引擎，再使用 `--index-root`、`--media-root`、`--parameters` 运行独立项目；`--reuse-run` 复跑同一项目。实际项目模式使用 `--live-connection`、`--project-id`、`--source-id`，核验当前开发引擎二进制且不改变资源设置。该模式会生成持久排名成果。

复用要求同一项目内存在完整、可验证且投影兼容的固定输入；新来源版本、缺失或损坏的输入、不同观察策略不能默认视为命中。分数和本次结果始终重新生成。
