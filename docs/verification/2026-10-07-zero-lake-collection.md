# 从零建湖与按需采集验收

日期：2026-10-07。基线 `b95808c`。对应[实施计划](../plans/zero-lake-collection-2026-10-07.md)与[操作指南](../architecture/zero-lake-collection.md)。

## 已实现的结果

- Danbooru、Gelbooru、Yandere、Pixiv 均可从两个空目录创建、登记并加入项目。三站空湖不依赖旧生产者索引；首次发布和项目读取可以从版本 0 开始。
- Booru 单标签发现与本地 all/any/none 筛选保留完整有效元数据，只为匹配条目处理媒体。稀疏 ID、OR 去重、预算续跑和错误响应均保持独立扫描进度，不推进全站新帖水位。
- 有证据的查询页可跨任务复用，检查边界、代次、访问条件与新鲜度。A∩B 后 A∩C 可复用 A；零散 B 记录不会冒充 B 的完整覆盖。复用保留原观察时间。
- 独立 Booru 元数据目录可分页查看未下载图片的帖子，并将固定版本、筛选条件和选择交给新任务。缺失媒体地址按需刷新。预约定义拒绝长期引用临时目录版本。
- Pixiv 在作者/作品范围内按完整标签筛选。仅元数据任务后可以复用详情与完整媒体清单补图；70 页清单以 64+6 分批规划，控制回写故障后接续。标签缺失明确报告缺口。

湖格式保持 Booru 归档 1 / 在线 2、Pixiv 归档 2 / 在线 3。共享控制库升级到 schema 14，旧执行器不能忽略新增条件。没有对正式湖执行转换或改写。

## 本机证据与限制

本机命令日志位于 `.local/logs/zero-lake-stage*-*.log`，最终界面摘要与代表性截图保留在 `.local/reports/zero-lake-collection-20261007/`；这些文件不随仓库分发。临时湖、项目、解释器缓存和测试结果不提交 Git。

本轮未使用正式湖、实际账号或真实源站进行全站采集，未运行容量压测或发行版原生窗口验收。该结果证明隔离样本中的协议、保存/读取、界面和恢复行为，不构成真实源站可见性、限流或大规模吞吐的测量。近期覆盖代表原扫描时间下的结果，不保证源站此刻的标签状态。
