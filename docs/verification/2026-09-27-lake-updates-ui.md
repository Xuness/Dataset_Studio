# 三站更新工作台验收

日期：2026-09-27。对应 Studio `31b5dc7` 与 Store `991613b` 之后的工作区改动；最终源码清单保存在本机验收目录。设计见 [0039](../decisions/0039-lake-update-workbench.md)。

## 已接入

- 全局“数据湖”编辑器：起始页、工具菜单、项目来源菜单和底部活动入口；无项目也可使用。
- 三湖大纲、任务时间分页及筛选、上下文操作、详情、元数据/媒体进度、覆盖记录与问题分页。
- 范围及图片策略表单、多湖独立幂等提交、暂停/继续/重试/原文重新解析和取消。
- 数据湖 API 凭据设置、显式连接检测、运行环境配置与已有湖登记。
- 单次预约、固定间隔计划、显式启用及修订校验。
- 当前选择、工作集、固定查询和来源范围的后台准备，固定成员映射为各湖完整帖子输入，完成后进入同一更新表单。

界面复用现有 UE 5 风格主题和停靠组件，不另建一套工作台。原有浏览版本提示保留，任务状态刷新只刷新更新服务数据。

## 自动验证

Store 全套 249 项测试通过；随后针对摘要字节预算、首次基线和固定输入预检等补充修正，28 项更新回归通过。覆盖任务时间/筛选游标、稀疏失败、活动计数、大 ID 列表的响应上限、暂停退出确认、稳定输入身份、归档/恢复及原有三站处理。

Studio 已通过 `pnpm check` 和原有完整 `pnpm test:integration`。已有更新 HTTP/SDK 集成通过。新增 `tooling/smoke-lake-updates-ui.mjs` 使用隔离的真实引擎、真实 Store 控制库和无网络的三湖合成图片，检查：

1. 时区和夏令时日期边界、包含末端的 ID 输入及显式图片策略。
2. 三湖选择提交后立即清空，固定输入仍保留原三张图片与六个关联帖子；工作集和查询结果也能准备输入。
3. 映射完成、尚未封存的检查点重启恢复；关闭项目后准备继续；引擎重启后结果仍在。
4. 无项目打开全局编辑器，三湖经 UI 创建任务并由运行器完成。
5. 单次计划保存为未启用，显式启用及修订保存；测试时刻均在 2099 年。
6. 已准备输入回填新建表单，未点击开始时不发起源站抓取。
7. 刷新后恢复全局工作视图，2560×1400 及 1706×920 布局、底部活动入口。
8. 使用隔离测试凭据执行保存和清除，保存后输入框清空，状态响应不回显密钥；没有执行源站连接探测。

图片夹具使用每湖一张不同颜色 PNG，同图关联两个帖子。页面直接连接隔离 HTTP API；源站响应仅在创建夹具时由 Store 的录制站点类提供。大成员准备路径使用有界流式读取；本轮没有用百万级实湖成员测量准备吞吐，不能把小样本结果当作容量或冷 HDD 延迟保证。

初始冻结未发布前中断，需要重新选择原范围；已发布固定成员后的准备可续跑。完整删除事件流、日历式调度、后台 OS 服务、媒体默认策略仍保持此前边界。
