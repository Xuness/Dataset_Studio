## 本机 SQLite 访问计划

测试通过 Rust 工程实际使用的 rusqlite 0.40.2 / libsqlite3-sys 0.38.2 执行。SQLite 报告版本 **3.53.2**，source ID 为 `2026-06-03 19:12:13 d6e03d8c777cfa2d35e3b60d8ec3e0187f3e9f99d8e2ee9cac695fd6fcdf1a24`。

合成项目分别装入下列成员数量，固定一个 affected 资产且确认成员和帖子关联没有变化。外部实验使用的 Python SQLite 3.46.1 没有参与本轮测试。

| 既有成员 | 原关闭 SQL 约 VM 指令数 | 原全族 COUNT 约 VM 指令数 | 新完整发布路径 VM 回调次数 |
| ---: | ---: | ---: | ---: |
| 10,000 | 130,000 | 70,000 | 715 |
| 100,000 | 1,300,000 | 700,000 | 715 |
| 500,000 | 6,500,000 | 3,500,000 | 715 |

原两项计量粒度为 100 条 VM 指令；新路径 progress handler 每条指令调用一次，并断言观察器确实触发。旧方案两项不含其余发布开销，新路径包含发布函数执行的 SQL。计数不等于 CPU 指令、墙钟耗时或物理页访问数；B-tree 深度和 I/O 成本不由此证明为常数。

实际新计划定位 `family_id + source_id + asset_id`，旧关闭 SQL 仅定位 `family_id + source_id`。回归门槛要求单键发布的 VM 工作量小于 50,000，避免再次退化为全族扫描。此实验不外推为千万图查询或 UI 吞吐保证。

## 正确性与并发覆盖

- 混合一来源全量、另一来源增量；新增、删除、相同成员、帖子关联变化、NULL、重复 stage 行、不同来源相同资产 ID。
- 旧成员区间仍可读；计数和 `stored_members` 与独立 SQL 枚举一致；空结果和无变化修订准确。
- 重复/错序、未封存和已取消发布拒绝；最终来源校验失败恢复旧成员；成员提交后重启、无变化提交后重启均清除临时发布记录并允许重试。
- 项目 writer 持有未提交草稿时，独立读取仍取得旧提交；保存继续拒绝过期 expected_revision。
- 冷写入暂停时另一暖 key 命中继续完成，维护不删除活跃临时文件；读取开始前已取得 pin，clear 不删除其材料。
- 正在写入时清理/降配额覆盖该写入，重启后状态一致；删除某 key 暂停时其他 key 仍可读；离线读取不回退并发在线校验时间。
- 既有损坏缓存、LRU、目录保护、持久配额和跨重启清理测试继续执行。

这些缓存测试使用通道暂停指定 I/O 阶段，检查另一操作是否能在解除暂停前完成，避免只凭一次偶然耗时判定并发安全。
