## 恢复与一致性

直接从封存 Parquet 和固定 journal 前缀构建私有在线库，不读取生产者索引。对导入摘要、全部 raw 无损回读、SQLite/FTS、引用关系和最终数据库摘要进行验证；随后比较对象、观察、资产、raw、来源 schema、当前帖子及当前对象七类逻辑关系。

| 湖 | 对象 | 观察及 raw | 资产 | 最终对照 |
|---|---:|---:|---:|---|
| Danbooru | 11,607,955 | 13,524,221 | 11,633,213 | 一致 |
| Gelbooru | 4,080,365 | 4,092,791 | 4,091,187 | 一致 |
| Yandere | 1,156,598 | 1,252,308 | 1,157,150 | 一致 |

Danbooru 首次对照发现 266 条当前帖子关联差异：观察完全一致，当前 API MD5 缺失，早期现用投影仍保留同帖历史资产，而现行严格推导得到空关联。没有改写现用数据库或原始事实。

这 266 条选择已保存到归档 `source_manifests/legacy-online-bindings-v1.json`，并由公共恢复代码回放。交接先确认原完整验证的文件 SHA-256，再只修改私有库的帖子关联，完整重比全部 11,659,302 条当前帖子关系；其它六项事实沿用已完成且受原文件摘要约束的全量证明。记录保留原验证、原差异及变更后的摘要。后续帖子有新观察或资产时，正常发布规则生效，历史兼容选择不覆盖新事实。

最终 `ONLINE.json` 文件摘要与退役前完全相同；三个旧生产代次目录均不存在，退役标记为 `complete`，校验专用租约剩余 0。内置和旧 Store 两个 Index 入口均对三湖真实退役标记拒绝再创建生产者索引。

## 元数据存储与运行环境

Parquet 延续 Zstd；在线 raw 延续逐条 zlib，统一 UTF-8 长度、SHA-256、压缩流结束和解压预算校验。排名优先使用有效的结构化保存尺寸，必要时再读取 raw。

按 raw SHA-256 前缀 `00` 抽样，Danbooru 52,865 条中重复压缩内容约占 2.724%；Gelbooru 15,962 条、Yandere 4,936 条样本未发现重复。该测量不支持为小幅容量收益重写三湖格式；不把样本结果表述为精确全量去重收益。

更新服务已通过配置接口切换到 Studio 专用 Python，原控制状态目录保留。切换前后，任务、凭据、数据湖登记、固定输入、计划、搬盘记录和覆盖记录的逻辑摘要一致；旧的无效 `store_root` 配置已移除。旧兼容工具需要的 F 盘 Python 环境仍保留。

旧 Danbooru 规划任务的 852 个帖子已交接：839 张入库，13 项明确排除（7 项格式不支持、6 项没有图片地址）。旧记录标为 `handed_off`，保留交接凭据与日志备份，不伪造旧验收水位。原暂停增量任务保持暂停。
