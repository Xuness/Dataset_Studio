# 内置数据湖更新服务与图片配方验收

日期：2026-09-27。基线 Studio `538a414`、Store `00ec572`。本轮修改在 Studio 内，Store 仓库保持干净。决定见 [0040](../decisions/0040-owned-lake-worker-and-image-recipes.md)，安装和参数见[服务说明](../../services/lake-worker/README.md)。

## 交付

更新服务及其规范存储依赖已纳入 `services/lake-worker`；31 个 Python 模块的本地导入闭包核对没有缺失。源码嵌入 Rust 引擎，按版本摘要展开并以隔离 Python 路径启动。设置页不再要求 Store 仓库目录，兼容读取旧配置但不使用其中的源码路径。源码、依赖声明、安装脚本、测试和 CI 在同一仓库维护。

自定义图片配方支持 WebP/JPEG/PNG、原尺寸或最长边、各编码适用的质量/无损/压缩选项、动画原文件或首帧、透明通道及背景合成。原图和旧 WebP 预设保持处理语义。完整配方以摘要参与资产复用，参数变化可补入新版本；旧资产保留。命名预设可保存、应用、更新、删除，任务和计划固定参数。

## 状态与兼容性

开发环境监视到代码变化后已自动重载，正式控制目录的进程由 Studio 内置源码运行，使用 Python 隔离启动。只读核对时控制库为 schema 4，有原有的 3 个任务、0 个计划。本轮没有创建正式抓取任务，没有修改旧每日自动化。

对正式控制库做只读 SQLite 备份后，在隔离副本中模拟 schema 3 功能版本并升级到 4；15 张表的全部行摘要保持一致，包含任务、计划、固定输入和加密凭据。schema 3 运行器仍占锁时拒绝升级由独立测试覆盖。这个副本实验不冒充正式升级前后的完整文件比对。

在线湖仍为格式 2，项目仍为格式 13，数据目录与库身份没有重新迁移。旧 Store 更新控制工具不能读取 schema 4，独立旧 daily 流程使用自己的状态，仍保留原入口。Python 解释器及第三方依赖没有嵌入引擎；原环境继续兼容，同时本机已准备 `.local/runtime/lake-worker`。
