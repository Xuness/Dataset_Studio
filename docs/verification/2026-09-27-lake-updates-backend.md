# 三站更新后端验收

日期：2026-09-27。实现覆盖 Studio 和 Danbooru-Store。决策见 [0038](../decisions/0038-lake-update-control.md)，范围见[实施计划](../plans/lake-incremental-updates-2026-09-26.md)。

## 已交付

全局更新 HTTP API、类型化 DTO 与 SDK；受监督的 Store 运行器；三站 API/标签分类适配；加密凭据；有界范围、固定输入、元数据与图片队列；暂停/续跑、重试与原文重放；单次预约及周期计划；归档重放、在线发布和共享磁盘准入。前端仍待单独设计。

图片保存策略保持可选，默认值待定。`existing=keep` 与 `match_profile` 区分只补缺图和显式升级，避免改变保存策略后自动重抓已有 HF 图片。缺少 MD5 时，不借用同帖旧图作新观察的图片依据。

## API 与真实样本

已使用用户提供的 Danbooru/Gelbooru 凭据验证；Yandere 使用匿名 API。Danbooru 账号验证与帖子读取成功。实际响应还确认了以下站点差异：

- Gelbooru 会忽略点号 ID 区间和逗号 ID 列表；适配器改为两个比较条件，明确 ID 则单帖获取。
- Yandere 使用 `deleted/holds/pending` 参数，不能沿用 Danbooru 的 `status:any`。
- Gelbooru 图片请求需要正确的站点 Referer。
- Yandere 的标签摘要提供活动标签类别；Gelbooru 使用标签接口。完整参考响应及分类上下文一同保存。

隔离湖完成三站各 2 张原图的真实下载和发布；遇到的参数/媒体差异在隔离阶段修正，再恢复原任务验收。原文、失败原因、重试和新观察均保留。
