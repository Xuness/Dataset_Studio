## 故障支点和验收矩阵

| 位置/场景 | 实现与预期 |
| --- | --- |
| project 创建事务提交后 | 强制结束测试引擎；重启补建唯一 stage，恢复冻结配置与引用 |
| ledger stage 提交后、项目建成确认前 | 强制结束；按持久意图对账，不能重建第二个 stage |
| 未建成意图明确放弃 | 释放引用，保留墓碑；重启和同键重试不复活 |
| SQLite BUSY | Rust 持有真实外部 `BEGIN IMMEDIATE` 验证回滚和恢复；HTTP 层另注入持续 BUSY 验证账本隔离 |
| FULL / IOERR | 测试构建在真实 receipt 事务提交前返回对应错误，验证共享故障域及恢复；不填满用户磁盘 |
| writer 退出 | 真实测试写线程 panic，验证独立错误、其他项目可用、关闭与 unknown 恢复 |
| receipt COMMIT 后丢失确认 | 同 attempt 重试本地持久化，模型只调用一次，所有计数只应用一次 |
| ledger 收尾 / 项目引用同步 COMMIT 失败 | 重试收尾，计数与最终状态保持幂等，不留下没有执行器的 running 状态 |
| 已取消阶段的账本丢失 / 损坏文件 | 缺失时不新建空账本，损坏时不覆盖原文件；要求恢复历史 |
| 上传等待结束、最终提交前暂停或熔断 | 暂停/故障闭合后不能新建 attempt；未发送批次可以恢复 |
| receipt 提交后中断，evidence 提交前/后中断 | 已保存返回本地重解析、接受一次，不新增网络请求 |
| HTTP JSON/供应商结构错误 | failure 保留 provider request ID 和不确定状态 |
| 15 张可判断 + 1 张不可判断 | 排除和独立同 Rating 重评都有出口，不虚增曝光 |
| 1,000,000 / 1,000,001 与预检后输入变化 | 能力边界一致，权威 create 在调用前拒绝超限/旧 token |
| 旧模板与新模板 | 发送冻结消息；未知执行版本/缺失冻结消息拒绝，旧 attempt hash 不补造 |
| 派生发布前/后、原始 HTTP 接收/保存/解析分层 | 在 R0 登记，完整扩展分别属于 R3/R2；本轮不声称已经提供恢复包或原始字节重解析 |
