# 三湖视觉后端生产运行验证

日期：2026-10-12。代码能力覆盖可控任务、结果读取、增量、后台索引与历史保留；真实材料继续保存在正式特征库。全湖连续扩展已启动，本文的完整数值核验与检索结论只覆盖明确列出的快照和夹具。

## 真实图片、范围与完整性

Danbooru、Yandere、Gelbooru 各取固定目录前 5000 个对象，三模型使用同一批 15000 个不同 SHA。该目录前缀不是全湖随机样本。NaFlex、EmbeddingGemma 2、Kaloscope 3 分别保存 1152、768、256 维完整 FP32；每湖 pHash 与三个配方最终均为 5000 成功、0 失败、0 待算。

通过正式 `/exports` 接口按固定快照分四页导出每个模型，验证 45000 条向量的 Arrow 类型、完整维度、有限值、L2 范数、对象唯一性、三模型成员一致性及每个文件的 SHA-256。384 张旧快照继续可读；指定集合、任务范围复用、旧快照查询和不同游标模式均已核对。复用 384 条来源关联和 9 张指定图片均为读取 0 字节、模型调用 0 次。

随后连续执行每湖 16 张的两轮增量，水位从 5000 → 5016 → 5032，新增 96 张，两轮成员无交集。相同 `request_id` 重放得到原任务，改变参数被拒绝。三表在检索验证时各有 15096 条向量。

连续扩展的下一轮又完整新增 15000 张（每湖 5000），失败特征 0，阶段覆盖达到 30096 张、每湖 10032 张。控制器自动为三表重建 173 分区索引，原生构建耗时分别约 Gemma 1.32 秒、Kaloscope 0.52 秒、NaFlex 1.88 秒，全部索引 30096 行。此后继续下一轮；这些新增图片不混入前述固定 15096 张的检索对照。

## 小批量与阶段开销

从三个湖各取 8 张真实图片，共 24 张，读取一次后对每模型分别预热并测试 2、4、8、16、24 张小批量，每档两遍。以下为模型预处理与前向合计吞吐，不包含全链路读盘、解码、pHash 和写入：

| 模型             |   4 张小批量 |   8 张小批量 | 选择                              |
| ---------------- | -----------: | -----------: | --------------------------------- |
| EmbeddingGemma 2 |  33.71 图/秒 |  42.11 图/秒 | 8；继续增大无稳定收益             |
| Kaloscope 3      | 101.16 图/秒 | 108.72 图/秒 | 8；24 张约 109.05 图/秒，收益很小 |
| SigLIP 2 NaFlex  |  81.89 图/秒 |  93.90 图/秒 | 8                                 |

各档向量相对 2 张基准的最小余弦相似度不低于 0.9999668，包含 BF16 批次舍入差异。三个参数分别配置，本轮恰好均选 8，不再被实现强制绑定。

首次 15000 张任务在累计写入触发 Lance 维护时暴露 Windows `\\?\` 路径拼接错误：向量已经落盘，后续维护失败却被旧异常处理记成模型失败。该错误已修复，基础设施异常现在保留待确认批次。原任务暂停后取消，按同一冻结范围恢复，2432 个已提交对象无需重新推理，最终覆盖核验全部成功；旧失败记录保留为故障证据。

两个执行阶段实际新解码合计 14616 张，另外 384 张原已存在。两段测得的运行时间合计 1351.9 秒（约 22.5 分钟），不含排查修复间隔，不能当作一次无中断冷启动基准。读取合计 4,922,535,594 字节。阶段统计如下：

| 阶段                                  |         两段已确认批次合计 |
| ------------------------------------- | -------------------------: |
| 读盘                                  |                   51.10 秒 |
| SHA-256                               |                    1.91 秒 |
| 解码                                  |                  469.62 秒 |
| pHash                                 |                   47.35 秒 |
| EmbeddingGemma 2 加载 / 预处理 / 前向 | 10.11 / 126.56 / 263.43 秒 |
| Kaloscope 3 加载 / 预处理 / 前向      |   1.86 / 110.31 / 39.68 秒 |
| NaFlex 加载 / 预处理 / 前向           |    7.04 / 96.09 / 88.29 秒 |
| Lance 写入与整理                      |                   10.31 秒 |

工作进程 RSS 高水位约 3.64 GiB；PyTorch CUDA 分配／保留峰值约 2.52／2.99 GiB。RSS 是进程生命周期高水位，CUDA 指标取已确认批次最大值；它们不是整机占用。模型全阶段与细分阶段有包含关系，不能重复相加。当前主要时间仍在解码、预处理及 Gemma 前向，不能仅用 GPU 前向吞吐推算全湖 ETA。

下一轮完整新增的 15000 张没有提取中断，已确认批次累计耗时 1362.96 秒，约 22.7 分钟；读盘 60.95 秒、解码 481.08 秒、pHash 48.31 秒、写入与整理 11.12 秒，RSS 高水位约 3.69 GiB。控制器在此期间的退出／接回只改变观察进程，提取任务保持同一个 ID 连续执行。该轮进一步证明万级续跑，不等同于全湖稳定吞吐。

## 真实索引召回与延迟

为三个模型在 15000 条上构建 122 分区 IVF_FLAT，随后增加 96 条，冻结查询快照。固定种子从每湖原 5000 张内选 32 个查询，每模型 96 个全来源查询；另取 24 个做来源过滤。请求 top-21，排除自身后比较 top-20 与精确检索。

| 模型             | 32 探针平均 recall@20 | 64 探针平均 recall@20 | 64 探针最小召回 | 64 探针 p50 / p95 |
| ---------------- | --------------------: | --------------------: | --------------: | ----------------: |
| EmbeddingGemma 2 |                95.89% |                99.38% |             85% |    21.3 / 32.5 ms |
| Kaloscope 3      |                97.24% |                99.58% |             80% |    23.3 / 32.9 ms |
| SigLIP 2 NaFlex  |                98.96% |                99.74% |             90% |    29.5 / 36.3 ms |

来源过滤的 64 探针平均召回分别为 99.38%、99.79%、100%。全 122 分区时，三模型的 360 个全来源／过滤查询均达到 100% recall@20。因此将默认探针数设为 64，调用方仍可指定或使用精确查询。

延迟包含本机 HTTP、向量查询与身份解析，采用共享缓存的连续查询；探针按固定顺序测试，存在暖缓存和调度效应，不能用几毫秒差值判断探针数的单调性能变化。本组是 15096 张上的测量，不承诺千万级真实数据沿用同一召回率。

## 容量与运行恢复

在隔离目录生成 1000000 × 1152D 合成聚类向量，通过正式索引 API 测量 1000 分区构建。初始流式 coreset 训练把约 47 万行聚到一个分区，超过查询缓存有效范围，32 探针查询出现秒级延迟。改为有界普通 K-means、4 个 Lance CPU 线程和 64 MiB shuffle 缓冲后，正式 API 复测：

- 原生索引构建 19.865 秒，含调度的任务墙钟 21.20 秒；峰值 RSS 1,352,904,704 字节，约 1.26 GiB。
- 128000 条训练样本目标；986 / 1000 分区非空，最大分区 10622 行。
- 32 个查询、32 探针：p50 41.1 ms、p95 80.6 ms、平均 recall@20 90.47%。这是合成容量结论，不是百万张真实图的质量结论。

独立 20000 条操作夹具实测索引构建阶段暂停、恢复完成、取消以及引擎重启后恢复暂停任务；子进程终止后旧发布版本仍可查询。保留规则经实际回收检查，显式旧快照与最近版本存活，重复回收幂等，缺少必需版本／保留 pin 时拒绝回收。故障注入覆盖 Lance 已提交而回执尚未保存的恢复，恢复不产生第二份索引提交。

正式连续控制器按每湖每轮 5000 张扩大，轮间自动检查索引重建建议。测试中终止并重启控制器后，仍观察同一个在跑任务，未创建重复提取。该进程不是系统服务，主机退出后应通过状态文件恢复。完整三湖约 1695 万条来源对象尚未全部提取，不能把启动补算写成全量完成。

另修复 `--resume` 授权持续到后续手动暂停的问题：显式恢复只适用于控制器启动时首次观察到的暂停／失败任务。真实第二轮任务中，手动暂停后控制器退出、引擎保持暂停；重新显式 `--resume` 后同一任务继续推进。停止状态下另创建了 32912 张的阶段快照，随后恢复连续扩展。

## 内容、画风与近重复

内容／画风对照使用三个空间的精确近邻，避免把 ANN 漏召回混入模型比较。本机交互报告保留三张查询图、各空间候选和原排名；对展示图片使用普通评级与标签筛选，隐藏的候选不重新编号。

直接核看的例子中，黑发制服生日贺图的 Gemma 近邻保留了人物和场景，NaFlex 近邻包含生日文字及肖像构图，Kaloscope 近邻则出现不同角色的平涂卡面。戴帽男性肖像在两个内容空间中仍返回类似人物构图，Kaloscope 的首项转为双人和服插画。另一长发角色样例的 Kaloscope 近邻有接近的细线与柔和色块，但题材也相近。因此三个空间确有不同侧重，尚不能据此宣称画风表示已和内容解耦。

96 个查询各取精确 top-10。由于跨湖字段缺失，每模型只有约 155–168 对具备双方一般标签，Jaccard 均值约为 Gemma 0.119、Kaloscope 0.089、NaFlex 0.134；作者标签重合分别为 0/149、3/156、0/160。该统计仅作为稀疏元数据检查，不构成内容或画风质量排名，更不能替代人工真值。

固定 15000 张的全部 pHash 独立计算得到半径 ≤7 的 289 对不同 SHA 候选，汉明距离 0/2/4/6 分别为 86/85/61/57 对。260 个实际 API 查询经分页后与独立计算完全一致。人工核看的距离 0 样例仍有嘴形变化、戴眼镜／不戴眼镜的版本，说明它适合提供同图变体候选，不能自动当作可删除的完全重复。没有修改或删除任何原始湖图片。
