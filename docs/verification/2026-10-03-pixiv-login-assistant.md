# Pixiv 登录助手验收

日期：2026-10-03。基线为公开生产阶段 `98be091` 之后的登录助手；实现决定见 [ADR 0054](../decisions/0054-pixiv-browser-login-assistant.md)。归档格式、在线索引版本和控制数据库版本均未改变。

## 使用入口

在 Windows 桌面版进入“设置 → 数据湖 API → Pixiv”：

1. 选择“新增登录会话”，或选择需要重新登录的已有会话，填写名称。
2. 点击“通过浏览器登录”，在 Pixiv 官方页面使用邮箱／密码完成登录及必要的验证码。
3. 返回 Studio，点击“已登录，验证并保存”。后端确认账号身份后才写入加密凭据，并关闭登录窗口。
4. 新建 Pixiv 更新任务时选择这个已验证会话。已建立的公开任务继续保持原固定定义。

窗口有效期为 30 分钟。关闭设置页面后可以重新打开接续；取消或关闭登录窗口会结束尚未提交的登录流程。发生“结果未确认”时，点击“重新确认保存结果”，继续使用原请求。Web 模式保留手工导入 Cookie 的入口。

原生验证使用与正式桌面版相同的桥接模块、真实 WebView2 和设置组件。验证服务、Cookie 与账号记录均为隔离夹具，具体证明了：

- 清除登录配置时，主窗口普通配置中的标记 Cookie 保持不变；再次开始时，上一轮私有 Cookie 不会被沿用。
- 空会话不能提交；仅当前 Pixiv Cookie 被直接送往本机验证服务，其他域和普通配置中的 Cookie 不会被传递。
- 登录网页不能调用宿主命令或取得引擎连接。前端收到的结果和状态没有 Cookie 字段或值。
- 登录子窗口异步创建，关闭父窗口时一并关闭；设置页刷新后可继续原流程。
- 验证拒绝及账号不匹配保留原有有效账号。后端另以真实控制数据库验证两次修订检查，避免候选认证覆盖并发清除操作。
- 模拟后端已保存、响应传输中断，再关闭登录窗口并刷新设置；同一请求重放得到保存结果，账号修订只增加一次。
- 恢复后的错误显示完整中文原因，没有把序列化错误对象显示为 `[object Object]`。

## 同日真实登录回归修复

用户在官网完成登录后，首次点击保存返回 `COLLECTION_CREDENTIAL_REQUIRED`。后端已经收到会话材料，但验证器只读取旧式 `meta-global-data`，漏掉当前官网的 Next.js 页面状态。此前的合成认证和登录表单检查没有覆盖真实首页格式。

当前解析同时支持旧格式与 `__NEXT_DATA__`。新格式要求 `props.pageProps.isLoggedIn` 为布尔值 `true`，解析其 `serverSerializedPreloadedState` JSON 字符串后，仅从 `userData.self.id` 确认身份。公开用户列表、统计字段或 Cookie 中的数字不能替代本人身份；字段缺失、非法 ID、不完整或重复页面状态均不能通过验证。

修复已通过开发引擎更新加载，运行中的 83 个 worker 文件与当前源代码逐一相符。用户再次点击保存后确认成功；本机公开接口也确认会话为 `valid`、凭据已保存且存在账号绑定。验收记录仅保留这些状态，不保存真实 Cookie、账号 ID 或已登录页面正文。

## 已知边界

邮箱／密码路径已由用户完成真实登录并验证保存。R-18／R-18G 或 AI 显示条件仍未完成独立验证；本次修复没有改变这些字段的未知状态，也没有启动新的采集任务。

主要操作路径为邮箱／密码登录。第三方登录和通行密钥未作成功认证验收；登录子窗口不承诺完整的 `window.opener` 行为。需要时可继续使用现有 Cookie 导入方式。

## 本机证据与清理

完整日志位于 `.local/logs/pixiv-login/`。长期证据目录为 `.local/reports/pixiv-login-20261003/`，保存测试摘要、截图、日志归档、文件清单和清理回执；这些本机材料均被 Git 忽略，不随仓库分发。

同日首页格式修复的日志位于 `.local/logs/pixiv-login-format/`；公开官网结构检查、脱敏会话状态和回归清理回执保存在 `.local/reports/pixiv-login-format-20261003/`。

临时验收宿主使用独立的 `.local/test-runs/pixiv-login-native-*` 浏览器配置，后台及数据库测试也位于本轮明确的测试目录。正式 Pixiv 湖、共享控制目录、真实项目和 `.local/dev/` 不属于清理范围。

可复跑命令见[工具导航](../../tooling/README.md)。官网页面检查必须显式传入 `--live-login-page`，不会夹带在自动离线回归中。
