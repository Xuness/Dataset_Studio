# 查询结果交接与缓存保护计时

2026-09-11

G 筛选曾在后端成功得到数百万成员后被容量回收。结果发布与缓存占用统计共用排他缓存锁；统计期间界面不能取得读取租约，而新结果原有的 10 秒保护仍按墙钟消耗。回收前的容量统计同样可能超过保护期，正在浏览的 90 秒租约也有相同风险。

内存中的结果保护、浏览租约和客户端缓存会话改用同一个单调计时器：取得排他缓存锁后暂停，释放锁前恢复。只有界面能够取得缓存锁的时间才消耗 10 秒交接窗口和 90 秒租约/会话期限。暂停由锁守卫负责，覆盖正常返回和错误提前返回；底层互斥锁不再向调用方公开。

这项规则覆盖后台结果发布、同步复用结果、范围捕获、范围排序、读取租约、缓存维护和其他已有排他缓存操作。长时间维护不会使锁内仍有效的保护过期，进入锁前已过期的保护也不会恢复。未被界面接管的结果会在可用交接时间耗尽后正常接受容量回收；浏览租约释放及显式结束会话仍立即生效。

查询族的持久闲置时间、用户设置的容量、项目引用与固定成员规则保持原有含义。计时状态仅存在于引擎进程内；无需数据库迁移或接口契约变更。此修复不减少同步容量统计的 I/O 或持锁时长，也不改变缓存空间的分类核算。

回归测试使用可推进的测试墙钟和独立 SQLite 项目，在零容量策略下模拟 120 秒发布统计与 180 秒缓存维护，验证结果及会话仍可由界面接管、浏览释放后成员可回收、无人接管时按期释放、复用结果独立获得交接窗口，以及错误返回不会留下暂停状态。
