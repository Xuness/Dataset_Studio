# 0054：Pixiv 浏览器登录助手与验证后保存

日期：2026-10-03。继承 [0053](0053-pixiv-public-operation-and-incremental-refresh.md)。本轮以用户的邮箱、密码登录方式为主要路径，沿用现有账号、加密存储和后台 HTTP 采集。

## 登录窗口与凭据交接

Windows 桌面版在“设置 → 数据湖 API → Pixiv”提供“通过浏览器登录”。原生宿主打开官方 `accounts.pixiv.net` 登录页；用户完成登录和必要的交互后，回到设置点击“已登录，验证并保存”。Web 模式继续提供已有 Cookie 导入入口。

窗口使用 Studio 独立的 WebView2 InPrivate 配置。每次开始时先在空白页清除该私有配置的数据，用一个临时 Cookie 确认异步清除已作用于 Cookie 存储，再导航到官网。不会清除日常浏览器或 Studio 主窗口的登录数据。账号密码只输入官方网站，助手不读取密码字段。

Cookie 通过原生接口读取，限定 Pixiv 的两个网页地址及允许的域、路径、有效期和大小。过期及其他网站 Cookie 被排除，传递时固定只用于 HTTPS。Cookie 不进入 React 状态、前端 IPC 响应、日志或采集归档。宿主直接请求当前受控引擎的 loopback API，禁止代理和重定向；后端继续用 Windows DPAPI 加密保存。

前端模块只依赖 `CollectionLoginAssistant` SDK 端口；Tauri 调用集中在 platform。桥接 DTO 与 HTTP DTO 共用生成契约。原生命令同时核对主窗口标签与应用来源，登录网页不能获取引擎连接或调用助手命令。

## 验证与保存的事务边界

新增 `POST /v1/source-collections/accounts/{id}/authenticate` 和对应 SDK、worker 操作。请求沿用 `SaveCollectionAccount`，仅允许 `mode=session`，响应为 `CollectionAccountProbe`。

候选凭据先请求 Pixiv 确认账号身份，验证成功后才在同一数据库事务中写入加密凭据、身份绑定、验证状态与幂等回执。网络请求前后均检查修订号；已有账号的绑定身份不能被另一个登录身份替换。登录失败、账号不匹配或验证期间清除凭据，都不会覆盖之前的账号状态。网站在验证过程中轮换的 Cookie 会随成功结果保存。

请求键的参数摘要也经过 DPAPI 保护。响应丢失时，原生宿主保留同一候选请求并进入“结果未确认”，重试仍使用原请求键，避免重复保存或增加修订。该状态可以跨设置页刷新恢复，即使登录窗口已关闭也可确认结果；确认期间不允许把未知结果误报为已取消。

登录身份确认仍不证明 R-18、R-18G 或 AI 显示条件，这些字段保持独立、未知时不作推断。保存账号不会自动新建采集任务。

## 生命周期和兼容性

同一宿主最多保留一个登录流程，目标账号、修订和共享控制目录在开始时固定。引擎重启后可重新连接；控制目录改变时停止提交并要求重新开始。

关闭设置页面不关闭正在使用的登录窗口；重新打开可接续。取消、关闭父登录窗口或关闭主应用会回收关联窗口。等待登录的流程在状态检查或操作时执行 30 分钟有效期检查。流程和待确认请求仅存于宿主内存，退出整个应用后需查看已保存账号状态，必要时重新登录。

当前 Tauri/WebView2 宿主在新窗口回调中同步创建窗口会阻塞 UI，因此登录链接的子窗口改由宿主异步建立，最多三个，并随父窗口关闭。它们共享私有配置，但不承诺完整的 `window.opener` 语义。第三方身份提供方在嵌入窗口中的兼容性仍需分别验证；本轮不把通用 OAuth 兼容列为已验证能力。

测试宿主与正式程序共用桥接模块，通过原生构造参数选择隔离测试页面；测试 URL、Cookie 注入和退出命令不属于正式应用的 IPC 接口。真实账号登录成功仍需用户亲自在官网完成登录后验证。
