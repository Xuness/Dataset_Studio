# 0022：工作集排名位置定位

## 语义与接口

排名浏览保留 Danbooru ID 起点，新增 `start_rank` 正整数字符串及可选 `start_rating`。

- 未指定 Rating：定位当前固定范围、当前查看顺序中的第 N 个成员，从 1 开始。降序下第 1 位是反向榜单的首项。总榜保持既有 Rating 分组顺序，不跨 Rating 重新评分或混排。
- 指定 G/S/Q/E：定位评分材料中、当前排名类型对应的原始第 N 名。仍受工作集或查询结果的固定成员范围约束；被筛选排除的名次明确报错，不跳到相邻名次。并列名次取当前方向的首个成员。
- 输入顺序支持总榜位置，没有 Rating 名次；V1 材料的直算/融合顺序沿用既有主排名回退。
- 两类排名定位都包含目标图片，后续沿当前方向继续浏览完整范围。定位不改变成员、筛选、评分、选择范围或榜单数据。

ID 和排名起点互斥。排名游标签名绑定数字和 Rating，恢复游标时核对目标成员。未使用排名起点的签名算法不变，旧 ID 起点和分页书签继续有效。

## 有界位置读取与缓存

固定范围索引每个排序新增 `rank_positions(order_name, sequence, ordinal)` 稀疏位置表，每 128 个成员保存一个书签。构建时沿已有覆盖索引顺序生成书签，使用既有构建取消、内存/磁盘预算、后台队列和原子发布机制。数值跳转先直接取相邻书签，再向前读取至多 127 个成员，不使用大 OFFSET 或重复全表扫描。降序位置转换为对应正序位置后复用相同书签。Rating 原始名次直接查既有 `(rating, rank, ordinal)` 索引。

完成标记新增 `position_stride=128`。缺少该标记或位置表的旧派生缓存，在打开时按既有失效流程重新构建一次；原工作集、查询结果、排名材料与数据湖无需迁移。首次准备成本随成员规模增长；准备好后，位置、方向、每页数量和顺序变化共用同一索引。

## 界面与状态

定位栏提供 ID、总榜位置及 Rating 名次入口，并说明两种数字口径。空值、非正整数、超大整数和总榜越界在界面校验；不存在的分级名次由引擎明确反馈。切到输入顺序时清除分级名次起点。起点、Rating、已解析游标与页历史一起保存；旧会话缺少新增可选字段时正常恢复。普通排序、重置起点和旧 Rating 筛选升级会清除排名起点。

## 验证

存储测试通过独立排序核对稀疏成员、Rating 跨组、空名次、并列名次、书签边界、首尾位置及 V1/V2 顺序，并限制大位置读取的 SQLite 指令数。API 集成覆盖分页、页大小、重启恢复、稀疏查询、缺失名次、输入校验和游标篡改。真实 React 与隔离引擎的 UI 测试覆盖两种入口、正反方向、刷新恢复、重置和错误提示。
