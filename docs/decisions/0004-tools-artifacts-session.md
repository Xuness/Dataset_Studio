# 0004：注册算子、项目成果与编辑会话

日期：2026-09-08。状态：已实施并验证；读取调度和持久缓存见[独立决策](0005-read-coordination-cache.md)。

## 分层与注册

`studio-domain` 保存版本化身份和值状态；`studio-application` 定义纯计算算子与存储端口；`studio-operators` 注册内置实现。算子只接收固定输入，没有文件、来源、网络或窗口访问。引擎负责来源投影、独立执行器、发布和 HTTP，项目数据库负责成员及引用事务。

前端模块通过 `@studio/ui` 的 `ModuleRegistry` 显式声明入口、视图、面板、命令及草稿模式。启动时拒绝重复身份、未知贡献类型、协议不兼容和悬空命令，中央视图与查询面板按需加载。应用框架传递公开 SDK、范围引用与回调，不要求用户按工具顺序操作。首轮不是可执行任意外部代码的插件安装系统。

## 固定任务输入

提交保存规范化参数、实现版本、参数模式、必需字段及来源版本。SQL 事务固定实际成员，并保护消费的查询结果和成果。数据湖范围先使用既有后台结果捕获；固定范围复用后端成员关系，不经过前端全量 ID 数组。

字段准备阶段要求提交时的来源版本仍然匹配，读取中和计划发布前再次检查。来源已更新时明确失败；不以新值替代无法再取得的旧值。完整 `input.jsonl` 中保存字段值、资产粒度、来源记录、观察身份和判定规则，并由计划中的 SHA-256 校验。执行和重试只读取该材料。

首轮字段包括存储字节数、来源宽度及固定标量成果。来源宽度使用**按身份字典序排列的第一条关联来源记录的原始观察**，不替换成同帖子较新的其他观察。无来源记录、无原始观察或未记录宽度均显式为缺失；依据中的相应身份保持空值。

`core.manifest` 保留旧清单形状；没有附加字段时可验证旧任务输出。`core.scalar` 计算有符号 64 位整数的乘加，参数采用十进制字符串。溢出是单项失败，其他对象继续处理。进度协议 v1 限制单条消息 4 KiB，输入输出行限制 1 MiB，执行计划和检查点分别限制 1 MiB 与 64 KiB。取消会终止独立执行器；显式重试等待旧尝试退出，沿用逻辑任务与已固定输入，并增加执行尝试。

## 成果材料与发布

一个算子可声明多个输出；标量算子分别交付完整值表和单项失败表。输出身份按 `(job_id, output_id)` 唯一，重启恢复不会重复登记。重新提交的新逻辑任务生成新的成果版本。

父进程根据已注册实现重新验证主输出的每一行，生成其余声明输出和校验清单。受控文件落位后，项目以 `publishing` 状态分批建立索引；所有成果及任务成功状态在同一事务中公布。发布中断后重新验证已有文件、重建不完整索引并复用原成果身份。取消或校验失败不会把部分材料显示为完整成功。

当前单标量材料采用有模式的 JSONL 加 SQLite 类型化标量投影：项目数据库按成果、资产身份和整数值建立索引，API 用 keyset 分页，单次最多 128 行，写入批次最多 256 行。查询按来源产生的有界候选批次读取项目标量索引。此决定适用于首轮单个整数列及清单，不声称 JSONL 是列式格式；宽表、向量和大型多列材料需要按具体工具的读取模式再引入列式文件实现。

成果目录保留文件列表、内容校验、算子与参数、输入范围和校验、消费的成果版本及执行尝试。具体字段值与观察依据位于固定输入材料及相应输出行中。旧任务成果保持原路径；升级时只登记为 `legacy`，首次读取该成果再验证原清单或文件。无法证明的旧参数和字段依据保持未知。单个旧成果不可用不阻止打开项目。

`project.<artifact-id>.value` 是不可变的资产级派生字段。查询普通比较只接受可用整数；`is_missing` 只接受覆盖范围内的字段缺失，`is_present` 只接受已计算的可用值。单项失败、未计算、范围外及零值保持区别。原湖字段和观察规则不因加入派生条件而改变。

保存查询、查询结果、任务输入及消费成果均登记引用；通过结果保留的工作集或选择也间接保护这些依据。释放成果先在事务中检查引用并登记墓碑，再清理该成果列出的受控文件及索引。已有消费任务的输入依据继续受保护；缓存维护不接触成果目录。

## 编辑状态与正常关闭

项目草稿按模块与实例隔离，保存模式版本和 CAS 修订；单份最多 64 KiB。旧 `drafts` 内容保留，新记录使用 `tool_drafts`。未知或更高版本草稿不自动覆盖。查询编辑、已保存定义与已提交任务各自独立；恢复不会执行任务。

SDK 每个草稿身份维持一个串行写入流，以 400 ms 合并编辑；在途响应只更新自己的修订，不替换较新的本地值。控制器可跨功能卸载和引擎重新连接保留。并发冲突保留本地编辑，界面提供明确的重新载入或保留本地并保存操作。

项目切换和原生关闭等待已接受的保存；超时或冲突时保留窗口并显示原因。强制终止、页面突然重载和开发热替换只保证已落盘内容，尚未发送的最后一小段输入仍可能丢失。正常关闭不依赖 `beforeunload` 的异步请求。

项目会话保存当前视图、面板、范围、焦点身份、当前分页游标及稳定锚点；不保存全量浏览历史。恢复验证对象和范围，未知模块、失效结果、无效游标和不可用焦点具有显式回退。选择输入保存原修订，变化后必须重新绑定。面板显示和缩略图密度位于应用偏好中，不写入数据湖或历史任务参数。

## 兼容与验证

项目数据库升级至 v4，应用注册表至 v2，项目清单仍为 v1。旧模式升级前保留包含 WAL 已提交内容的一致备份。旧选择、工作集、任务、查询、事件和成果路径不由迁移重写；日常项目已通过升级前后全表与原成果哈希核对。

可重复验证入口为 `pnpm check`、`pnpm test:integration`，其中 `tooling/client-foundations.mjs` 和 `tooling/integration-tools.mjs` 分别验证前端协调协议与真实引擎链路；两万行标量验证位于 `tooling/integration-artifact-scale.mjs`。原生窗口报告位于 `.local/reports/phase4-native-tools.json`。完整范围及日常升级结果见 [0.4 验收记录](../verification/verification-tools-resources-v0.4.md)。
