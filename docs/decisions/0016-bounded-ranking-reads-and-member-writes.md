# 排名浏览复用、有界读取与成员写入

2026-09-11

千万级排名工作集的首屏可能先经过大量不属于当前查询的排名成员。改变页大小和选择状态不应重复支付这段成本。普通浏览的帖子摘要也不应在每次翻页时重复扫描数据湖。

## 浏览和计数

排名浏览缓存首屏已匹配的成员前缀（最多 129 项，包含下一页判断项）和已经扫描到的位置，键包含项目、固定范围、排名成果及保存筛选、查看顺序和方向、起点 ID，不包含每页数量。修改页大小仍回到第一页：较小页面取已有前缀，较大页面从已检查的位置继续，准备尚未完成时也保留进度。每个 512 候选批次完成后记录进度，单次仍最多检查 4,096 候选；已足够显示页面时不会为了凑齐 129 项继续穿过下一个稀疏空档。缓存最多 128 个条目、闲置 30 分钟过期；不保存数据库句柄、完整成员或项目租约。引擎重启后可重新准备。客户端最多保留 32 个非活跃图片页、60 秒回收；未完成页面即时重新读取，不被当作稳定结果。

这是对最初“只保存第一张位置”方案的修正：当前帖子筛选可能包含旧排名 E 分段里的少量 S 图片，第一张与后续匹配之间仍有大量非成员。只记住第一张会在换页大小时重复扫描这些空档。相同范围的首屏推进串行执行、等待可取消，进度按阶段、已匹配数量和已检查数量单调更新，较小页面或迟到请求不能倒退已有进度。固定查询成员和评分时分级的区别保持不变，不把当前 S 条件错误地下推为旧排名 S 条件。

客户端游标中的“第一页”标记不能单独作为缓存依据。引擎最多保留 256 个实际返回过的首屏续读状态；只有这些状态或已有起点可以更新起点缓存。客户端改写标记仍可按已校验的成员位置读取，但不会污染默认首屏。旧游标和重启后的游标继续可读，缓存资格需要重新建立。

选择状态通过独立的 `selection/members` 读取当前页最多 128 个成员，返回同一快照中的选择修订和标记。选择变更只使该查询和选择信息失效；以当前选择为输入的浏览仍由选择修订改变范围身份。

排名工具分页按照分级和排名索引逐段 seek，不再对全部分级的资格成员临时排序。每次接口读取最多检查 4,096 个候选，稀疏条件通过受校验的准备游标续接。已有摘要可证明的计数直接返回；其他条件由独立 `ranking/count` 请求每次统计最多 262,144 行。最多保留 64 个计数进度，同一不可变成果及条件共享进度，取消不会累加半次扫描。计数和分页互不等待。筛选输入稳定 180 毫秒后发起读取。

SDK 和引擎只对白名单中的 POST 读取接入 `x-studio-read-id`：排名浏览、排名表行、排名计数、选择标记、图片摘要。写入 POST 不按只读请求取消。排名 SQLite 读取受 Index 准入与 progress handler 控制；元数据的取消标记一路传至 DuckDB，保留现有超时预算。

## 应用侧身份索引

新增 `browse-index/<source-id>.identity.sqlite`，将图片 SHA 映射到来源记录及帖子摘要。构建由后台 NativeQuery 预算管理，每个索引最多 8 GiB，并纳入来源索引空间统计。首次构建使用应用缓存目录中的私有文件，完整提交后替换目标；后续使用数据湖变更序列增量更新。generation/sequence/batch 锚点不匹配时重新构建，取消或错误保留先前已提交版本。格式版本为 1。

普通图片页先返回成员和预览所需信息；身份索引尚未就绪时，摘要标为 preparing，由独立 `assets/summaries` 补齐。详情读取按索引取得有界 record ID，再使用来源已有的记录主键索引。生产引擎不再按图片 SHA 在 DuckDB 中为每页重复扫描。数据湖数据库、图片及已有排名文件保持只读；首次建立索引仍需要一次后台元数据遍历，准备时间没有被伪装为零。

## 项目读写与缓存统计

项目保留单个串行写连接；普通只读操作使用短 WAL 快照，与写连接的 Mutex 分开。最多缓存 4 个闲置只读连接，每个连接使用 4 MiB 页缓存，请求退出即结束事务。读者只能看到完整提交前或提交后的状态，不能看到半个工作集或半个任务。

`meta.query_storage_revision` 在查询成员物理变化的同一事务中递增，旧项目缺少该键时按 0 读取，不需要项目结构迁移。容量快照绑定此修订，成员数使用已有 `stored_members` 汇总，精确 dbstat 页统计移出项目写锁和引擎租约/回收锁。陈旧统计不能驱动回收，写入忙碌或配置变化时重新规划；每轮只回收一个成员家族后重新统计。显式清理意图在重试期间保留。此前的租约时钟保护继续生效。

## 大规模成员固定

排名工作集保存按 512 个排名候选批次读取和插入，不做重复 COUNT 预扫描。任务提交以及来源查询完成后的任务成员固定按 32,768 个成员批次复制。两者保留一个原子写事务，避免改变固定成员语义；普通项目读取可同时进行。每批更新独立的进度记录，并检查取消标记；SQLite progress handler 也允许批次内部取消。错误或取消回滚全部未发布成员，清除回调和附加数据库后才复用写连接。

进度记录最多 64 个，已结束记录保留最多 15 分钟。`member-writes/{id}` 读取进度，`member-writes/{id}/cancel` 发出取消；排名工作集保存和任务提交使用各自的幂等请求键，后台固定使用任务 ID。界面在提交和保存期间显示进度及取消按钮。已提交结果不因迟到的取消而改变，重复请求仍返回同一对象。

## 验证约束

隔离测试覆盖写锁持有期间读取已提交快照、缓存修订失效、写入一批后的取消回滚与再次提交、索引增量及取消、排名分页 SQL 工作量、旧游标兼容、源文件哈希不变。32,768 对象的 API 夹具确保 G 范围及其前置 E 段都大于 4,096；真实 React 界面验证页大小、过滤和选择请求次数。所有规模测试使用 `.local/test-runs`，不对真实数据湖做写入或重复全量排名。
