# 0005：读取协调与可重建预览缓存

日期：2026-09-08。状态：已实施；原生窗口、并发夹具、持久缓存故障恢复及指定真实范围均已验证。

## 端口与预算

`studio-domain` 表达资源类别、优先级、预算与统计；`studio-application` 提供 `ReadResources`、取消信号和有界 `MediaSource` 端口。`studio-resources` 实现调度与缓存，引擎负责 HTTP 订阅、批次组装及图片处理。计算算子保持纯函数，来源字段准备通过资源端口获得准入。

| 类别 | 并发 | 等待上限 | 同时预留字节 |
| --- | ---: | ---: | ---: |
| 索引及相应项目读取 | 4 | 64 | 128 MiB |
| 来源媒体 | 1 | 32 | 64 MiB |
| 图片解码 | 2 | 32 | 512 MiB |
| 原生查询及元数据 | 2 | 32 | 512 MiB |

交互、后台、预取按优先级安排；每四次按优先级准入后，最早等待的请求获得一次机会，避免后台及预取长期饥饿。已经获得资源的工作不会被强行抢占。原生查询保留两个槽位，每次预留 256 MiB；当前只运行一个后台查询构建，另一个槽位可供检查或字段准备使用。

预算控制准入与缓冲规模，不是整个进程 RSS 的硬限制。原生查询仍使用自身的 256 MB 内存和协作中断设置。统计提供活动量、等待量、预留峰值、累计等待、实际来源载荷读取量、包打开次数、解码耗时及取消完成延迟；Windows 另提供引擎进程的工作集、峰值工作集和私有字节。示例来源的图片生成时间计入来源读取时间；来源字节计数只记录实际媒体载荷，不包含 SQLite、目录元信息或操作系统缓存内部流量。

## 共享请求与取消

预览按内容及渲染键合并，SDK 同优先级请求也共享传输。前台加入尚未完成的预取时，通过独立订阅提升同一后台工作的优先级。某一使用者离开不会撤销其他使用者；最后一个离开后取消共享工作。

客户端同时中断 `fetch` 并发送显式取消请求。`GET media` 可使用 `request_id`，有信号的项目 JSON 读取使用 `x-studio-read-id`，取消统一进入 `POST /v1/projects/{pid}/read-requests/{id}/cancel`。请求键带项目身份；提前到达的取消保留 60 秒，最多 1024 条。活动订阅最多 256，生成工作及等待队列各最多 128。关闭项目在保存编辑后等待自身取消确认，再释放项目视图。

等待资源时每 20 ms 检查取消；媒体载荷每个至多 64 KiB 的系统读取前检查。解码库调用前后检查取消，已经进入系统 I/O、内容哈希或解码库的单次调用不能硬中断。验证分别检查界面/传输脱离和后台真正停止；排队的真实包读取夹具在取消后没有打开媒体包、读取载荷或生成缩略图。

## 物理批读与预取

单批最多 16 个对象、64 MiB 编码输入。来源适配器重新核对当前索引长度不超过已准入的逐项字节上限，再按包路径、偏移排序，复用同包文件句柄，并把结果还原为调用者的逻辑顺序。来源内容经过 SHA-256 校验。索引变更不能使旧准入预算被静默放大。

预览 API 的 `max_source_bytes` 可以进一步限制冷生成的源读取；已有可用缓存仍可在零源读取预算下返回。该预算不进入内容键。

首轮预取是页面稳定 450 ms 后读取下一页最前面的四个对象；使用已有 keyset 游标与范围，只取四条索引记录。页面、范围和模块切换撤销等待及预取。可见图片通过可见性观察器请求，没有全湖预热和媒体目录递归扫描。

## 缓存身份、验证与离线

默认目录为应用数据目录下的 `preview-cache`。可用引擎 `--cache-dir` 或进程环境变量 `STUDIO_CACHE_DIR` 指定目录；该目录必须为空或带有应用自己的版本标记。缓存控制文件与材料目录不能是指向其他位置的链接。

键包括来源种类、逻辑来源 ID、资产身份、内容版本、尺寸、缩放规则、渲染和编码标签。Danbooru 使用库身份及内容 SHA-256；示例来源使用生成器版本。路径重新关联及追加索引不改变已有内容身份。改变渲染语义或影响输出的依赖时必须提升对应标签；未知来源不能退化为仅按本机路径缓存。

命中前仍验证当前项目已加入来源。在线检查库身份及对象目录成员；离线只允许来源路径不可用时使用先前校验过的缓存。对象不存在、库身份不匹配和格式错误均不会被离线命中掩盖。每次磁盘命中校验缩略图长度及 SHA-256；源图片 SHA-256 在实际读取载荷时校验。

“来源上次验证”表示最近一次库身份及目录成员验证，并不表示命中时重读了原图。离线响应保留上一次验证时间，原生图片视图显示“离线缓存”。SDK 内存复用最多延后重新请求 15 秒；已经显示的图片不是持续检测磁盘在线状态的监视器。

## 生命周期与恢复

缩略图先写受控临时文件并同步，再原子落位，最后登记 SQLite 索引。未登记材料和中断写入按批清理，损坏条目在使用时失效并重新生成。缓存索引损坏时隔离旧索引并重建；独立原子配置文件保留用户配额和未完成清理意图。

默认配额 2 GiB，界面可修改并持久保存；0 表示停止保留新缩略图。按最近使用顺序淘汰，持有读取引用的条目暂时保留。一次清理操作会在后台分批继续，重启后续做，完成前的新预览暂停写入缓存。启动和周期维护每次最多扫描 128 个材料目录项，配额淘汰与显式清理也使用有界批次。

配额衡量登记的预览载荷。SQLite、配置文件、隔离的损坏索引以及待扫描的未登记材料另占少量或待回收空间；统计明确显示维护状态。所有清理都限于缓存管理的固定文件名，不进入项目的 `artifacts`、`.staging`、`.backups` 或原湖。

## 可重复验证

- `studio-resources` 测试优先级、公平性、取消、字节上限、LRU、在用保护、重启、损坏及分批清理。
- 来源适配器夹具检查真实文件打开/偏移顺序、逻辑返回顺序、取消及准入长度变化。
- `tooling/client-media.mjs` 检查订阅取消、前台提升、晚到响应、关闭确认及内存引用。
- `tooling/integration-resources.mjs` 使用 96 张有实际载荷的合成图片，通过独立引擎验证共享读取、缓存、来源身份、离线和成果隔离。
- `tooling/verify-reads.mjs` 接收 1–8 个显式 SHA-256 身份和总源字节预算，记录冷应用缓存、暖缓存及引擎重启；不清空操作系统或设备缓存。

本轮真实验证由一个指定对象扩大到最多四项、总量不超过 2 MiB 的范围，实际读取 720,678 字节。D 盘缓存位置已确认是 NVMe SSD；E 盘媒体经 USB 挂载，Windows 未报告 HDD/SSD 类型。因此本轮数据证明实际包读取和缓存复用，不声称已完成冷机械盘或全湖吞吐压测。
