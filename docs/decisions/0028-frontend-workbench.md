# 0028：公共工作台与编辑器布局

日期：2026-09-23。状态：首轮已实施。验收见[工作台验证](../verification/2026-09-23-workbench.md)。

## 问题

固定全局侧栏与功能内部布局并存，控制项和配置长期占用内容空间。美学排序的离线结果已经有 SDK，但尚无以排名图片为中心的浏览入口。

## 决策

建立 `@studio/ui` 公共工作台，统一面板身份、位置、标签组、尺寸和隐藏恢复。业务组件提供面板内容，不能在 UI 中另建传输或拟合逻辑。编辑器布局存入独立的应用偏好键；项目会话保存已打开功能及当前内容，旧会话缺失新字段时兼容补全。

第一阶段保留每功能单实例标签，后续多实例内容编辑器另行版本化。关闭标签只影响呈现，不删除对象、不取消任务、不清空项目选择。资料浏览和美学排序共同验证接口的通用性。

浏览筛选、定位和评审状态采用公共面板 Portal：业务状态留在所属视图中，DOM 宿主随停靠位置移动，非活动标签保持挂载。避免标签切换丢失未应用条件，或中断查询结果向浏览范围的交接。项目查询同样进入停靠面板；不再占据中央内容上方。首要设计基准为 2560×1440、100% 缩放，150% 为远程控制兼容场景。

排名浏览使用 `client.aesthetic.analysis`，遵守 Rating、分量、并列、未知稳定性与复核水位规则。独立任务列表采用有界分页；媒体通过公开媒体接口获取并释放。业务重试与布局恢复互相独立。

不修改后端 DTO、公开 HTTP 路由、数据库或付费执行语义。完整设计、分阶段边界和官方参考见[工作台设计](../design/frontend-workbench.md)。
