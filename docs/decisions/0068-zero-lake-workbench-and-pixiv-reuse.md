# 0068：从零建湖工作台与 Pixiv 元数据复用

日期：2026-10-07。承接 [0065](0065-empty-lake-initialization.md)、[0066](0066-booru-tag-discovery.md) 和 [0067](0067-query-coverage-and-metadata-catalog.md)。

## 工作台和本地选择

四来源共用创建/登记入口；创建后可通过现有来源接口加入当前项目。入湖任务仍归共享控制器管理，项目只持有来源引用。创建成功但关联失败可原请求重试，不重新生成湖身份。

Booru 独立元数据目录使用公开 SDK 和有界后端分页，不借用只返回图片对象的项目查询接口。一次搜索固定读取版本；选择上限为 10000 个帖子。选择或整个条件转入更新表单时携带标签、ID 边界、缺图条件和版本，不把显示截断的标签用于求值。未应用的表单变更禁止提交旧列表选择。

`range.kind=tags, source=local` 增加 `missing_media`。即时任务可使用目录版本；预约和周期定义不得携带临时版本，后端明确拒绝这种定义，界面创建计划时主动省略。已创建即时任务仍使用已有持久租约保护冻结范围。

## Pixiv 条件与缺失值

`CollectionScope.tags` 可选，包含 all/any/none 的完整标签名称。省略时保持旧任务定义与幂等身份；空格不分词。完整标签条件在同一个作品观察上求值，未命中的详情仍归档，媒体不入队。

新观察在来源字段中记录 `pixiv.tags_known`。未知标签的筛选任务以 `COLLECTION_TAGS_UNKNOWN` 标记缺口，不当作已成功排除；读取端的缺失值和负标签查询遵循同一语义。旧观察没有该字段时保留原查询行为，采集复用对无法确认标签的旧记录保守复查。

## 保留观察与媒体规划

近期详情、清单和访问条件相容时，可以复用元数据，即使图片尚未齐全。已完整的媒体计入 retained，缺失媒体从原不可变清单每次读取最多 64 项，并保留下一页位置。动画帧和单页规划受条数、字节预算约束；没有重新生成抓取时间或复制一份详情观察。

计划使用冻结提交序号内的不可变资产/对象证明已有文件，而非依赖可被版本维护清除的临时视图行。缺失或截断的已发布包明确报告完整性错误。详情新鲜而清单不存在、过期或不相容时，保留原详情，仅抓取所需媒体清单。

复用依据、逐页媒体任务和后继清单页通过既有归档回执及控制事务回放。控制写入中断后可恢复，重复回放不重复计数。作者目录的批量复用和独立作品任务使用相同规则；已知标签排除也遵守新鲜度与访问条件，未知标记继续复查。

## 兼容与验收

控制库升到 schema 14，阻止旧执行器忽略新增的本地缺图条件或 Pixiv 标签条件。Booru 归档 1 / 在线 2、Pixiv 归档 2 / 在线 3 保持不变；无全湖转换。

验证包括仅元数据后零元数据 HTTP 补图、修改标签后复用原详情、70 页清单分页及控制回写中断、未知标签缺口、目录筛选/版本传递、四来源空湖创建和项目挂载。完整检查范围及限制见[阶段验收](../verification/2026-10-07-zero-lake-collection.md)。
