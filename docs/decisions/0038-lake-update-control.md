# 0038：全局数据湖更新控制与归档运行器

日期：2026-09-27。承接 [0037](0037-versioned-online-lakes.md) 与[增量更新计划](../plans/lake-incremental-updates-2026-09-26.md)。后端先交付，前端随后设计。

## 模块和持久状态

Studio 增加 `LakeUpdateBackend` 应用端口，领域层不依赖 HTTP、进程或 SQLite。引擎通过版本化控制协议管理 Store 运行器，DTO/SDK 公开任务、进度、范围、图片策略、凭据状态、固定输入和计划。入口为 `/v1/lake-updates`，任务不依赖某个项目存活。

共享控制库拥有计划、任务、凭据和执行队列，Studio 不再复制另一份完成状态。归档提交日志与批次保存数据接受事实，队列可重放已经接受的批次。控制目录是长期状态，调度定义和加密凭据不能视为临时缓存。来源登记验证 library_id、site、媒体根与在线根。

Store 将站点请求、协议、持久状态、标签参考数据、媒体准备、归档和调度拆开。旧 native 分析消费者仍可用，并支持重建新的 API 观察格式；在线发布不等待分析同步。

## 所有权与运行边界

运行器由 OS 文件锁排他拥有，每湖沿用 `.daily-run.lock`，由 `UPDATE-CONTROLLER.json` 绑定共享控制位置。旧归档 writer 也加入同卷写入准入。网络及编码在事务外，发布维持既有 online v2 保留版本协议。

凭据通过本机请求正文或标准输入传入，DPAPI 加密持久化，不进入命令行参数、状态或日志。API 与图片端点分别受站点域限制。HTTP 错误原文存档前清除可能被回显的 API Key。控制库与归档日志使用已经修复 WAL 问题的 SQLite 运行时。

窗口与任务生命周期分离。引擎监督运行器，正常退出通过通道通知停止，异常退出从锁释放及持久检查点恢复。系统关机期间不会执行任务，代码不会安装操作系统定时任务。

## 数据和范围语义

日期、ID、变更序号及本地观察范围分别表达；时间采用明确偏移和左闭右开区间。最后修改时间只代表当前 API 状态的筛选条件，不能当作完整历史事件流。无远端日期筛选时有界扫描，达到预算暂停。

保留 API 原文、帖子 JSON 子串、标签参考响应和已使用的分类上下文。Yandere 使用 deleted/holds/pending 参数；Gelbooru 使用两个 ID 比较条件，不能用被忽略的点号区间或逗号列表。返回范围、顺序和进展要经过校验。

元数据发布和图片补齐独立推进。保留旧图与升级图片版本是明确的策略选择。MD5 缺失时，native/online 仅接受同一观察直接产生的图片关系，避免给旧图附加未经证实的新元数据。

大型固定输入支持分块 ID 和对象 SHA 映射，保留全部来源帖子。草稿使用短租约，封存后生成持久输入和摘要。工作集/查询结果依托已有固定成员协议接入，不增加另一套查询索引。

手动、单次预约和周期计划共用任务协议。周期漏跑合并，单次执行后禁用。Gelbooru 独立删除事件游标暂未启用，未返回帖子不被当成已删除。现有 Codex 自动化不由本次接入修改。
