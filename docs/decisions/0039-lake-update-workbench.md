# 0039：全局数据湖工作台与固定更新输入

日期：2026-09-27。承接 [0038 更新控制](0038-lake-update-control.md)与 [UI / UX 规划](../plans/lake-updates-ui-ux-2026-09-27.md)。

## 应用与项目生命周期

数据湖更新使用独立 `ApplicationModuleContext`，不向项目模块传入空项目 ID。全局标签、布局和非敏感草稿通过既有应用偏好保存；项目浏览上下文仍由项目会话管理。“工具 → 数据湖”、起始页、项目来源菜单和底部活动入口指向同一编辑器。

任务不依赖编辑器组件挂载。关闭标签、切换项目和关闭项目不暂停更新。退出引擎停止其托管运行器；此功能没有安装操作系统常驻服务。原有 Codex 自动化不由新计划列表接管。

沿用公共 Workbench、停靠菜单、详情分组、对话框、主题角色和设置框架。中央提供更新任务、定时计划、项目范围准备三个视图，详情随选中对象变化；保持 2560×1440 的默认工作密度。

## 读取与执行状态

Store 控制库增量升级到 schema 3，增加任务时间索引、按湖/状态统计和问题索引，保留既有任务与加密凭据。时间游标绑定筛选条件；多状态查询分别从索引取有界页后合并，稀疏异常不通过遍历全部历史查找。任务页同时限制行数与约 2 MiB 序列化内容，避免大 ID 列表撑满控制通道。

运行器持有每任务的操作系统锁，返回 `execution_active`。暂停/取消请求可以先被接受；锁释放后才确认在途执行已退出。旧执行仍在退出时拒绝继续、重试或重新解析，后台状态更新也不能覆盖用户的暂停/取消。

元数据覆盖、图片状态、下载遥测分别呈现。未知总量不生成整体百分比；陈旧采样不显示为实时速率。图片原始策略没有新增全局默认，界面要求明确选择。多湖提交分别保存幂等键，网络结果不确定时续交同一请求，不重复派发已确认任务。

## 项目范围准备

新增 `/v1/lake-updates/preparations` 及其操作接口。全局登记库保存准备记录、原始 ScopeRef、来源版本、固定结果引用、成员游标和各湖输入身份。准备时以项目租约及结果引用维持后台读取，重启后可以重新取得后台项目连接。

来源/浏览视图复用已有固定查询构建。选择、工作集和固定查询结果则从单个项目读取快照枚举成员，以 512 条为批次写入临时阶段，再使用独立 `members.sqlite` writer 发布。大成员写入不占用项目控制 writer；项目库只登记封存结果头。这样提交后继续改变选择，不会改变已提交成员或使后续页面依赖新的选择版本。

后续映射按有界成员页推进，通过 Store 批量控制命令分块映射到该来源版本的全部关联帖子，固定输入以稳定身份去重创建。进度在批次接受后保存，重放一个未确认批次不会重复成员；封存后不再依赖项目成员。结束时释放内部结果引用及版本租约；若用户另行引用了结果，尊重已有引用，不强制清除。

初始冻结尚未发布固定成员时若进程中断，不将后来变化的选择当作原范围重跑；会明确要求取消该准备并重新选择。固定成员已经发布后的映射、封存阶段可以接续检查点。取消过程中出现路径或存储错误进入需要检查，避免无休止快速重试。

此扩展不改变既有项目格式 13 或在线湖格式 2。全局登记库新增准备表，Store 更新控制库需要相应的 schema 3 实现；只回退 Store 代码不能继续使用已升级控制库。

## 计划、凭据与可见边界

计划支持单次预约和固定间隔，创建时默认未启用。修订号保护编辑与删除；界面明确固定间隔、日历时间、固定日期范围的不同含义。相对日期和跨夏令时日历调度未加入。

凭据单独置于“设置 → 数据湖 API”，只显示保存状态，不回填密钥或保存到草稿。检测连接是显式操作。大范围更新不依赖前端保持打开；更新发布也不主动使项目查询失效或重置图片位置。

范围准备列表显示最近 100 条，底部状态汇总在途及异常准备。普通任务提供游标分页与状态/湖过滤。前端没有加入每帖选择性重试、完整删除事件发现、全湖覆盖日历或精确耗时预测；它们不由局部记录推断。
