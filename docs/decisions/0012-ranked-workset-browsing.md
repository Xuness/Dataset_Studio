# 0012：排名工作集的浏览顺序与 ID 起点

日期：2026-09-10。开发版本 0.9.1。

## 固定成员与查看顺序

工作集继续保存成员集合。来自排名的工作集已在 collection_scopes 中保存 ranking_artifact 与原 RankingFilter，并通过 artifact_references 保护原成果；这些已有信息用于恢复排名浏览，无需重新计算或改写已有工作集。

RankedScope 只沿明确的工作集来源或查询 input_scope 寻找排名依据。普通工作集即使引用某个成果，也不会因此被认作排名工作集。查询结果保留自己的固定成员，最多追溯 16 层输入范围。

浏览接口独立传入主排名、补救排名或输入顺序，以及方向和起点。未指定依据时采用工作集保存的顺序。成员条件始终使用原 RankingFilter；例如主排名前五名的工作集改为补救排名查看后，仍是原来的那批成员。

排序与原榜单保持一致：分级、相应名次或输入序号、固定 ordinal 构成稳定顺序；降序反向遍历这一完整顺序。名次是在分级内计算的，不另造跨分级总排名。空名次和缺失分数保留并明确显示。

## 有界读取

不超过 4,096 项的范围按主键取得固定成员，再从现有身份索引读取排名位置，在有界集合内排序。更大范围按评分索引游标读取，每批最多 512 行、每次请求最多检查 4,096 行。与当前排序索引不匹配的保存条件通过匹配标志和成员主键检查筛选，避免稀疏结果触发一次无界条件扫描。

一页额外取得一个匹配成员，用于确定是否存在下一页。未完成的一页最多在游标中保存 129 个 ordinal，并提供继续读取状态。游标校验项目、固定范围、成果与文件摘要、原筛选条件、查看依据、方向和起点；缓冲成员还会重新校验范围归属与顺序。

新增排名字段是 Asset 的可选信息。按普通帖子 ID 或图片身份查看排名工作集时也显示评分；非排名来源的读取不需要评分表。

## Danbooru ID 起点

用户明确选择：输入帖子 ID 定位它在当前排名中的位置，再按排名方向浏览。定位图包含在第一页第一项，不使用 ID 数值作为过滤边界，也不改变工作集的成员或“选择全部范围”的含义。

帖子 ID 以十进制字符串传输，验证为正的 i64，避免 JavaScript 数字精度丢失。不存在或不属于当前范围时返回 RANK_ANCHOR_NOT_FOUND。同一个帖子 ID 对应多个范围成员时，选择当前查看顺序中的第一个匹配成员。

新生成的固定输入在发布前建立可选 input_post(post_id,ordinal) 索引。已有输入保持只读，按至多 262,144 个 ordinal 位置分段查找，每步最多返回 512 个匹配项；界面显示进度并续接，切换范围或起点即可停止后续请求。

定位完成后返回可复用的首屏游标。项目会话保存这个游标、帖子 ID、排序、方向和分页位置，重开时不必重新扫描旧输入。游标与显示名称分离，重命名不会丢失位置。

## 兼容与界面

项目数据库仍为 v9，清单和排名材料格式仍为 v1。旧材料没有新索引时走有界兼容路径，原文件及其 SHA-256 不变。此次升级无需数据库迁移。

浏览设置使用独立的 rankedBrowse 项，不把排名顺序塞进原 QueryOrder。基于工作集应用标签或分级筛选后，查询成员仍按原查询规则固定，显示继续使用原评分。切换查看依据不会改变查询定义。

已有会话没有 rankedBrowse 时，排名来源范围默认使用保存时的榜单顺序；普通范围继续沿用既有排序。图像网格与单图查看都显示分级、主/补救名次和分数。方向控件说明名次或序号的大小关系，起点可显式重置。
