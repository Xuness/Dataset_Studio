# 项目数据范围与生命周期

日期：2026-09-08。对应开发版本 0.3.0。接续 0002，不修改已经保存的 AssetKey 身份。

## 字段与查询

字段目录由来源适配器返回，包含类型、单位、缺失语义、依据、显示能力、支持操作、排序能力和成本说明。目录描述的是实现能力；来源当前离线或索引损坏时，执行仍会明确失败。

查询协议 v1 最多包含 8 个项目内来源、12 个联合条件。来源和条件规范化后保存。条件值使用有类型的联合类型；64 位整数通过规范十进制字符串传输。只允许白名单字段与操作，客户端不提交 SQL。

| 字段 | 类型 / 单位 | 本轮查询能力 |
| --- | --- | --- |
| asset.id | 文本 | 相等、不等、范围比较、缺失判定 |
| stored.bytes | 整数 / byte | 相等、不等、范围比较、缺失判定 |
| stored.extension | 文本 | 相等、不等、范围比较、缺失判定 |
| post.id、score、fav_count | 整数 | Danbooru：相等、不等、范围比较、缺失判定 |
| source.width、source.height | 整数 / pixel | Danbooru：相等、不等、范围比较、缺失判定 |
| source.extension、rating | 文本 | Danbooru：相等、不等、缺失判定 |
| tags | 标签 | Danbooru：完整标签包含、缺失判定 |
| is_deleted | 布尔 | Danbooru：相等、不等、缺失判定 |
| stored.width、stored.height | 整数 / pixel | Danbooru 未记录，不支持查询，不从来源尺寸推断 |

缺失只指 NULL。空字符串、空标签和 false 均为已记录值；普通比较遇到 NULL 不匹配，包括“不等于”。没有关联观察的对象不参与元数据条件匹配。仅查询存储字段时，以 catalog 中全部存储对象为候选。

观察规则：

- `current_post`：通过 current_posts 选择关联观察和存储对象，所有元数据条件在该观察上联合判定。
- `any_observation`：同一来源记录所关联帖子的某条观察，或该记录的原始观察，必须同时满足全部元数据条件。帖子的图片内容可能变化；该规则不表示每条观察都描述当前存储文件，也不能用来源尺寸代替存储尺寸。

只支持按 `(source_id, asset_id)` 升序或降序。多观察元数据未定义归约规则，所以不声明元数据排序。界面提供单湖条件编辑，也能重算通过 SDK 保存的多湖定义；后端仍校验每个来源的能力。

## 定义、结果与固定成员

查询定义可按版本修改。每次构建生成新的项目内结果身份，并保存当时的规范化定义、定义版本、来源版本与观察规则。修改定义不会改写旧结果。

结果状态为 queued、running、ready、cancelled、failed、interrupted、released。构建由独立后台调度器执行；只有成功完成全部来源读取并通过末端版本检查，结果才能成为 ready。`count` 只在 ready 时返回准确的去重成员数；`processed` 是已处理候选记录数，可能包含同一存储对象的重复关联。没有隐式结果条数上限。

结果成员保存在项目自己的 result_members 表中，主键为结果 ID 与 AssetKey。客户端读取最多 128 项的游标页；游标绑定项目、结果与最后身份。界面每页可选 12/48/96 项，不缓存所有页面成员，导航历史最多保留 128 个游标。

来源版本变化后，旧结果的定义和成员保留。结果的 validity 接口报告来源是否仍匹配，直接浏览或消费变化后的查询范围会要求重新计算。此前已经固定到选择、工作集和任务的成员保持不变。版本水位和事务末端检查不提供跨库原子历史快照；它们依赖来源遵守其提交协议。

取消后不再发布结果。引擎重启可继续尚未开始的 queued 构建；已经运行的构建变为 interrupted，需要创建新结果重新计算。失败、中断和取消产生的部分成员不可用，可通过释放操作清理。释放前检查选择、工作集和任务引用；被引用的结果拒绝释放。释放清除数据库中的成员，空页可被后续写入复用，不保证 SQLite 文件立即缩小。

## 统一范围与选择

ScopeRef 显式携带 project_id 和以下一种目标：

| 目标 | 版本与含义 |
| --- | --- |
| source | 数据湖 ID + catalog 版本；使用前需要后台捕获成员 |
| workset | 项目内不可变的工作集身份 |
| query_result | 项目内已完成结果身份，使用时检查来源版本 |
| selection | 项目当前选择 + 乐观并发版本 |

跨项目范围被拒绝。焦点对象仅用于查看，翻页、查看原始元数据和切换观察不写入选择。

全选查询结果时，选择只记录一个结果引用，另存少量排除项与额外显式成员。替换、添加、移除、交集由 SQLite 完成，前端不传全量 ID。集合操作通过有界数据库缓存与临时关系执行；针对选择基底的相关查找使用单例标识和完整主键，避免逐候选扫描整个结果表。

当前选择的分页直接合并两个已排序的主键范围，排除项逐键判定；不在外层包装 UNION 后对剩余成员重复建立排序表。10 万成员夹具使用 SQLite 虚拟机工作量预算验证单页读取，同时覆盖排除、重复成员和末页额外成员。

保存工作集将实际成员复制为固定集合，同时保存范围依据和结果引用。工具可以使用已有工作集、查询结果或带版本的选择。清单任务还可以直接使用 source 范围：先创建后台捕获，任务处于 waiting_input；只有完整捕获成功才固定成员并进入执行队列。选择和工作集操作若输入 source，可先使用 scopes/capture 得到完成的结果引用。

非空任务的 job_inputs 在事务中固定，之后更改选择、重算或修改查询、关闭视图均不改变该任务成员。`input_members_frozen` 区分尚未捕获的输入和已经固定的成员；输入构建失败时不把未知数量显示为完整的零项输入。固定后的执行器继续使用原有检查点恢复机制。输入捕获阶段中断的任务明确失败，需要重新提交。

当前清单任务保存成员身份与执行时实际需要的存储属性，并记录输入范围及查询依据。元数据值没有被完整冻结；未来依赖元数据的算子需要另外固定必要字段，不能凭水位重建历史字段值。

## 项目打开、关闭与恢复

项目列表只读取应用注册表摘要及已有句柄状态，不遍历打开最近项目，不取得它们的写锁，也不触发批量升级。摘要不是项目当前可用性的证明。显式打开负责检查清单、取得独占租约、迁移和恢复项目；失败信息留在摘要中。

当前引擎中的项目视图和后台工作分别管理。关闭项目禁止新的视图请求；已经接受的请求和后台操作持有 Arc 租约，直到完成才释放文件锁。关闭返回 closed、background 或 draining。调度器只访问已经由本引擎持有的项目，并释放已经空闲的关闭项目。

原生窗口关闭前，SDK 等待已经发出的打开请求落定，并关闭该客户端打开的项目视图；引擎和后台任务继续独立运行。引擎级项目关闭也会让其他仍订阅该项目的页面收到关闭状态。单个项目并未实现多客户端独立视图租约。

注册表以保守的后台工作标记记录待恢复项目，先标记再入队，避免崩溃造成未登记的任务。启动后进行一次逐项目只读探测，只为确认有待办工作的项目取得租约。恢复在监听服务启动后进行，错误按项目隔离；离线、损坏、占用、未知版本不会使健康项目停摆。每个调度周期不重新打开全部最近项目。

来源位置由当前应用注册表共享，项目只保存逻辑身份和显示名称。普通添加不能静默覆盖已有位置。重新关联必须先验证新索引和图片湖仍有同一个逻辑 ID，再更新共享位置；只通知已有打开的引用，不为通知打开其他项目。独立引擎数据目录中的注册表不属于该共享范围。

## 模式、资源与边界

项目清单仍为 v1，项目数据库为 v3。v1→v2→v3 和 v2→v3 使用有序迁移及升级前的一致备份，保留旧账本、选择、工作集、任务、事件和成果关联。schema.sql 是冻结的 v1 基线，v3 定义位于 schema_v3.sql。应用注册表独立使用版本 1；旧无版本注册表升级前同样备份。未知未来版本在写连接改变 journal_mode 前拒绝。

应用只读数据湖。存储条件在 SQLite catalog 上执行；元数据条件经白名单编译后由固定的 DuckDB 1.5.4 原生 C API 执行。元数据候选以 [C data chunks](https://duckdb.org/docs/current/clients/c/data_chunk) 分批转出，最终去重和排序由项目数据库承担。创建流式结果使用该固定版本仍提供的接口；升级运行库时需重新验证接口、向量布局、中断和句柄释放。

- 同时运行一个结果构建与一个清单执行器。
- 每批最多转移 512 个身份；元数据 DLL 内部预算 256 MB、1 线程，禁止临时溢写和外部访问。
- 单个来源构建预算 600 秒，使用协作中断；查询规划、元数据检查与版本探测仍有短请求预算。操作系统文件 I/O 和句柄关闭不是硬实时边界。
- 256 MB 不是引擎或窗口整体内存上限。大型元数据连接可能明确返回资源不足；当前不承诺任意全湖条件都能在该预算内完成。
- 前端只持有引用、有界页面与短期检查数据。原始图片及元数据不复制到注册表，也不依赖归档 Python 运行时。

通用算子注册、完整派生成果目录、完整工具草稿、持久预览缓存和更复杂调度继续留给后续阶段。
