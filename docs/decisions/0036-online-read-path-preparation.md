# 0036：在线架构升级前的发布与预览并发边界

日期：2026-09-26。对应[升级计划](../plans/数据库架构审查升级-2026-09-26/README.md)的 P1。此阶段改善已有交互路径，不改变正式数据湖的读写所有权与来源版本语义。

## 查询成员发布

将发布实现从 `query_cache.rs` 抽入 `query_cache/publication.rs`。增量关闭成员按 `affected(source_id,asset_id)` 定位成员主键；全量来源仍需检查其既有成员。继续用 `post_id IS ...` 保持 NULL 与帖子关联变更语义，未变化成员复用原区间。

单结果族以已完成的 `latest_count` 为基线，分别统计关闭区间数与新插入区间数，计算准确的新成员数。初次构建基线为零，stage 的唯一键消除重复，成功插入数即首次准确成员数。`changed_members` 仍表示关闭数加新增数，不能作为净增量。

同一项目 writer 保护发布；还显式拒绝同族其他待执行/运行结果、错序修订、混用直接成员追加，以及尚未完成的重复发布。`meta` 中的 `query_publication/<result_id>` 记录与成员、计数同事务提交，在最终成功或回滚/恢复时移除；无变化修订也保留该临时记录，避免重复调用影响基线计数。

`finish_result` 仍在最终一致性校验后推进 family 水位并设为 ready。在此前，公开结果 API 隐藏总数，旧结果保持原成员视图。取消、失败及重启恢复不推进最新计数。全部成员变更仍使用一个事务，分块导入不是分块公开。

本阶段没有 project schema 升级、成员表重建或大库迁移。保留现有 revision 区间和成果引用格式。初次/全量结果发布仍可能长时间占用项目 writer；控制库与大成果隔离在 P3 处理。

## 小型项目读取

草稿读取改用现有 `ReadPool`，一个请求持有一个短 WAL 读取事务。保存继续使用项目 writer 和 `expected_revision` 校验；读取旧提交不授权覆盖新修订。评审账本与注册表职责不变。

## 预览缓存

`PreviewCache` 的全局状态互斥量只协调目录索引、计数与 pin/写入保留。缓存字节读取、SHA 校验、临时文件内容写入和 `sync_all` 在锁外完成。短暂的临时文件创建与登记、最终重命名与目录 SQL 仍在锁内，避免出现可见半文件或活跃临时文件被误判为孤儿。

读取在释放状态锁之前取得 pin，直至响应持有的材料释放。写入与删除按单个 key 保留独占权；读取/替换不能越过同 key 的删除，其他 key 可继续读取。校验失败在最后一个读者处将 pin 原子地转为删除保留，避免删掉并发修复的新文件。并发离线读取不能回退较新的在线验证时间。

`CachePin::drop` 只递减 pin 并标记维护待办；不执行 SQLite 写入、文件删除或 fsync。配额/清理及孤儿扫描在独立维护门内串行，文件删除在目录状态锁外逐项执行。活跃 `partial-*` 文件登记后才开始写入，扫描会跳过这些文件；重启后的孤儿继续按旧协议清理。

正在写入时发生 clear，`clear_pending` 持续到活跃写入退出，写入完成后丢弃该次保留。降低配额也在发布前重新核验。正常准入用已登记字节加暂存字节限制至配额加一个最大条目（16 MiB），避免延迟淘汰造成无界积压；已有 pin 在主动降配额时仍可暂时超过新配额，释放后分批清理。

引擎沿用每批最多 128 项的后台维护；持续冷请求的批处理循环也定期维护，避免延迟淘汰被持续请求饿死。管理端 clear/配额响应允许返回尚未释放的 pin 及待办状态。所有权标记、目录/链接检查、完整内容校验和单缓存管理者文件锁保留。

## 观测与后续边界

查询发布记录 writer 等待/持有时间、关闭与插入 SQL 时间、commit 时间和分开的变化计数。草稿记录读取时间以及保存等待/事务时间。预览 debug 事件记录锁等待、读取、哈希、写入、fsync 与维护时间；默认不开启逐图诊断。

仍存在目录 SQL/LRU 更新的串行部分和底层 SQLite I/O，不能承诺缓存命中完全无等待。并发测试证明字节 I/O 不再占用全局状态锁，不证明真实用户首屏 p95。来源历史视图、统一在线投影、直接返回查询页面和三站 API 更新属于后续阶段。
