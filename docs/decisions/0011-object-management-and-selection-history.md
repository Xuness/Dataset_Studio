# 0011：项目对象管理与选择历史

日期：2026-09-10。对应开发版本 0.9.0。

## 显示信息与历史数据

项目数据库升级到 v9，清单 format_version 保持 1，应用注册表保持 v2。升级继续先生成包含已提交 WAL 的一致备份。已有 incremental auto-vacuum 项目无需为了添加管理表再次执行全库 VACUUM。

名称、备注和整理状态保存在项目自己的 object_metadata。名称覆盖原显示值，不改写计算输入、评分表、输出文件、AssetKey 或历史参数。项目显示名随数据库移动，清单仍记录初次创建时的名称；注册表摘要与显式打开结果读取最新显示名。

数据湖取消关联使用项目内的状态标记，逻辑来源行及被工作集、选择、查询和任务保存的身份继续存在。本机位置注册和其他项目不受影响。普通来源列表排除未关联来源，显式图片、预览缓存和元数据读取检查关联状态；已有不可变计算表仍可读取。界面显示未关联项并支持恢复，同一个逻辑数据湖再次加入也能恢复。使用该来源的未结束任务或查询会阻止取消关联，新任务提交在项目事务内再次检查来源状态。

## 引用与删除

管理面板通过分页接口读取具体使用关系和来源关系，包含工作集、查询定义、查询结果、任务、成果、当前选择和选择历史。页面先显示阻止删除的关系；列表使用有界游标。成员归属通过主键范围的存在性检查确定，不把全湖图片身份传到前端。

- 工作集删除清理成员、范围记录和自身引用。已经固定成员的任务保留独立输入；仍依赖该工作集的保存查询和未完成查询明确阻止删除。
- 查询定义删除保留轻量记录和旧结果中的条件快照，解除定义自身的引用，后续直接读取、修改或重算已删除定义返回 OBJECT_REMOVED。界面保留正在编辑的条件草稿，允许另存。
- 任务归档只改变列表状态，支持恢复。清理已结束任务要求其保留成果已经释放，然后清理 job_inputs、自身的 job/job_input/job_scope 引用和受控暂存；保留标记及原参数用于说明历史。已清理任务不能重试。
- 成果通过事务中的引用检查登记 released，再逐文件清理受控 artifacts 路径。文件被占用时报告待清理，界面可查看剩余字节并重试；已释放记录可从列表重新找到。生成任务保留，任务列表明确标记成果已不可用。
- 工作集和任务的旧请求身份仍保留。已删除排名工作集的请求转入 retired_workset_requests；重放同一请求不会重新创建被用户移除的对象。

删除成功后，浏览范围和工具结果入口回退到可用状态。重命名不改变浏览身份、当前页及分页游标；旧会话中带显示名称的 scopeKey 在读取时兼容规范化。

## 选择撤销与设置

Ctrl+Z 撤销选择，Ctrl+Y 或 Ctrl+Shift+Z 重做。输入框、可编辑文本、对话框和菜单保留自己的键盘行为。历史仅针对图片选择、清空、范围替换、添加、移除及交集，不恢复被删除的对象或计算文件。

每步保存两侧选择基底、计数、来源引用，以及 selection/selection_exclusions 的净增删差量。项目事务内的触发器记录成员变化；单项编辑不会复制查询基底的所有图片。恢复时关闭记录，重放相应差量，重新核对计数，并推进选择修订。CAS 冲突、计数不一致及空历史不改动当前选择。

历史通过 result_references 和 artifact_references 保护两侧需要的材料。新编辑丢弃重做分支；清空和裁剪解除对应保护。缩小上限优先保留最近的撤销及连续的最近重做，不能留下断开的重做链。

本机设置默认 50 步，范围 0–200，0 关闭历史。已打开项目立即裁剪，关闭项目下次打开时应用。历史保存在项目数据库中，可跨引擎重启恢复；升级前的选择保留，历史从之后的新操作开始。存储量取决于实际变化的成员及被保留的材料，步数不是整个应用内存或磁盘大小的硬上限。

## 交互与复用

对象条目旁的“⋯”打开快捷菜单；右侧“属性 / 管理”相邻标签承载名称、备注、来源、使用关系和清理。排名与基础工具使用同一管理入口。未提交的名称备注草稿按对象保存，版本冲突需要明确处理。

工作集与成果列表支持名称/备注/身份查找、排序和分页。排名列表先在服务端按成果类型过滤，不再从最近 64 个混合成果中挑选排名。任务记录具有状态筛选、查找、分页、归档及恢复。

历史参数复用和项目内命名预设只修改工具草稿，不自动提交任务，不绑定当前选择。预设可独立修改名称备注、更新参数和删除；保存前使用注册算子规范化参数。

文件位置由引擎按项目对象解析，文件打开使用独立参数调用资源管理器，不拼接 shell 命令。界面提供完整路径的展开与复制；大成果可直接定位原文件。

## 构建产物

Tauri 会把 externalBin 副本复制到 target/<profile>。打包副本使用 studio-engine-sidecar，避免覆盖 Cargo 生成的 studio-engine。开发协调器继续使用按实际 EXE SHA-256 缓存的引擎；原生独立启动使用 sidecar 名称。pnpm check 准备该副本后再检查桌面宿主，并已核对桌面检查前后的实际引擎字节一致。
