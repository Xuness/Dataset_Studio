# 0040：Studio 内置更新服务与可配置图片配方

日期：2026-09-27。修订 [0038](0038-lake-update-control.md) 的外部 Store 运行器边界，扩展 [0039](0039-lake-update-workbench.md) 的固定保存策略。

## 所有权与交付

Studio 的下载和写入执行此前依赖另一个本机 Git checkout，导致源码、测试和发布不完整。将更新执行链及必要规范存储依赖迁入 `services/lake-worker/src/studio_lake`，与主项目统一检查。初始来源为 Store `00ec572`，保留文件摘要清单；不是运行时外部依赖或 Git 子模块。

服务仍以独立 Python 进程运行，Rust 接口和 domain/application 端口保持分层。构建引擎时嵌入服务源码，按内容摘要展开到应用数据目录，以 `python -I` 和固定 UTF-8 执行。GUI 不再要求 Store 仓库路径。旧配置中的路径仅为读取兼容而忽略，现有 Python 解释器、状态目录和湖位置继续有效。

Python 依赖由项目内 pyproject 及安装脚本声明，解释器与第三方二进制没有打包进引擎。CI 安装该环境并运行 Python 测试；引擎检查与完整 HTTP 集成都覆盖新服务。开发监视范围纳入服务源码。

保留旧 Store 仓库及原每日入口，不改变用户的自动化。Studio 不需要访问该 checkout。规范归档格式、库身份和在线投影语义保持兼容，无需全湖迁移。旧批次恢复所需的 legacy 代码纳入迁入闭包，避免出现“下载器已经迁移，恢复仍依赖外部仓库”的缺口。

控制库 schema 4 增加功能版本隔离。升级需要取得旧运行器和执行锁，先提交升级再释放锁。并发初始化重读版本；任务定义、检查点、幂等键、加密凭据、计划及固定输入保持不变。旧 Store 更新控制工具不能读取 schema 4；旧 `daily` 工具使用独立控制状态，继续通过既有湖锁和设备准入协调。

## 配方契约

保持三个旧 profile 的定义及字节处理，新增 version 1 自定义编码配方。支持 WebP、JPEG、PNG，可配置最长边、各格式适用的质量/无损/压缩参数、动画及透明背景处理。默认不放大；多帧可保留原文件或显式提取首帧。JPEG 必须选择背景合成或拒绝透明输入。没有新增全局默认策略。

服务端规范化并严格检查配方，以稳定摘要标识。所有参数进入任务和归档证据，执行阶段不读取可变 UI 预设。`existing=match_profile` 按配方身份查找资产，`keep` 保持既有复用规则；备用图片来源仍独立标注。旧图保留，新物理对象继续使用内容寻址，不因配方不同重复存储相同字节。

当前 UI 复用 UE 风格属性分组：快捷预设、自定义格式及条件字段、折叠编码高级项、命名预设管理。PNG 和无损 WebP 不显示有损质量。命名预设通过应用偏好存储，与项目分离；应用到表单后是独立副本，计划也固定参数，不随预设修改变化。
