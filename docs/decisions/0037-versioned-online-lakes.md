# 0037：保留版本的在线湖与独立固定成员存储

日期：2026-09-26。承接 [0036](0036-online-read-path-preparation.md) 与 [升级计划](../plans/数据库架构审查升级-2026-09-26/README.md)。正式切换及证据另见 [P2/P3 验收](../verification/2026-09-26-online-upgrade-p23.md)。

## 边界与选型

E 盘继续保存不可变图片包、完整观察、raw、schema 和归档日志。F 盘增加持续维护的 SQLite 在线投影。它是有身份、发布协议和保留责任的共享读取数据库，不能作为临时缓存随意删除。

Studio 的浏览、筛选、详情、身份定位和帖子排序直接读取在线库。原生 DuckDB 仍承担 Store 的离线分析、导出及生产者索引工作；Studio 不再打开正式湖的 native DuckDB。排名把保留视图中的有界输入捕获到私有分析数据库，再运行现有算法。

选择 SQLite WAL，是因为本机多进程读取与单发布者模型无需额外常驻分析服务即可落地。50,000 条真实观察的 Tag 实验支持整数词典加 FTS5 压缩倒排；该微型实验不能代表完整 DuckDB 服务的性能比较，也不证明 SQLite 对任意分析负载更快。

数据流：E 盘归档 → Store 每湖有序发布 → F 盘在线库 → 保留版本的分页视图 → 显式捕获 → 项目成员库 → 工作集、选择、任务。

## 在线协议 v2

ONLINE.json 绑定 library_id、站点、schema、代次及受控相对路径；媒体根的 online-index.json 供 Store 发现发布目标。活跃代次不被原地替换。

archive_seq 表示归档完成，served_seq 表示在线可见，analysis_seq 表示生产者分析完成。三者独立。新对象、资产、观察和 raw 先分块写入，帖子和对象排序使用 valid_from/valid_until 区间；唯一最后提交才推进 served_seq。

每湖 .online.lock 串行化发布及回收。SQLite 事务小批提交，网络、图片下载、封装、源文件解析和大块压缩不占用在线写事务。发布失败按归档日志和 pending_publication 指纹重放，稳定身份幂等插入；身份、文件摘要或提交连续性检查失败时不推进水位。

变化记录保留字段名，区分 score、tag_string、relations、media、raw 和新增观察。现阶段在线固定结果按显式捕获构建，不假称已实现所有字段的结果增量复用。

版本格式为 online-v2:<generation>:<seq>，多湖保存版本向量。首次迁移从一致基线 S 开始提供保留视图；更早的完整观察仍保存，但不会伪造 S 以前的“当时在线状态”。

请求之间不持有 SQLite 长事务。普通读取和浏览视图采用 30 分钟租约，活跃浏览自动续期；固定结果与任务永久保留其版本。释放结果、删除任务时释放对应租约。回收在短事务中检查下界和租约、删除过期区间；不删除归档观察、raw 或图片对象。

大型后台捕获采用分段读取时间预算，不沿用旧查询整个来源十分钟即终止的限制。交互请求仍保留其独立截止时间及取消信号。

## 查询语义

原始 Tag 以 BINARY 词典保存，仅 U+0020 分隔。制表符、换行、大小写与标点保持原意。FTS5 只索引持久整数 ID 生成的 ASCII token，不用默认分词器解释原始标签。

组合条件由同一帖子/观察满足后再映射图片。CurrentPost、AnyObservation 保持原有语义，缺失值不填 0 或 false。同帖换图时，当前元数据不自动归给旧 MD5 的图像。

普通查询创建 query-views，只保存定义和版本，不生成全量成员。总数可为 null。分页返回后续游标及必要的扫描进度；前端自动接续有界扫描，保留已显示结果。

少量 Tag 候选、单帖子和单图像条件采用索引定位；有序扫描先读取有界候选，依序求值，满足本页即停止。帖子有值与缺失值分别定位，避免含 NULL 的 OR 触发全湖排序。跨湖保留独立来源身份，按帖子 ID 或来源 ID/内容 ID 合并。

低选择性负条件、无索引组合、完整导出和全局排名仍可能耗时。首屏可分页不代表全结果已构建。未知总数不显示成 0，来源更新不自动重置当前视图。

## 项目格式 v13

项目主库保存控制状态、定义、引用、编辑与任务进度，大结果写入 members.sqlite：

1. 构建并校验暂存结果。
2. 独立成员 writer 分批提交，记录恢复位置。
3. 成员库标记 sealed。
4. 释放成员 writer，用主库短事务登记。
5. 消费者仅看主库 ready 且成员库 sealed 的结果。

读取池先固定主库快照，再读附加的只读成员库；不依赖两个 WAL 文件的联合写原子性。孤儿回收避让活跃读者并分块删除。备份包含成员库，验证拥有者与封存引用。

工作集、任务可共享固定成员，仅复制稀疏增删。旧成员通过兼容视图保留。旧式仅固定项目数据的结果仍沿用“固定成员、任务创建时冻结元数据”语义；在线视图及直接捕获结果保留明确来源版本。

Windows 原子 JSON 替换对短暂共享冲突有限重试；失败仍报告，不丢失旧检查点。

## 迁移与退出边界

转换只读旧 SSD 索引，复制对象定位、资产、所有观察、raw 与 schema，不重读或重新打包图片。ONLINE-BUILD.json 记录基线和分块进度；全量摘要、SQLite/FTS5 与关系检查通过才可 activate。

用户明确允许丢弃旧 Studio 项目、工作集结果和查询缓存，因此正式切换采用新项目边界。全局账户配置、凭据、System Prompt 预设和图片湖不在清理范围。

旧 Studio identity/browse/Rating/query/ranked 缓存退出正式读取路径。Store 生产者索引及 Python 运行环境仍有使用者，不与旧 Studio 缓存混同删除。

未转换外部来源仍可使用 v1 兼容适配器；已启用在线格式的根目录若指针丢失或损坏则报错，不静默回退到旧 native 水位。新建正式项目不再为三湖生成旧式基础缓存。

P4 的三站 API 日期/ID/范围计划、鉴权、限流、媒体补齐、重试及背压尚待实施，必须复用本发布协议并完整保留原始响应。
