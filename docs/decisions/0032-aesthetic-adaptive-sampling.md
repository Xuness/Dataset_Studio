# ADR 0032：按轮次连接比较与动态曝光

日期：2026-09-24。状态：已实现；验收范围见[验证记录](../verification/2026-09-24-aesthetic-sampling.md)。本次是 R3 结果有效性的一部分，并将基础主动采样提前实施；不代表 R3 的读取治理、对象释放或 R4/R5 已完成。

## 问题与目标

145 图真实评审完成了每图 4 次有效曝光，但比较关系形成 129 图和 16 图两个分量。后一组四次都只与同组图片比较。旧组批器按曝光和当前未占用候选挑选成员，并发完成时序可能反复释放同一批成员；打乱显示顺序没有保证更换对手。

目标仍是各 Rating 内全体图片的相对排序。稳定的高位、低位图片都可以降低评审频率；尚不稳定的中段、弱连接和低曝光图片获得额外机会。低分本身不是降频或排除理由，顶级提名也不直接加分。

## 冻结策略与兼容

新建请求增加可选 `sampling`：`mode` 为 `balanced` 或 `adaptive`，`min_exposures`、`max_exposures`、`rank_tolerance`、`seed` 全部冻结。最低曝光必须与原 `exposures` 字段相同，最大曝光不小于最低曝光，范围 1–32；位次变化阈值为 0.01–0.25。

- `balanced`：满足基础覆盖和有效比较连接后停止；单图上限允许为补强连接留出空间。最低值与最高值均设为 4 可用作严格四曝光对照。
- `adaptive`：在基础覆盖、连接之外，继续评估对手多样性和经验位次稳定性。
- 请求没有 `sampling` 时，保持 `rating_year_mix_v1` 行为和历史幂等形状。旧阶段不因软件升级静默改用新策略。
- 桌面新建默认动态模式，最低 2、最高 8、位次变化阈值 10 个百分点、种子 17。它们是实验默认值，没有声称是最佳参数。

首版 `connected_rounds_v1` 明确限制为 10000 候选、20000 批接受证据。API 预检和启动/规划都会检查，超过范围在新收费前拒绝。初始轮次的计划批次数受剩余重放额度限制；实际图片传输仍按冻结请求体预算做可审计拆批。原有阶段与离线分析的百万候选协议上限没有因此被认证为动态采样容量。

## 一轮的行为

1. 上一轮全部停靠后，冻结接受证据水位。错误或结果不明的批次沿用现有处置流程，不能借新轮次自动重发。
2. 有界读取候选和原始梯队，复用 `davidson_v1`（128 次迭代上限、正则 0.1、并列强度 1），在 writer 外计算。调度不改变用户最终离线快照选用的估计器。
3. 按最低曝光、实际连接、不同对手和经验位次变化确定待评审图片。每个 Rating 独立，未知或已排除的图片不作桥接代表。被阻塞/排除的节点不能作为唯一连接依据。
4. 先从仍有未分配成员的较大分量选代表，增加不同分量、不同上一批次的成员，再考虑新对手和相近位次。每次匹配最多观察 256 个候选。基础覆盖充分时，从每个未连通分量的高、中、低位置选代表，避免为了桥接重跑整个工作集。
5. 稳定图片通过轮换抽查或比较对手继续参与。相同图片一轮至多出现一次；输入顺序由种子与轮次确定。尾批尽量与前批均分，避免单图或极小组。
6. 完整轮次、诊断和每图抽样原因一次性发布；随后执行并发请求。返回快慢不改变这轮成员。失败、拆批和不可评判会降低实际获得的信息，下一轮必须重新检查真实证据，不能把计划中的连接当成已完成连接。

年份不再是新采样器的强优先项。基础混合和跨质量段连接优先，年份仍保留在候选与分析诊断中。此项改变仅作用于明确选择新版本的计划。

## 经验稳定性及停止条件

调度使用全 Rating 可比较的百分位。连续两次获得新有效曝光后的百分位变化不超过阈值，且拟合收敛、不同对手达到 `min(24, 同 Rating 可用候选数−1)`、拟合残差小于 0.4，才记为暂时稳定。不同对手精确计数到 32，超过后表达为“32 及以上”。未新增曝光不能积累稳定次数；后续位次明显变化会重新进入评审。

这是经验调度规则，不是经过校准的置信概率、置信区间或审美正确率。分半波动也没有被改名为置信度。一批必须至少有两张被判断的图片才增加有效曝光，离线重放与权威账本保持相同口径；只有一张可判断图时可明确重评，不能因虚增曝光被上限挡住。整批仍是观测单位；16 图展开的图片对不能当成独立实验。重复同组、同模型的系统偏好仍需质量校准。

单个 Rating 仅剩一张可用图片时，转为有原因的异常候选，支持明确排除或在同类对手恢复后重评。全部候选被明确排除可结束为 `completed_with_exclusions`，不产生新的调用。即使调用预算已耗尽，也允许执行本地轮次诊断与收尾；发送前仍严格检查调用上限。

达到调用上限、单图曝光上限、没有可用对手或仍有待处理候选时，保留明确原因并进入 `needs_attention`。基础曝光完成不再单独足以让采用新计划的阶段进入 `completed`。均衡模式检查覆盖/连接；动态模式还检查经验稳定条件。整体连通不证明排序精度已足够。动态模式目前使用完整冻结 Rating 的百分位；若已有候选无法评判导致该范围不可比较，完成可用候选的基础覆盖与连接后即报告 `ranking_scope_incomplete`，不会为了不存在的全体位次变化继续收费。可以补齐候选证据，或使用均衡模式后按分量浏览；完整排名总体/排除语义仍属后续 R3。

## 追加计划和历史事实

`POST /stages/{id}/sampling` 接受持久幂等键、策略和追加调用次数。只能在候选冻结且阶段停靠、没有正在准备/发送/待解析的批次时保存；同键不同内容拒绝。追加预算以上一次保存时已发生的尝试数为起点计算，包含失败尝试。

操作只使阶段变为 `ready`，不会派发。用户仍需点击“开始评审”。模型、Prompt、图片策略、原始配置哈希、原始回执、接受证据和旧排名快照均不改写。新的调度策略是独立记录，并通过批次中的计划 ID、轮次、决策证据水位和逐图原因溯源。需要更换模型或 Prompt 时建立新阶段。追加计划引用上一份已计算的诊断；仅增加预算或放宽阈值时保留有效的稳定记录，收紧阈值则重新积累稳定次数，避免把追加预算误作全体从零复评。

未领取的轮次槽位可以被显式追加计划替代；已经生成的批次保留原成员与采样出处，按其原计划处理；新单图上限约束追加计划生成的批次。失败/结果不明的批次允许先追加预算，但不会自动变成重试队列；仍需现有的明确重试操作，未处理前不规划新轮次。旧幂等请求重试只返回现状，不能把旧计划重新激活。历史快照继续使用原证据水位，新证据须通过新建离线分析发布。

## 持久化、资源和恢复

`evaluation.sqlite` 升至 v7，新增 `sampling_plans`、`sampling_rounds`、`sampling_queue`、`sampling_diagnostics`，阶段关联当前计划，批次保存采样出处。升级前使用 SQLite Backup API 备份；原 v1–v6 持续兼容。项目库版本仍为 12，恢复包支持 v7。

轮次队列只保存候选 ordinal 与原因；领取时加载至多 16 个候选并冻结完整成员。规划读取按 64 条分页，内存预留 128 MiB，与请求共享 512 MiB 预算；引擎同时只运行一个采样规划器。重放/拟合/组批均检查取消，等待准入期间也检查暂停。writer 只发布结果，不执行拟合。十万/百万级在线规划与整个程序的 RSS 上限仍未验收。

## 结果展示

新排名摘要增加可选、版本化 `validity`，分别表达数值收敛、比较覆盖、Rating/分量排名范围和分半诊断覆盖及缺失原因。旧快照缺少此字段时标为历史缺失；不改写旧结果。

前端提供采样策略、曝光区间、经验阈值、种子、追加计划及恢复重试；右侧展示最近检查点的覆盖/稳定统计，候选详情显示调度诊断，批次显示抽样原因。排名页明确指出不同分量的列表顺序不是质量先后。SDK 是前端访问的唯一业务入口。
