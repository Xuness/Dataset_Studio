# ADR 0034：美学排序候选上限统一为 1000 万

日期：2026-09-24，验证完成于 2026-09-25。状态：已实现并通过本文范围内验收。用户明确要求将原 1 万图采样护栏解锁至 1000 万，并提交当前全部代码改动。

## 数量与预算

阶段创建、预检、所有轮次模式、离线排名统一使用 domain 的 `AESTHETIC_MAX_CANDIDATES = 10_000_000`。前端提示及追加评审入口同步更新。排名区间采用 1–10000000；候选 ordinal、分量标识采用 0–9999999，详情查询、筛选和复核不再被旧百万边界拦住。

轮次重放上限由 20000 调整为 20000000 批接受证据。以 16 图/批计，这覆盖 1000 万图每图 32 次曝光；拆批、拒判等情况下它仍是独立证据量限制。它不增加用户已经配置的付费调用预算。

以下约束不变：每批 2–16 图，每图 1–32 次曝光，单份调用配置/追加预算至多 1000 万次，并发至多 32，请求体默认 32 MiB/上限 48 MiB，真实请求的共享内存和上传预算，以及结果不明不得自动重试的规则。

## 读取与计算

原来的 `LIMIT 10000` 会截断后续候选和检查点诊断，因此替换为按 ordinal 递增的 1024 条 keyset 分页；检查冻结范围、诊断完整性和取消。分页控制读取中间页大小，规划器仍需要持有全体冻结候选及已接受证据。

将隔离大规模模拟已经验证的等价数据结构迁入组批器：有序剩余位置集合、分量剩余计数/大小索引、队列取锚点。保留原种子、排序优先级、256 候选前瞻、并查集合并和尾批规则。此项不更换 v1/v2 的统计策略版本。

## 分块暂存与原子发布

整轮 JSON 不再作为一个可能超过 32 MiB 的 writer 请求提交。先创建带唯一所有者标识的 `staging` 轮次，再分别以最多 256 条记录的短事务写入诊断和槽位。每页核对当前阶段、计划、旧轮次、尝试/接受计数和暂存所有者。

派发只读取 `sampling_plans.status_json` 指向的已发布轮次。暂存期间该指针保持原值；完成后重新核对证据水位及记录总数，在一个事务中处理孤立候选、更新轮次摘要并切换指针。取消或崩溃不会使部分槽位可领取，已有回执不受影响。

同计划重试可接管并分块清理未发布的暂存；新计划也清理同阶段已被替代计划的未发布暂存。清理只针对状态为 staging、序号大于该计划已发布检查点且没有已领取批次的记录，保留已发布历史及所有付费证据。writer 的单请求 32 MiB、普通/回执保留队列和优先级均保持不变。

数据库仍使用 v7 表结构，不改写旧快照。新的暂存恢复属于当前引擎的执行行为，中断暂存应使用支持此流程的引擎续跑。

## 验证边界

解锁的是候选数量准入，不是 1000 万图生产吞吐承诺。规划仍为整轮内存重放，原 128 MiB 规划预留不是进程 RSS 上限；CPU、数据库、磁盘和模型容量仍需单独验证。此前 150 万算法模拟保留原来的实验条件和哈希，不改写成千万级性能证据。

验证包括真实 SQLite 10000000/10000001 成员预检、所有采样模式边界、超过旧百万范围的排名入口、20 万候选/超过 32 MiB 诊断分块发布、暂存中断与重启、替换计划清理，以及等价组批对照。结果见 [验收记录](../verification/2026-09-24-aesthetic-capacity-10m.md)。
