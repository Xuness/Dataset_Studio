# 0056：Booru 浏览排序与通用图像排序分离

日期：2026-10-03。

后续：[0072](0072-pixiv-post-order.md) 于 2026-10-09 补齐 Pixiv 的作品 ID / 页码排序，Pixiv 现在也使用支持帖子排序的范围偏好。下文保留早期偏好隔离的背景；按当前范围解析来源的规则继续适用。

项目原先共用一个浏览排序值。打开不支持 `post_order` 的 Pixiv 或含 Pixiv 的混合范围时，浏览器会把帖子 ID 排序自动改成图像身份升序并保存，导致返回 Booru 数据湖后也失去原有帖子 ID 排序。

项目会话新增 `booruOrder`，用于当前来源均支持 `post_order` 的浏览范围；单独浏览 Danbooru、Gelbooru、Yandere 时默认帖子 ID 降序。来源判定使用适配器能力，不在前端维护站点名称列表。Booru 范围仍允许用户显式选择帖子 ID 或图像身份的升降序。

原 `order` 用于 Pixiv 及不共同支持帖子排序的范围，默认图像身份升序。遇到旧的帖子排序值，只为当前视图使用图像身份升序，不自动回写。两组偏好各自在用户手动选择时保存，切换范围不会互相覆盖。浏览器与快速筛选共享应用层解析后的有效排序；排名成果继续使用独立的排名查看设置。

查询结果、工作集和当前选择通过现有范围来源接口解析实际来源；只有“全部项目数据”使用项目内全部来源。2026-10-09 修复了 Yandere 等 Booru 数据湖经 Tag 筛选后，被项目内无关 Pixiv 来源误判成通用范围的问题。来源尚未解析时先等待，避免按临时哈希顺序读取或覆盖保存的翻页位置；选择修订和工作集成员变化会刷新来源判定。

这是 `studio.session` 版本 1 的可选字段扩展，无需修改湖或后端协议。旧会话没有 `booruOrder` 时，继承已有帖子 ID 升降序；已有图像身份值保留为通用范围偏好，Booru 初始化为帖子 ID 降序。旧格式无法区分自动回退与手动图像身份选择，因此旧 Booru 的图像身份选择也会在首次升级时恢复默认，用户之后可重新选择并独立保存。

隔离回归入口为 `node tooling/smoke-pixiv-ui.mjs`，使用 Pixiv 与三种 Booru 合成湖检查旧会话、往返切换、手动升降序、图像身份选择、混合范围、刷新恢复及现有 Pixiv 筛选流程。
