# 开发引擎升级时等待实际退出

2026-09-11

开发启动器更新引擎时，`/v1/shutdown` 的成功响应只表示已发出停止请求。HTTP 健康接口可能先于查询任务、缓存维护和 SQLite 收尾停止；此时进程仍持有应用目录锁。仅等待健康接口失联就启动新进程，会连续遇到 `ENGINE_BUSY`，并在旧引擎退出前耗尽重试。

对已认证的当前引擎发出停止请求后，启动器改为等待对应 PID 实际退出，再启动新版本。最长等待 120 秒，每 5 秒报告收尾状态；超时保留现有进程并返回明确错误，不强制结束进程、不删除目录锁。新引擎的就绪等待也按 120 秒期限管理，退出重试至少间隔一秒，启动错误会关闭对应日志句柄。

`pnpm test:launcher` 包含可控时间测试和真实子进程测试：健康接口关闭后继续保有模拟目录锁，延迟收尾再退出；验证启动交接等待实际退出、超时有界，以及原有中文/空格路径、重复启动和桌面进程存活行为。
