# 更新运行环境与数据湖位置恢复

日期：2026-09-29。对应 Astra F6、G1；补充 [0046](0046-update-command-handoff-and-cancel-cleanup.md)。

## 运行环境

Rust 控制器区分解释器更换和控制状态目录迁移。普通配置入口允许更换 Python，已配置时必须保留原 state_root；任务、凭据、计划、湖登记和固定输入保持原身份。状态目录迁移不在本接口范围内。

候选解释器先通过无状态 check：导入依赖、检查 Python/WebP 能力并核对 worker/protocol 版本。此时不打开控制数据库、不读取凭据、不启动抓取。然后核对状态目录的 studio-owner.json，停止原 worker，启动候选并等待它取得 runner.lock 后报告就绪。候选等待激活字节期间不调度任务；配置原子保存后才激活。

一个 Rust 读写门控制配置、监督器和 RPC 的代次交接。配置和停止使用写门，正常 RPC 使用读门，取消不必排在其他 RPC 后面。旧进程超过 8 秒尚未退出时，更换请求返回冲突，保留进程及原配置，不并行启动另一个代次。引擎退出仍采用既有最终终止策略，持久检查点负责后续恢复。

启动失败保留旧配置，候选首次创建的所属标记会回收；原工作运行器可重新启动。配置成功仅证明本次握手与启动成功，后续运行失败由监督器处理。控制器提供已保存路径、健康状态、脱敏错误、失败数和下一次重试时间；自动重试从 10 秒退避到最多 300 秒，最多保留 32 条不包含原始 Python 输出的启动事件。设置页始终提供验证和更换入口。

## 位置迁移

更新控制库升级到 v6，新增持久 lake_relocations；v5 的原子命令和取消回收保持。已登记更新服务的湖禁止从旧“重新关联”入口单独修改读侧位置。统一入口位于设置 → 数据湖 API → 迁移数据湖位置，并通过公开 API/SDK 操作。

阶段：draining → prepared → verified → writer_committed → complete。取消仅允许发生在 draining/prepared，且 prepared 必须仍能验证原目录。切换开始后只允许完成原迁移，避免中间态回退到不同的归档。

1. 先持久冻结该湖的新领取。控制器目录中的位置准入门与每次操作的 OS 锁证明现有更新、回收、重启及固定输入操作已经退出。多个正常操作仍可并行；位置门仅用于取得/释放操作资格。迁移不抢占长任务，可在任务页先暂停，随后重新检查准备状态。
2. 取得湖、归档、索引与发布锁，恢复可接受归档后保存身份、站点、generation、归档序号与清单摘要、served_seq、min_seq。磁盘清单逐文件记录归档、固定输入与恢复暂存。原始大归档文件检查路径和长度，清单及可恢复暂存检查哈希；本操作不等同于全库介质校验。
3. 用户复制或移动文件。新位置必须具有相同归档提交链和代次，在线可见水位不得回退，保留边界不得收窄，引用中的输入、metadata_staging、pack_staging 与 updates 文件不得遗漏。库和控制器归属也必须匹配。未经准备的离线旧位置无法建立可信水位，必须先恢复旧位置；不能仅凭相同 library_id 接受备份。
4. 写侧更新发布反向链接、cache_owner、UPDATE-CONTROLLER 和 lakes，记录 writer_committed，继续冻结写入。Rust 再原子更新共享 source_locations，通知打开的项目，最后确认 complete。引擎重启自动补完 writer_committed；其他阶段由设置页继续或在允许时取消。每次改变阶段前，在同一位置门下重读状态，防止旧取消覆盖新切换。

旧索引位置保留 LAKE-RELOCATION 标记，阻止支持此协议的旧发布/归档写入。只移动媒体时，共用索引的 cache_owner.root 会拒绝旧媒体位置。索引构建、版本回收也检查位置归属。外部生产者应停止后再搬迁，不能用直接改 JSON/数据库绕过交接。

新在线库建立一个无期限的 relocation 版本保留租约，保护搬迁前以及搬迁期间产生的固定引用。它可能增加历史版本占用；只有另行核对所有项目、输入和任务引用后才能释放，本接口不自动猜测“没有旧读者”。旧副本也不自动删除。

## 连接生命周期与诊断

Python 发布器读取 journal.sqlite 使用显式关闭，避免依赖垃圾回收释放 Windows 文件句柄。普通 sqlite3 的连接上下文仅管理事务，不能作为已经关闭连接的证明。

资源 API 的 online_sqlite 提供进程累计 busy_errors、protocol_errors、lease_retries、max_lease_write_ms；统计包含被成功重试恢复的错误。错误计数不等同于失败请求数。Rust 的 Index/Media/Decode/NativeQuery 准入以及 Python 更新资源预算仍各自独立，不宣称构成全应用共享的总内存上限。

真实规模副本上，四个并发浏览请求稳定出现约 10.8 秒的 SQLITE_PROTOCOL，发生在读取连接而非租约重试。检查当前 libsqlite3-sys 0.38.2 所带 SQLite 3.53.2 源码，Windows VFS 的 winIsUNCPath 把任何双反斜线前缀都视作 UNC，因此 Rust canonicalize 产生的本地扩展路径也进入共享句柄分支。

在线数据库仍先使用完整规范路径检查目录边界，再用 dunce::simplified 为 SQLite 选择等价且安全的普通本地盘符路径。读取与租约写入使用同一个结果；不改变只读打开标志、不新增常驻连接池，也不延长锁等待。相同大规模副本的前后对照从每轮 4 次协议错误变为零。超长路径、保留名称和真实 UNC 路径不能安全简化时保留原路径；本次实测结论限于当前本地卷和普通路径，不外推到网络文件系统。
