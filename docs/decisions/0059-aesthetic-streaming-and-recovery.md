# 0059：美学评审的流式回执、有限恢复与工作台流程

日期：2026-10-05。承接 [0031](0031-aesthetic-transport-and-recovery.md)、[0032](0032-aesthetic-adaptive-sampling.md) 和 [0033](0033-aesthetic-neighbor-refinement.md)。验证范围见[本轮记录](../verification/2026-10-05-aesthetic-execution-ux.md)。

## 执行策略与兼容

评审模型、Prompt、图片范围及原配置哈希继续冻结。传输方式、并发、超时和自动恢复组成独立的 `execution_settings`；每次明确保存增加修订并保留幂等请求，每个网络 attempt 记录当时的执行设置。调整设置不启动评审，不重算或覆盖已有证据。

新建界面默认选择 `refine`，可选择 SSE 或完整 JSON 响应。执行设置的建议值为连接 15 秒、首包 180 秒、读取空闲 60 秒、单次总时限 600 秒、批次恢复窗口 900 秒，最多自动重试 2 次。结果不明的请求默认不自动重试；用户可在阶段设置中明确允许。自动恢复耗尽后默认保留异常，也可选择关闭旧逻辑批次并在后续轮次补测。

历史阶段没有 `execution_settings` 时继续使用原连接设置和原来的明确重试要求。保存新的阶段执行设置时，核对冻结的模型身份、协议、端点、消息、工具和参数，再关联当前连接/模型版本；模型或请求内容发生变化时拒绝原阶段重绑定，使用复制配置创建独立阶段。只改全局连接超时不会静默绕过版本检查。

旧创建请求省略新增字段时保留原幂等序列化形状。新界面明确选择完整曝光预算或小预算试跑。完整模式在预检及创建时拒绝低于 `ceil(候选数 × 最低曝光 / 16)` 的调用预算；这只是下界，Rating 分组、连接、拆批和重试可能增加需求。新建预算建议随输入和模式更新，用户手动设定后保留其值；历史草稿的预算也按手动值保留。动态细排的起步建议考虑至少四次曝光的规划条件，不作为精度承诺。

## 网络时钟与流式证据

本地凭据读取、并发排队及发送节奏等待不占单次网络总时限。获得准入后，在发送前提交 attempt，再开始固定的网络时钟。连接建立、上传、上游排队、推理和响应接收都受单次总时限约束。首包等待持续至首个非空响应数据；只有响应头不会结束首包等待。此后的每次非空数据（包括 SSE 心跳）重置读取空闲计时，不延长总时限。

批次恢复窗口从首个网络发送承诺点起按持久化 UTC 截止时间计算，包含退避、后续排队和暂停。重试只能使用剩余恢复时间。明确的手动重试开启新窗口，但每个逻辑批次仍最多保留八次尝试，阶段总调用预算继续原子约束所有发送。

评审的 SSE 与 JSON 都使用 ReceiptSink 路径，不调用带隐式 HTTP 重试的通用流式接口。一次 attempt 对应一次应用层发送。原始响应、允许保留的响应头、请求 ID、解析版本、完整性与摘要先持久化，再转换为供应商输出、验证完整图片 ID/梯队并接受证据。Chat SSE 等待 `[DONE]`，包含结束前的最终用量帧；Responses 使用完成事件；Gemini 接收最终用量并读到结束。心跳、局部 JSON、缺失结束标记和流中错误均不能成为有效评审。

新增回执适配器 `native_sse_v1`，保留 `native_json_v1`。两者支持不联网的本地重解析。SSE 的完整性表示协议完成边界已经接收；完整 HTTP 内容但缺少协议完成标记仍解析失败。读取中断、取消、超时保留至多 16 MiB 的已收前缀；尚未收到响应头时不编造回执。网络时限不取消已收到内容的保存。进程在内容提交前被强制结束，仍可能只能恢复为结果不明，不能声称已经保存全部片段。

实时界面只接收阶段、时间和字节量等有界进度，不逐 token 写入 SQLite，也不将半份结果用于排序。

## 本轮派发与重试

单批错误保存后，本轮其他独立批次继续执行。瞬态错误按阶段策略进入持久化退避队列，采用秒数形式的 Retry-After，缺失或非数值时使用本地退避，附加有界抖动，并计入尝试次数和调用预算。等待重试不占用请求内存和供应商并发许可。认证、配置错误和持续失败会停止本阶段新派发；存储故障继续沿用共享准入保护。

暂停只停止尚未发送的工作，已发送的响应继续排空并保存。重启保留失败和重试计划，并等待用户明确恢复阶段，不自动购买新的调用。既有历史异常不会因保存执行策略而自动入队，使用单批或批量操作明确安排。

`deferred` 是没有接受证据的终结状态。暂缓操作保存原因，结束旧逻辑批次并释放可用候选，不增加曝光。跨轮规划可越过已经明确终结的旧批次，基于真实证据重新检查 Coverage、比较连接、曝光上限和预算。已关闭批次的迟到结果不能重新接受；原始回执仍保留。暂缓与补跑不保证全体可比较或排名精度。

批量操作冻结阶段内的批次上界，按至多 32 个批次的短事务推进，每项使用保存点；持久幂等键和游标支持中断后继续。单批拒绝不会回滚其他成功项，也不会暗中开启模型调用。

### 不可评返回的容错（2026-10-06）

新收到的结果必须至少有两张图片位于 `tiers` 中，才能成为有效比较证据；两张同梯队也构成有效比较。结构正确但可比较图片不足的结果记为 `EVALUATION_NO_COMPARABLE_EVIDENCE`，保留原始与规范化回执及用量，不接受 evidence、不增加曝光，也不累计候选不可评次数。记录失败与安排恢复处于同一事务，沿用 `max_retries`、恢复窗口、阶段调用预算、连续失败停止阈值及耗尽后的 pause/defer 策略。它是已知无有效证据的返回，无需打开 `retry_unknown`；没有执行设置的历史阶段仍要求明确重试。重试期间只保留批次占用，耗尽后的批次阻塞关联原批次，不转为候选质量处置。

有效比较批次中的单图 `unjudgeable` 不再立即进入 `needs_review`。落库事务读取候选当前曝光历史：已有有效曝光的候选保留资格；没有有效曝光的候选前两次继续参与新批次，第三个有效批次仍连续不可评时才转为 `needs_review`。批次内重复解析不会重复计数，成功比较清零计数，明确的人工重评也开启新的容错窗口；暂时不可评不会制造曝光或低分。旧版组批也会为不足 16 张的尾批补入同 Rating、已达到曝光目标的图片，避免只让少数异常候选互相比对。既有调用预算和采样曝光上限仍生效，预算不足、已确认的未决候选或缺少比较同伴仍可要求处理，不能伪装为完成。

账本 v9→v10 为候选增加持久化 `unjudgeable_streak`，升级前备份，并允许项目恢复包读取 v10。迁移从零初始化新计数，保留已接受证据、快照和历史人工处置；不会重放旧回执或自动解除旧版本已经保存的 `needs_review`。这些历史候选可用现有“重评”操作恢复。

## 工作台与本地分析

- 阶段支持改名、归档、恢复、搜索、状态筛选和按创建时间的键集分页；不提供物理删除付费证据。
- 批次使用稳定的阶段内编号，同时保留全局编号。后端支持异常过滤；被网络批次阻塞的候选显示关联批次，但不伪装为图片质量处置。
- 当前轮次派发/接受数量、排队、在途、重试、异常及曝光进度与历史诊断分开展示。增量计数避免刷新时全表扫描候选或批次。
- 图片可按输入顺序或梯队排列，证据与排名复用大图、缩放、平移和键盘浏览。缺失原始回执时不能点击本地重解析。
- 查看排名定位当前阶段的最新快照；没有快照时预填当前阶段生成对话框。运行中的阶段可以固定当前接受证据生成临时快照，未连通时保持分量排名语义。
- 结束阶段需要明确确认；暂停仍用于续跑。复制配置创建独立阶段，不复制或混合付费观察。
- Top N 使用既有 `rank_to` 筛选及完整并列边界。新的离线 `preview` 任务按有界页统计完整筛选范围、排名入选数、边界并列组及额外保护数；图片预览和派生固定相同复核水位，不以本页条数冒充总数。
- 复核时间按毫秒时间戳解析。

## 存储格式

`evaluation.sqlite` 当前为 v10，升级前自动备份，迁移在事务中检查引用和计数。v8 新增执行修订、归档属性、稳定局部编号、重试时点/恢复窗口、批量操作进度以及按曝光和批次状态维护的增量计数；v9 增加缓存与费用汇总，v10 增加候选不可评计数。候选保存其阻塞批次。原始配置、已接受 evidence、回执和现有快照不改写。

旧版本 v1–v9 仍走逐版迁移。项目恢复包接受至 v10；旧程序不能打开新版本账本，应连同升级备份保留。生产数据、模拟凭据、测试截图和运行日志均不提交到 Git。
