# 0021：固定查询依赖、项目缓存明细与无引用输入回收

2026-09-14，开发版本 0.9.1。补充 0007、0008、0017、0019 和 0020。

## 固定成员与最新来源的边界

排名工作集的快捷分级条件读取 `project.<artifact>.rating`，依赖已保存的成果。此前通用结果复用仍比较整个数据湖的来源版本：即使成员一项未变，跨日重新应用条件也会评估数百万候选、生成新成员版本并重新构建排名浏览索引。

输入为固定工作集或固定查询结果、条件全部来自项目成果、且按图片身份排序时，查询只依赖固定项目数据。工作集/查询范围和成果 ID 已进入规范化查询指纹；这些对象的成员及成果文件不可原地修改。直接复用同一家族的成员版本，不因数据湖水位变化而产生新版本。此规则兼容已有缓存，无需数据迁移。原来源版本仍作为观察到的来源信息保留，不作为固定条件的失效依据。

固定查询首次执行时只从项目成员或排名成果候选出发，不扫描最新数据湖筛选条件，也不强制刷新来源浏览索引。成果有效性、来源关联权限、输入范围的存在及成员就绪、任务完成时的范围检查保持有效。已有固定结果的有效性和普通图片分页允许来源变更；图片展示信息可读取当前来源，成员身份和原评分不随之更新。

来源范围、当前选择、原湖字段条件和帖子 ID 排序继续使用原来源版本检查。混合“固定评分分级 + 最新 Tag”仍是实时来源查询。新增图片不会进入已有固定工作集；已有成员的最新元数据变化仍由实时查询检查。固定成员不等于元数据值全部冻结。

实时刷新若实际执行后 `changed_members=0`，保留原成员版本。变化检测同时比较成员和保存的帖子关联，因此不能仅以成员数量相同判断复用。原家族版本继续提供稳定的 canonical ranked scope，新结果保留自己的 ID、来源版本及执行记录。

## 所有项目的缓存明细

增加 `/v1/cache/projects` 和按项目分页的库存接口，涵盖关闭项目。全局项目表展示成员存储、排名索引和合计；项目明细分别列出查询成员、项目固定输入、待回收成员及排名浏览文件，并给出引用对象、使用/固定保护、保留方式和文件位置。来源索引、共享分级基础、缩略图和构建中工作空间单独显示，避免重复归到项目。

成员文件是共享 SQLite 数据库，单个家族仍按保存成员数分摊页面空间。明细使用当前有效的内存或持久化空间快照；统计未完成时返回未知，不进行请求内 dbstat 扫描，也不显示为零。成员明细采用 ID 游标和有界分页；引用展示最多 16 项并保留总数；排名文件最多检查缓存目录的 256 个条目，正常保留上限仍为 128 份。

项目在新结果的空间统计落盘前关闭时，明细请求会安排后台补算；没有缓存目录记录的登记项目也会补入检查。不会要求重新打开项目才能恢复统计。

临时类容量保留原预算口径，包括归类为临时的固定输入。界面明确标注这种输入受项目引用保护，可查看具体引用，不能按普通临时查询清空。没有变更总容量、长期/临时保留规则或项目文件格式。

关闭项目的读取使用注册路径和只读连接，验证清单身份，不打开项目视图。修改保留和释放成员复用已有独立维护环境与普通项目文件锁；不改变用户项目打开状态或最近打开时间。排名文件释放检查文件键、项目范围、符号链接、活跃租约和读取保护；只能删除应用拥有的目标文件。

## 解除引用和历史残留

存在旧输入的 `cached=0`、`latest_count=0`、`latest_revision=1`，但 `stored_members>0`。旧候选条件和过期版本整理都漏掉这种状态，删除任务/工作集后的最后引用也未安排清理。

删除项目对象后为无引用输入安排有界清理。后台候选也覆盖这种存量状态，关闭项目的目录记录新增可回收成员计数；旧目录记录缺少该字段时进行一次检查。保持旧版本引用与最新版本分别回收的语义，不能为了回收孤立输入而扩大到受保护历史快照。

每个删除批次重新计算持久引用和当前读取租约。在没有任何保留版本时，同一事务中将旧结果标记释放、解除无效成果引用并分批删除成员。新的引用或读取仍可保护相应版本。清理进度、计数、错误重试、重启恢复和 SQLite 空间归还继续使用已有流程。

验证用例：`tooling/integration-cache-inventory.mjs` 配合隔离的 `ranking-fixture-update.py` 覆盖四种固定分级跨每日新图/元数据更新复用、实时条件刷新、无变化刷新复用排名索引、所有项目占用、关闭项目保留和释放、排名租约与项目身份检查，以及旧版无引用输入在项目关闭时的启动回收。完整集成回归保留同数量不同成员、历史引用、会话和分批清理检查。
