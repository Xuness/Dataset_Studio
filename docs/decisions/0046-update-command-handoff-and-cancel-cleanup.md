# 0046：更新任务的原子命令、按湖调度与取消回收

日期：2026-09-29。对应 Astra 审查 F5、F3、F4（R2）。延续归档先提交、控制状态可恢复、单湖执行互斥和独立下载/编码/发布阶段。

## 命令和执行者的交接

`updates/commands.py` 负责用户命令；`State.claim()` 负责执行领取。恢复、重试、重放取得实际的任务执行锁，再取得湖的 `.daily-run.lock`；没有持有数据库写事务等待文件锁。执行器和取消回收使用相同的取得顺序：任务执行锁 → 湖执行锁 → 归档/发布锁 → 控制事务。

重启命令先恢复可接受的归档并核对未应用回执，再进入 `BEGIN IMMEDIATE`，重读任务状态和 execution。条目重置、cursor 修改、execution 增量和重新排队在同一事务完成，条件更新失败会整体回滚。这样旧的失败回执不会在下一次启动时覆盖刚提交的重试。

暂停和取消只提交控制事务，不等待执行者退出。取消是关闭状态；重复取消幂等，恢复/重试/重放均不能重新打开它。已排队任务的重启命令为幂等空操作，保留已排队意图，不再次增加 execution。若前一执行者仍在退出，或同湖其他任务正在占有执行锁，重启命令返回 `UPDATE_CONFLICT`，可待退出后重试。

归档核对发生在命令事务前，可能合法补齐之前已提交的事实；命令同时遇到取消时仍必须拒绝重新排队。普通执行状态更新保留 paused/cancelled 保护。领取在事务内核对可执行状态及 retry_at，选中任务后发生的取消不能被领取覆盖。

## 按湖候选和异常隔离

`updates/dispatch.py` 为每个空闲湖选择最早的、已到 retry_at 的可执行任务，再优先分配给最久未获调度的湖；未调度过的湖优先，同序时按队首 created_at/id 排序。`lake_dispatch` 保存单调调度序号，跨重启保留轮转次序，不依赖系统时钟。`jobs_runnable_lake` 是仅包含可执行状态的索引；不再先截取全局最早 100 个任务。延迟重试不会挡住同湖已经可运行的其他任务。

同一运行器仍最多同时执行配置允许的 1–3 个湖；不抢占正在运行的任务。一个 Future 异常退出时释放该活动槽，在取得任务锁并核对 execution/状态后登记 60 秒后的重试，不覆盖取消、暂停、完成或更新的执行代次，也不终止其他湖的调度。

增加一个独立的清理槽，线程池上限为 4。每轮先为到期清理保留一个空闲湖，再领取其他更新任务；同湖的连续积压不能永远抢在清理前。清理过程中其他湖可继续利用更新槽位。

## 取消后的持久清理责任

更新控制库 `updates.sqlite` 从 v4 升到 v5，增加 `job_cleanup`、到期索引和取消触发器。状态进入 cancelled 时，同一事务写入带 execution 的清理责任；升级会为已有 cancelled 任务补齐记录。旧运行器仍持锁时拒绝升级，需先停止旧控制进程。新结构不改变项目数据库、数据湖身份和归档格式。

清理过程由 `updates/cleanup.py` 执行：

1. 实际取得任务和湖的执行锁，确认任务仍为 cancelled 且 execution 匹配。业务状态和 `execution_active=false` 本身不充当清理许可。
2. 校验登记湖、cache_owner、UPDATE-CONTROLLER 与任务目录的归属；拒绝路径逃逸、符号链接和 Windows 重解析点。
3. 恢复可接受的正式归档，核对控制回执，释放该任务的固定输入版本租约，然后持久记录 `reconciled`。
4. 回收该任务的 SSD 暂存。目录只允许扁平、已识别命名的普通文件；每轮预检并删除至多 256 个文件，只删除空的任务目录，不递归删除 updates 根或归档。
5. 目录回收完成后才记录 `complete`。进程在任一步退出可重复执行；文件占用或 I/O 错误保留责任，默认 30 秒后重试，锁忙 1 秒后重试。

正式归档、主盘上尚无法验证的未封存材料、暂停任务、可重试失败和待复核任务仍保留。取消不撤销已经提交的数据；已经开始的编码和发布允许在安全边界完成，清理必须等这些执行者全部退出。

资源预留与实际文件不是一回事。阶段退出正常释放预留；清理取得终止任务执行锁后也可回收该任务遗留的内存预留，实际磁盘占用随文件删除下降。原有共享暂存目录扫描方式未替换，成本测量仍属于 R4。

## 可观察性和边界

公共 `LakeUpdateJob.cleanup` 可为空；有责任时返回 phase（pending/reconciled/complete）、retry_at 和脱敏 error_code。HTTP/SDK 契约由工具生成。任务详情区分“已取消”和“暂存已回收”，在清理尚未完成时继续刷新；路径归属异常明确提示文件保留。

内置 worker 必须与当前源码及 revision 对应。构建脚本使用相对依赖跟踪和当前 `CARGO_MANIFEST_DIR` 的文件引用，避免复用 target 时绑定旧审查副本；更新集成逐文件核对引擎实际解出的 worker，包含故障注入构建切回普通构建后的校验。

归属异常、离线数据湖或持续文件占用会使清理保持待重试状态，不能宣称已释放磁盘。清理吞吐和恢复所需时间不作为固定 SLO；归档核对仍可能受主盘和现有恢复扫描影响。跨控制器/外部生产者的长时间锁占有不由本调度器抢占。
