# 0058：固定排名成员引用与直接分页

日期：2026-10-04。

全湖排名成果已经保存完整、不可变的输入和分数，但保存排名工作集仍会复制每个成员，首次打开又为这个工作集建立独立排名索引。冻结 Rating 筛选还会再次物化成员。千万级范围中，这些中间步骤远比实际读取一页记录昂贵。

## 固定成员协议

项目格式升至 v14，沿用备份后迁移流程。新增 `ranking_memberships`，为内部或公开查询结果保存版本化成员描述：成果 ID、项目内相对文件位置、来源集合、保存时的排名条件、额外冻结 Rating 条件和精确数量。描述只引用当前项目成果目录中经过规范路径检查的只读材料。

保存排名工作集创建一个已就绪的内部固定结果，并通过现有 `collection_bases` 引用它。成员集合由不可变分数文件及条件共同确定，不在 `collection_member_legacy` 或成员库中复制全体身份。相同成员描述可共享查询家族和成员版本；不同工作集仍保持独立呈现状态。

只含同一成果 `project.<artifact_id>.rating` 等于或集合条件的细化，合并到同一描述中。多个条件取交集，空交集保持为空。不同来源、当前湖字段、标签和其他复杂查询继续使用原有固定成员构建路径。冻结 Rating 与当前帖 Rating 仍是两个不同字段，不能为了性能互相替换。

工作集内部结果使用成果原始来源版本；新查询保留查询时捕获的来源版本，使当前详情和自然帖子排序保持既有语义。每个结果独立持有成果引用和所需版本引用，释放父工作集不影响仍被使用的子结果。

## 读取与兼容

排名浏览直接使用原始分数文件的索引。主榜、补充榜、直接榜和融合榜均先显示具有当前榜单名次的成员，再显示未排名成员；正序和倒序都保持未排名部分在末尾。每部分内部沿用 Rating、名次和输入序号的方向排序，输入顺序及显式帖子/资产 ID 排序保持各自语义。

翻页、Rating 名次、帖子定位和总榜位置使用同一显示顺序。总榜位置通过逐步缩小范围的计数定位，不执行大 OFFSET；定位结果可在有界缓存中复用，缓存键包含成员、成果文件摘要、顺序和方向。客户端提供的定位字段不能写入可信缓存。

显示顺序版本纳入游标签名与派生索引键。旧翻页游标失效后界面回到第一页；已保存的起点游标会按原帖子 ID 或排名数值重新定位。复杂查询的派生索引记录已排名数量，并按已排名/未排名两段生成位置书签，倒序只反转各段内部。旧格式派生缓存由正常缓存流程重建，原始成果与工作集成员无需迁移或重新评分。

小范围成员最多读取 4096 条后进行有界排序，避免 Top N 工作集按另一顺序浏览时遍历整个成果。普通自然排序复用来源的有界分页和固定成员判断。翻页游标同时约束结果、顺序和来源版本。

SQLite 只读虚表 `ranking_members(recipe)` 把成员描述接入现有查询、选择、工作集和任务关系。身份约束下推，按键分页拆为互斥范围以使 SQLite 规划器看到来源与资产边界。扫描每批最多 512 个候选，未匹配标记交给外层 SQL，让原有取消回调能够在稀疏范围中持续运行。连接和缓冲随请求释放。

选择整个排名工作集复用基础结果，单项变更仍存入稀疏包含/排除表；保存普通工作集不会仅因共享排名材料而获得排名呈现。后续任务继续通过统一成员关系读取，复杂查询建立派生排名索引时也使用同一关系。

已保存的旧排名工作集可从现有成果引用和保存条件恢复描述，直接浏览；已有旧成员数据不会被自动删除。无法用成员描述表达的固定查询继续保留原来的持久排名索引。无公共路由或 DTO 变更。

## 生命周期与验证

成员描述、结果状态和引用在同一项目事务中提交。取消发生在提交前则回滚；已提交的幂等重试仍返回原工作集。成果依赖保护、选择历史、任务及普通工作集共享现有引用规则。删除对象、历史裁剪和启动恢复会分批释放不再被引用的内部排名结果；公开查询仍由正常查询生命周期释放。

计数优先使用成果中已有且覆盖完整输入的精确统计；未知组合执行精确 SQL 计数，成本取决于可用索引和条件。保存和读取均不更改原始输入、分数及湖元数据。另修复排名查询进度把累计值再次累加的问题，进度回调现在传入本批处理量。

存储测试对照独立 SQL 核对成员、五种顺序、空/未知值、深位定位、取消和只读边界。集成验证多 Rating 及空交集、四种自然顺序、跨结果游标拒绝、选择与稀疏排除、后续任务、重启及父工作集删除。界面验证沿用真实浏览器和隔离引擎。真实规模入口为 `tooling/benchmark-ranked-worksets.mjs`，需显式指定实际项目和已发布成果；它记录第一次创建、重复筛选、湖首屏对照、深位定位以及派生索引构建数，不清除操作系统文件缓存。
