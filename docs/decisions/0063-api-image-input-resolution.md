# 0063：API 图片缩放与可调整的评审输入规格

日期：2026-10-06

美学评审增加发送前等比例缩图。图片最长边属于可修改的执行设置，用户可以在同一阶段暂停后调整，恢复时的新调用与重试采用新值。无需复制阶段；已接受证据与旧尝试不修改。沿用执行设置的版本、幂等保存和等待在途请求结束规则。

## 配置与转换

`AestheticExecutionPolicy.image_max_edge` 为可选整数，范围 128–8192；缺省或 null 表示使用存储原图。创建阶段和执行设置共用原尺寸、2048、1536、1024、768、自定义选项。创建草稿记住选择，复制阶段沿用最新执行设置。旧阶段没有这个字段时继续发送原始字节。

转换组件位于 `studio-resources`，图片输入记录位于 `studio-domain`，不依赖某个供应商协议。首个接入方是美学评审；Chat、Responses、Gemini 编码器接收已准备好的图片。该设置不修改模型参数，也不等同于供应商的 `detail` / `media_resolution`；缩图的 Token 收益由实际模型用量确定。

只缩小、不放大、不裁切；已在尺寸范围内的图片原字节通过。需要缩小时先应用 EXIF 方向，使用 Lanczos3 等比例重采样，普通图片编码为 JPEG 95，带透明通道的图片编码为无损 PNG，并保留 ICC 配置。转换版本单独标识。源图读取仍受原有 2 MiB 门槛约束，不因发送图变小自动放宽。转换解码限制为 8388608 像素、64 MiB 解码字节，编码输出最多 16 MiB。

## 记录与兼容

`candidate.content_version` 和 `member.image_sha256` 始终表示原图身份。每次发送承诺同时持久化实际输入清单：有序短 ID、原图与发送字节的 SHA-256、原尺寸、发送尺寸、原始与发送字节数、格式、最长边选项、转换版本和完整请求体字节数。请求语义摘要包含该清单以及原生请求体摘要。

评审库 v12 为 attempts 增加可空 `image_inputs`。历史尝试保持缺失，不从当前设置反推尺寸；迁移前沿用 SQLite Backup API 备份。恢复包版本检查引用同一评审库版本常量。执行设置修改不重写创建配置或冻结配置哈希，每次尝试保存当次设置；同一批换尺寸重试后，旧尝试仍可独立查阅。阶段统计允许包含不同输入规格的结果，不对历史评分或权重进行自动修正。

## 资源与缓存

候选冻结只检查原图可读取性、签名与身份，不提前转换整湖。派发逐图处理，并使用已有 Decode 资源准入；请求准备阶段额外考虑 256 MiB 的单图工作空间、输入缓冲以及转换后的请求预算。转换与最终 JSON 编码峰值分别估算，发送后沿用在途降额。图片消息累计超出预算时在发送前拆批，已有尝试仍遵循禁止改成员的规则。

API 缩图使用独立键空间，按原图 SHA-256、最长边与转换版本缓存在已有有界图片缓存中，共享磁盘配额和清理入口。每次命中前仍重新读取并验证源图；可重建缓存损坏或不可用时重新转换。输入记录属于评审证据，不随缓存清理。界面调用详情显示实际输入信息和上游报告的输入 Token。
