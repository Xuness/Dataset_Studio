# 0045：查询许可复用与多湖续页进展

日期：2026-09-29。对应 Astra 审查修复计划 R1（F1/F2）。

## 许可归属

一次来源操作由入口取得一个 `SourceRead`，查询视图的保留、创建后保留、固定结果保留、版本校验、来源捕获、任务保留和部分失败清理显式接收这个读取对象。它们不在已有 Index 许可下再次调用 `inspect()`。固定结果构建末尾的版本校验也复用构建许可。

查询工厂接收取消信号和截止时间；在线版本读取、校验和租约保留沿用同一上下文。SQLite 租约写入使用短 busy 等待，按完整事务重试，每轮检查取消和截止时间；正常繁忙重试最长 3 秒，调用方截止时间更早时以调用方为准。

`SourceRead::lease_cleanup()` 只暴露版本释放，借用现有许可。它忽略原请求的取消，使用独立的 3 秒总截止时间，使取消发生于部分保留之后时仍能清理已经写入的租约。这个接口不允许创建新租约或执行新查询。失败仍记录清理错误，不能把来源永久离线或持续锁定描述为一定已经回收。

这些修改不扩大 Index 的默认 4 并发 / 128 MiB 预算。不同资源类别继续使用各自的准入；本决定不声称已重新审计所有其他调用链的跨类别锁序。

## 无状态合并的预算边界

保留现有游标字段：项目、结果、排序、各来源已消费/已完成空扫描的位置、耗尽集合和扫描统计。查询范围及冻结版本由持久结果引用确定；不在游标里加入完整预取页，也不新增服务器会话缓存。

每一轮合并先补齐所有未耗尽来源缺失的头部。只有所有头部已知时才输出全局最小项；如果某来源这一轮只有未命中扫描，则保存其扫描终点，延后输出，避免排序错误。200 ms / 8192 扫描项是软预算，只能在这类可恢复边界阻止下一轮读取；已经在缓冲中的命中仍可用于填满当前页。

因此成功返回且仍有后续的页面至少满足其一：输出了成员，或某来源的已完成空扫描位置/耗尽状态前进。不会仅因首湖稍慢而反复返回同一逻辑检查点，也不会把位置推进到尚未输出的命中之后。

一次补头可能超过软预算，最多额外完成一个至多 8 湖的有界扫描轮次。当前在线适配器每湖最多返回 129 个命中，条件扫描窗口最多 2048 项；请求仍受取消和读取截止时间约束。200 ms 不是端到端延迟承诺。服务端只保留当前调用的缓冲；放弃未消费预取可能产生重复读取，其性能成本留待 R4 实测。

## 兼容与恢复

- 公共 DTO、路由、项目格式、在线 schema 和游标编码字段均不变，原有效游标继续使用。
- 游标仍限制为 8192 字节，每页最多 128 项、来源最多 8 个。
- 同一游标可重试，也可在引擎重启后继续；冻结版本必须仍有效。
- 视图按既有 30 分钟续租期限管理。过期返回 `VIEW_EXPIRED`；范围或排序不一致返回 `INVALID_INPUT`，不静默切换到当前版本。
