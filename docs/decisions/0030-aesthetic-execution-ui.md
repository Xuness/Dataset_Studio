# 0030：评审执行与离线实验接入

日期：2026-09-23。延续 [0029](0029-aesthetic-reading-and-review.md)，本轮把已有执行和实验 API 接入工作台，不宣称完成 R2/R3 的全部后端加固。

## 创建与预检

新建阶段先显示现有 preflight 的候选数量、阶段容量及图片/请求限制，修改配置即清除旧预检。创建携带预检的 input_version，由后端再次校验。当前预检没有逐图读取，不表示图片可读取性或编码后的大小已经通过。

创建前把完整请求和幂等键持久保存到原 configuration 草稿；结果不确定时锁定原配置。关闭、重载后可以恢复同一创建、查找已创建阶段，或通过后端放弃未完成意图。后端拒绝放弃已经建成的阶段；前端保留请求并提示找回后取消。创建不自动开始模型调用。

## 候选异常处置

评审阶段新增“异常候选”，右侧为“候选处置”。状态过滤包含待处理、正常参与、重评和排除，候选序号键集分页，每页至多 64 项，浏览历史至多 64 个游标。选中候选使用单图查询，处置后即使移出筛选列表，右侧仍能确认当前结果。

公开候选列表增加可选 disposition，SDK 保持旧签名参数兼容；新增单个阶段候选读取。评审库从 v3 升至 v4，沿用完整性检查、SQLite Backup API 备份和事务迁移，仅增加 candidate_disposition_page(stage_id, disposition, ordinal) 索引。原 candidate_disposition 索引用于派发，继续保留。项目库格式不变。

处置只在后端允许的暂停/待处理状态提交，Rating 不确定不能重评，原因限制按 UTF-8 字节验证。最多 32 份逐图草稿；提交前保存请求键，丢失返回时用同键重试。重新评审只是安排后续比较，必须显式开始阶段才调用模型。排除保留旧证据，当前接口没有撤销。执行处置与保护候选复核保持两个明确用途。

## 离线实验

“实验配置”视图可创建 1–12 个变体，分别选择已有阶段、Davidson/Borda、计算参数和可选分半种子。保存定义冻结已有证据，运行调用现有 runExperiment；确定性任务身份保证重复运行不会复制任务。定义草稿和创建键持久化，返回丢失后能重试。

实验列表、阶段选择、结果列表保持有界分页。结果可进入排名，或把两份快照带到现有对照页面。比较不同模型或 System Prompt 需要先取得对应阶段的证据；本界面没有自动派发多模型评审或融合分数。
