# 0057：全湖排名读取与固定输入复用

日期：2026-10-04。

千万级在线湖的排名原先先复制成员，再按小批成员重复查宽元数据，最后生成、读取和校验完整输入。原 4 GiB 分析内存上限还会在进入评分前使全量投影失败。优化目标按提交任务至成果持久化、读取首批排名记录的端到端时间衡量；首轮与固定版本复跑分别报告。

## 固定范围与来源读取

单一保留版本的全来源排名直接使用发布计数和版本租约固定成员。`job_scopes.provenance_json` 的版本 2 标记 `membership=ranking_input`；排名输入自身是成员材料，`members` 使用只读视图，不再把同一组身份复制进中间成员库。来源删除依赖检查同时读取任务的来源版本。

在线全湖通道按表行号扫描图片、资产、当前帖关系及原始尺寸，内存中只保留身份链接和尺寸。图片序号仍按 SHA-256 排序。宽观察按有界页面并行读取，再交给单个材料写入器；到达顺序不代表最终序号。准入估计涵盖对象、资产、稀疏观察号数组、解码页和写入缓冲，不满足条件时回退原有有界通道。

单条当前观察可直接构造类型化输入；重复帖、特殊时间或尺寸表达、超大字段保留 SQL 参考路径。重复帖的最新元数据、热度合并、尺寸来源及未知值语义不变。原始记录仍检查解压长度、尾部、摘要和 JSON。

只读大文件映射在批量通道中按需启用。批次之间结束 SQLite 读事务、重新检查保留版本并续租，连接和映射可以复用；不持有覆盖整个湖的 WAL 读事务。仓库内编译的 SQLite 提高映射上限并关闭未使用的全局堆统计，避免并行分配争用。映射页使用操作系统文件缓存，不等同于独立堆缓冲。

## 材料与检查点

全来源输入先顺序写入堆表，再建立唯一身份、序号与查询索引。输入格式沿用现有字段及版本；读者通过列和索引读取，不依赖物理行号等于排名序号。唯一索引、总数和序号范围共同校验覆盖，来源和序号范围在写入时检查。

这份尚未封存的私有输入在中断后会重建，因此构建期关闭回滚日志与逐批同步。引擎在写入完整标记后关闭连接、同步整个文件、生成摘要，最后原子保存执行计划；未封存材料不能发布或供执行器消费。普通范围与其他项目写入继续保留原有事务规则。

排名结果的恢复边界是资格分类或一个完整分级。结果写入器按这个边界提交私有事务，未完成分级在恢复时删除并重算。统计随已写出的结果累计，并与同一个检查点持久化；旧检查点缺少统计时先清除未提交到检查点的分级，再重建一次统计。索引使用预算内缓存与 SQLite 排序辅助线程；`temp_store=MEMORY` 会关闭这些辅助线程，因此使用文件支持的排序段。

分类、候选加载和校验各自只读取实际消费的字段。发布前仍核验输入摘要、完整覆盖、资格、特征范围、分数组成、名次排列、分级名额与输出摘要。没有抽样替代全量校验。已不被读取的年份辅助索引不再新建，现有成果仍可读取。

## 固定版本复用

复用只在当前项目内查找已发布的全来源排名，要求来源版本、成员总数、算子版本和投影规则一致。投影规则包括重复帖策略、是否捕获 V2 标签、是否请求尺寸；旧的完整代表策略还要求相同分级集合。阈值、时间系数、年代偏好、种子等评分参数可以改变，分数仍重新计算。

引擎先核对候选材料头，再把输入复制到新任务的私有目录，在复制过程中校验原摘要。摘要不符则放弃该副本，寻找其他候选或重新捕获。验证成功后仅在新副本中更新任务参数、时间与资源预算，再重新生成本次摘要。原成果不被改写，新成果也不依赖旧成果文件的持续存在。

新来源版本、不同投影规则、缺失或损坏的快照均不能被默认为命中。界面以“复用固定元数据”展示该阶段。复跑时间包含复制核验、计算、校验、发布和首屏读取，不能把缓存构建耗时计成零首轮成本。

## 验证边界

使用 `tooling/benchmark-ranking.mjs` 保留参数、二进制摘要、阶段遥测、成果和首屏证据。操作系统缓存未强制清空。接口级首屏不包含图片缩略图解码时间。测试与真实数据材料不进入 Git；验收记录单独注明首轮与复用场景。完整来源/物化范围对照、参数变更、损坏副本、取消恢复和旧检查点兼容由回归测试覆盖。
