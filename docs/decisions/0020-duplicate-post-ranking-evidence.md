# 0020：重复帖热度、最新分级与评分浏览口径

日期：2026-09-13。状态：已采纳。

同一图片可关联多个 Danbooru 帖子。旧实现从中选一条完整代表记录；较新的低热度重复帖可能覆盖原帖的热度。通用 Rating 查询又允许任意关联当前帖命中，造成 G 查询混入评分时属于 S/Q 的成员，并按分级拼接到尾段。属性页默认记录也可能与评分记录不同。

用户要求以较高评分或重复帖评分合计为热度依据，分级冲突默认取最新元数据。该要求替代原实施设计中“所有评分字段必须来自一条代表记录”的默认限制；旧规则继续可选。

## 输入规则

- 新参数 `duplicate_heat`：`highest` 为新建配置默认值，`sum` 为可选合计，缺省或 `null` 保留旧完整代表规则。缺省的历史任务不会因更新程序而改变含义；编辑中的旧配置草稿升级到 `highest`，显式选择的 `null` 保留。
- 新规则以实际已登记图片身份为边界；只在同一图片关联的帖子之间处理。成员范围先固定，不以 parent_id 或相似标签扩大图片范围。
- 当前记录模式下，在该图片的所有关联当前帖中选最新元数据；原查询负责选择图片成员，不再把另一关联帖的热度或最新分级挡在输入之外。显式历史观察模式仍限制在命中该历史查询、且与图片内容相符的观察中。
- 同一帖子先取最新可用完整观察，多个查询分支、来源记录或历史快照不能重复累计其互动。无 post_id 的记录按稳定记录身份区分。
- 最新的判定沿用已知观察时间和精度：日期级与当日精确观察无法明确分先后时比较 updated_at，再按来源优先级、观察/记录身份稳定排序。新版不优先选择被勾选的 Rating；最新分级不在参与范围时正常排除，分级未知时保持未知。
- `highest` 使用与公式一致的收藏/赞票热度顺序 `(fav+1)×(up+1)`；只有一个字段有效时使用该字段的平方形式。取胜帖的收藏、赞票、负票、净分和时间整套使用，避免逐字段拼接各帖最大值。分级、标签和状态来自最新元数据记录，来源分离被明确保存。
- `sum` 将不同帖的有效收藏、赞票、负票绝对值和净分分别合计。负净分仍参与合计；缺失或无效计数不补零冒充完整数据，部分合计有明确标志。统计以宽整数执行，超出存储整数范围时饱和并记录标志。
- 合计代表帖子互动总量，不表示去重后的独立投票用户数；现有字段无法识别同一用户在多个帖子上的重复投票。
- 较高记录模式使用热度帖的上传/观察日期。多帖合计使用最早已知发帖日期，但不伪造单一帖龄：观察时间为空、精度为 aggregate，时间参考沿现有未知时间路径回退。单帖不改变时间处理。

## 冻结与兼容

新输入材料保留数值、元数据记录和热度来源的独立证据。多帖输入保存 `RankingDuplicateEvidence`，包括最新元数据观察、热度来源、不同帖子总数、部分合计及整数上限标志。合计精确覆盖全部合格帖子，明细最多保存 64 条并标明省略数量；单帖不写冗余 JSON。中间重复帖关系不复制大标签载荷，详细合计和证据关系仅为多帖图片物化。

输入材料版本 3 表示 v1 公式加新证据，版本 4 表示 v2 公式加新证据；既有输入版本 1/2 和评分材料版本 1/2 均继续读取。评分成果格式及原公式仍区分 v1/v2，输入证据独立演进。验证核对材料能力与任务参数相符。

改变输入规则创建新成果。既有成果及其文件不原地改写；清缓存也不改变其评分依据。查看层修复可以直接作用于旧成果，但采用新热度规则需要重新提交排名任务。

## 筛选与浏览

- 新派生字段 `project.<artifact_id>.rating` 表示该成果冻结的评分分级，支持等于和集合包含。查询持有成果引用，成员真正按该字段过滤，因此批量选择、保存工作集和分页使用同一范围。
- 排名工作集的快捷分级筛选默认构造该字段；标签仍按当前元数据检索，界面说明二者依据。纯评分分级查询直接从已有评分索引有界读取候选；混合条件复用一次打开的评分材料进行有界过滤，避免先枚举整个数据湖。
- 浏览器自行生成、尚未被用户编辑的旧 Rating 筛选会生成对应的新查询结果，保留旧结果记录。升级保留查看顺序和方向，重置可能已离开范围的旧定位起点。新查询继续使用既有 family/member_revision 缓存机制；升级后重复切换和重启不重复构建等价索引。
- 通用当前帖子 Rating 查询仍保留原有检索语义；从这类查询按排名浏览时，明确提示可能包含其他评分分级。各分级榜单明确标为分别排序，不能把列表末端解释为跨分级低分区。

## 属性与协议

- 排名卡片携带评分记录/观察身份。属性页通过新的单条排名读取接口取得冻结输入，直接展示实际用于计算的数值，以及热度记录和分级记录的区别。
- 属性页默认定位评分元数据观察，支持按观察 ID 有界读取；可以继续浏览其他关联记录和历史观察。原始 JSON 入口明确标示帖子和观察日期。
- “年代”表示同 Rating 全体的年代相对榜，不冒充单年名次；年内名次仍在评分详情中单独显示。
- 所有公共字段和路由由 `pnpm contracts` 生成 OpenAPI/TypeScript 契约；查询、任务和文件写入均经引擎执行，数据湖只读。

## 验证要求

覆盖正常原帖与更晚低热度重复帖、同帖旧高票快照、重复查询分支、跨分级最新记录、未知计数、整数上限和有界明细；覆盖 v1/v2 与旧输入兼容、纯分级及混合 Tag 查询、正反方向和全部查看顺序、实际选择范围、查询别名和重启缓存复用；用真实界面验证旧筛选升级及评分原始元数据的默认定位。

这些验证证明输入和浏览语义，不证明审美质量或好图召回率提高。完整质量比较需用重新计算的新成果和独立标注进行。
