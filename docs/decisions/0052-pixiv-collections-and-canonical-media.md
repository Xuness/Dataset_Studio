# 0052：Pixiv 采集与规范多媒体湖

日期：2026-10-03。状态：阶段 1–3 已实现，前端页面暂缓。接口和使用入口见[接入说明](../architecture/source-collections.md)，实测边界见[验收记录](../verification/2026-10-03-pixiv-stages-1-3.md)。

后续：[0053](0053-pixiv-public-operation-and-incremental-refresh.md) 已接入现有界面、公开完成状态、增量复查和周期计划，并将控制库推进到 v10。下文保留阶段 1–3 的实现基线。

## 关系与兼容性

Pixiv 使用独立湖实例、归档格式 2、在线格式 3。旧 Danbooru、Yandere、Gelbooru 继续使用归档 1 / 在线 2，项目图片身份仍为 `source_id + stored SHA-256`，不重写已有湖和工作集。

新 `media_lake` 保存作者、作品观察、媒体清单、清单成员、动画帧时序、取得凭据、来源资产和物理对象。页序号属于一次清单，不是永久文件身份。相同文件只保存一份 TAR 对象，不合并不同页或作品的来源记录。原始响应以 Zstd Parquet 归档，在线原文为有长度和 SHA 校验的压缩副本。

每次发布使用固定水位。最新完整清单替换当前成员；未取得的新页不会借用旧清单相同序号的图片。未完整取得的清单保留其观察及缺口，当前已知完整清单标为需刷新。作品条件与媒体条件在同一来源关系中匹配后再按物理 SHA 去重；Pixiv 标签保留空格和原文，不使用 Booru 的空白切分。

Ugoira 保存网页返回的 ZIP、帧名和时序，并派生首帧 PNG。ZIP 是归档对象，不能进入普通图片浏览或图像解码器。原图与派生图保留配方、来源 SHA 和取得证据。历史复用显式标为 `historical_reuse`；本版 `revalidate` 重新下载，不声称执行了 HTTP 304 校验。

## 控制、恢复与资源

共享控制库升级为 schema 8，新增采集账号、任务、实体前沿、依赖、检查点、回执和派生计数表。v7 及更早版本升级保留旧任务和调度顺序，先检查旧运行器及执行锁。旧 `/v1/lake-updates` 不返回 Pixiv 行；新接口位于 `/v1/source-collections`。

新任务与旧更新由同一个受控 Python 进程调度，共用每设备写入、活动湖数、下载、编码、解码内存、暂存和带宽预算。调度以湖轮转；默认时间片 30 秒，已开始的有界网络请求与归档必须结束或安全交接后才能让出。Pixiv 默认下载并发 2、API 1 次/秒、媒体 2 次/秒。元数据执行当前每湖单路，`metadata_concurrency` 是保留的上限设置，调大不会产生额外并发。图片编码及动画封面是一次媒体取得任务的必需输出，共同确认后归档。

任务先归档固定意图，再发出请求。持久结果回执先落到任务私有暂存，封存并提交归档后，控制回放与在线发布分别确认。两者都确认、没有执行消费者后才回收暂存。首次归档接受校验 execution epoch、claim token 和输入指纹；已入归档的事实可以在暂停、取消或新执行代次后继续回放，不重新启动采集。发布先于控制确认的计数也必须只应用一次。

暂停保留断点；取消等待实际持有者退出并回放已接受结果，只清理任务私有临时文件。含缺口的已结束任务也可取消以回收诊断原件；归档证据不删除。预算耗尽为 `waiting_budget`，继续操作重置本轮预算但不改变固定任务定义。有限自动重试耗尽后进入缺口或待核查状态。

作者目录和关系发现分别保存进度。公开关注、公开收藏和作品推荐以有深度限制的图扩展；作品到作者、作者到目录作品不额外增加关系跳数。较短路径重新传播已知边，并重新允许此前只因深度限制排除的发现任务。目录结束只证明当次可见列表已经遍历。

## 会话与覆盖

账号明确区分 `anonymous` 和 `session`；这是相对设计基线增加的公开验证模式。登录 Cookie 和含秘密的幂等请求摘要通过 Windows 当前用户 DPAPI 保护，接口及日志不返回秘密。媒体连接使用独立空 Cookie 容器，限定 HTTPS pximg 地址且不跟随重定向。

登录会话先由服务端页面确认用户 ID，并绑定本地账号引用；运行时间片开始时重新检查。更换为另一用户、失效或交互验证不会退回匿名执行。Cookie 更新使用修订比较，旧执行不能覆盖新导入。

用户 ID 被验证不等于 R-18、R-18G 或 AI 显示条件被验证。这些条件本版保留 `unknown`，不推断完整覆盖；因此公开样本即使媒体缺口为零，仍可能结束为 `completed_with_gaps`。真实登录和完整可见性探针继续待验收。

## 维护与后端

`archive_rebuild` 按归档版本分派，新格式使用与增量发布相同的事实导入和投影代码。无需旧在线库即可构建独立准备库；固定归档前缀、原文、外键、数据库、全表签名及可选参考快照分别校验。参考快照受租约保护。激活不覆盖现有在线指针；旧版本关系、生产者索引退役和旧单帖 bindings 不套用到新格式。

搬盘继续使用共享位置门闩、发布锁和检查点，保留 schema 3 的代次及版本。Rust 来源读取保持原生有界分页，增加作品、媒体清单、作者与作者目录端口；现有图片、元数据、历史观察、原文和条件查询可消费 Pixiv。SDK 与 OpenAPI 从 Rust DTO 生成。运行包同时嵌入 `.py` 和 `.sql`，避免开发环境与内置运行器不一致。

本决定落实[三份设计契约](../plans/Dataset%20Scraping/contracts/README.md)。账号公开模式、派生计数及发现边表、媒体原子取得单元以本文和实现为准；设计期 SQL / JSON 继续作为当时的基线，生产 API 以生成的 OpenAPI 为准。
