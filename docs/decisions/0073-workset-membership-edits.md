# 0073：编辑已有工作集的成员

日期：2026-10-09。

工作集可以加入图片、移除图片，也可以移空后继续使用同一 ID。移除只修改项目中的成员关系，不删除数据湖中的原图，不修改项目选择。入口位于浏览操作栏、选择属性和图片/大图右键菜单。

## 版本与提交

项目数据库升级至 v15，仍使用 manifest v1；升级前沿用项目数据库备份流程。旧工作集从成员版本 0 开始，已有查询结果中的工作集范围补为版本 0。

`Collection.revision` 是成员版本，与工作集名称等管理信息的版本分别维护。`ScopeTarget::Workset` 的可选 `revision` 指定历史成员；省略时，在接收查询或任务的存储事务中固定当前版本。查询结果、分页签名和排名描述均绑定该版本。`runLatest`/`browseLatest` 显式重新读取工作集当前版本；直接读取旧结果仍得到旧成员。

`POST /v1/projects/{project_id}/collections/{collection_id}/members` 接收请求 ID、目标工作集的 `expected_revision` 和 `add`、`remove` 或 `restore` 操作。加入/移除接收后端范围引用，或最多 512 个显式图片身份。来源/浏览视图先通过既有捕获流程得到固定引用。

成功回执记录实际变化数、输入数、操作前版本和操作后的工作集。重复加入、移除不存在的成员均自动跳过；没有变化时不增加版本。同一请求 ID 重试返回原回执，不再次发布版本，即使原输入引用后来已不可用。版本冲突要求重新读取状态。撤销将指定旧版本的成员恢复为一个新版本，并要求当前版本仍与回执一致；不覆盖后续编辑。

## 存储和读取

基础成员继续使用既有 `collection_member_legacy`、固定查询结果或不可变排名材料。`collection_member_changes` 仅保存发生变化的身份及其有效版本区间；原成员、排名输入和评分文件不改写。读取关系排除基础成员中已有覆盖的身份，再合并该版本的显式加入项，避免恢复成员时产生重复。

`collection_versions` 保存各版本数量，`collection_edit_requests` 保存幂等回执。变化项、数量、版本和事件在同一事务提交。处理中断、取消或来源验证失败时整体回滚；批次最多 128 项，SQL 扫描支持取消。读者继续读取已提交版本，同项目其它写入按既有单写入者机制排队。

当输入与目标共享基础结果，或者输入排名范围可以证明属于目标的完整排名材料时，加入操作只比较目标排除项和输入新增项，不枚举未变化的基础成员。其它范围通过后端关系计算差异，不把大成员列表送到前端。

任务和项目选择继续采用固定基础引用与独立覆盖项。复制已有工作集时，复用基础结果并复制当前覆盖项；传统没有基础结果的工作集仍沿用原有复制成员行为。成员历史目前随工作集保留，不单独自动回收。

## 排名与历史依赖

排名描述增加固定成员版本的覆盖层。已在原排名输入中的图片复用原评分；外部新增图片保存加入时可用的基础信息与 Rating，保持未排名。按主、补救、直接或融合名次浏览时，正向和反向都将未排名成员放在已排名成员之后；分页、帖子定位、分级名次和总榜位置使用相同规则。输入顺序仍使用输入序号。

新增成员保留来源适配器给出的图片身份，包括内置参考图的 `sample-*` 标识。成员分页将原 SHA-256 索引与新增文本身份分别读取再有界合并；文本游标可转为原哈希索引的比较边界，不要求把全部原成员转换成文本或复制到新索引。

Rating 条件作用于当前完整成员，包括新增图片。新增图片没有原评分时，Rating 使用加入时按来源查询取得的分级；分级冲突或不可用时保留未知。标签条件沿用当前元数据语义。组合查询保存排名描述，并用自己的固定成员结果限制范围；这样可以继续按原评分排序，也能保留新加入的未排名图片。

派生工作集的覆盖层可叠加在固定查询结果之上。查询结果持有它使用的工作集版本和中间成员结果引用；删除、释放和缓存回收使用这些引用保护历史。释放结果同时移除对应版本引用。工作集仍被排名结果引用时，删除工作集会说明依赖并拒绝删除。

成员材料与显示方式分开：通过普通“保存当前范围”创建的工作集不会仅因复用排名材料而自动采用排名排序，既有的普通工作集行为保持一致。

美学评审的配置保存 `membership_revision`，准备阶段逐批冻结该版本。旧配置缺省为 0，序列化时省略 0 以保持旧配置哈希兼容。编辑当前工作集不改变已提交评审的准备输入和账本。

界面在成员更新后重置当前工作集的分页游标，保留用户选定的排名顺序和方向。历史筛选结果继续显示原版本，并提示刷新或重新应用筛选。

## 验证入口

- `pnpm test:rust -p studio-storage collection_edits::tests`：版本、撤销、空集、幂等、失败/取消回滚、相同数量的不同缓存版本、排名/查询派生，以及十万成员共享基础下的有界差异比较。
- `pnpm test:rust -p studio-storage --test migrations`：包括 v14 的工作集查询固定到版本 0，以及升级备份和旧成员保留。
- `pnpm test:integration worksets`：隔离合成湖的 HTTP、任务、游标、跨来源新增、排名/Rating/标签、重启和不可变材料校验。
- `node tooling/smoke-workset-members-ui.mjs <integration-worksets运行目录>`：2560×1440、100% 缩放下的实际操作栏、图片/大图菜单、撤销、丢失成功响应后的同键重试，以及空工作集重新加入。

这些测试使用 `.local/test-runs/`；不修改正式工作集，不代表千万级差异写入的吞吐测试，也不触发付费模型调用。
