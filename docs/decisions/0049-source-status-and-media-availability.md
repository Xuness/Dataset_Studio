# 0049：来源状态与原图可获取性分离

日期：2026-10-01。

## 背景

Danbooru 新帖补全中，部分 `is_deleted=true` 的帖子仍在 API 响应中提供原图地址。旧更新服务在检查地址前直接将 Delete/Ban 标记转换为 `source_deleted` / `source_restricted`，因此没有请求仍可访问的原图。

## 决定

- 三站共用的更新下载流程按 API 返回的可用地址决定是否尝试获取图片；`is_deleted`、`is_banned` 不再作为独立的下载否决条件。
- 原始 API 响应、原始元数据和结构化观察继续保留来源标记，成功下载不会清除或改写标记。
- 原图、备用图许可、已有资产复用、HTTPS 与站点域名检查、格式支持范围、资源预算、MD5 校验和编码配方保持各自语义。没有允许使用的地址时记为 `no_image_url`；有地址但请求失败时保留实际 HTTP/传输错误。
- 旧任务的 `source_deleted` / `source_restricted` 历史回执仍有效。“重试未获取项”沿用既有逻辑刷新这些条目的元数据，再用新规则处理；已保存项不重排，暂停状态不会自动解除。

不改变控制库或数据湖格式，不回写历史元数据，不需要重新导入。旧独立每日流程不由 Studio 更新服务接管。

## 验证

回归覆盖三站、原图与自定义配方、Delete/Ban 四种组合、原始及结构化标记保留、无原图地址、未支持格式、HTTP 403/404，以及真实归档回执下的旧任务重试。真实图片与验证边界见[验收记录](../verification/2026-10-01-source-status-downloads.md)。
