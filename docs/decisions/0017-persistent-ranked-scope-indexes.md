# 固定范围的持久化排名索引

2026-09-11，开发版本 0.9.1。

本决定替代 0012 中排名浏览的逐批交集及旧输入 ID 扫描路径，以及 0016 中的首页成员前缀缓存。排名工具表格、独立计数、选择标记读取、普通来源浏览索引和成员原子写入仍按原决定执行。

## 问题和职责

固定查询结果已经保存准确成员，但排名浏览此前仍沿完整成果读取候选，再逐个判断是否属于该范围。单次只检查 4,096 项保证了请求有界，却没有限制生成一页所需的总工作量。任意两张匹配图片之间都可能有很长的非成员区间；首页前缀缓存只能处理首页，无法改变后续页面、返回旧页以及引擎重启后的扫描成本。

成员固定和视图排序分别表达，但排序必须以当前固定成员为输入。由存储层生成只包含该范围成员及排序标量的 SQLite 投影，引擎管理准备、发布、租约及容量，浏览接口只按索引读取。前端继续传递 ScopeRef 与游标，不持有完整成员，不承担推进完整成果扫描的职责。

## 索引内容和一致性

`ranked-index/<key>.sqlite` 是应用拥有、可以重建的临时缓存。格式版本为 1，键包含固定范围、原工作集、排名成果及其文件摘要、保存条件和成员数；不包含页大小、查看依据、方向或起点 ID。同一固定范围的主排名、补救排名、输入顺序、两种方向及所有帖子起点共用一份文件。

构建从 project.sqlite 的 result_members 或 collection_members 出发，通过原输入的身份索引和评分的 ordinal 主键取得成员。只复制 ordinal、原评分分级、两类名次和帖子 ID。当前帖子筛选得到的 S 成员可能在旧评分中属于 E/G；保留它们的原分级和名次，不能把当前 S 条件替换为旧评分 S 条件。复制数必须与固定成员数完全相等，否则不发布。发布前再次检查范围仍存在且成员数一致。

项目、固定输入及评分文件使用只读附加连接，复制完成后先分离，再建立六个索引：三种查看顺序及各自的帖子定位索引。每一顺序以原评分分级、名次或 ordinal、ordinal 排序；空名次置于已有的末尾哨兵位置。降序反转完整顺序。同一帖子对应多个成员时，定位当前顺序中的第一个，并将其包含在返回页中。

每页最多读取 129 个位置（128 个显示成员和一个下一页判断项），然后按主键补齐有限的展示信息。分级集合固定为五组；同名次内按 ordinal seek，再读取严格大于或小于当前名次的段，避免 SQLite 在大量同名次或空名次成员中重新过滤长前缀。帖子定位也使用对应索引，不再分段扫描旧输入文件。

## 准备、取消和发布

同一个键只启动一个后台任务，等待队列最多 16 项，构建串行执行，并取得查询工作预算和 Background NativeQuery 资源许可。内存预约最多 512 MiB，各 SQLite 页缓存有界，排序允许使用磁盘临时空间。

仅私有 `rank-build-*.sqlite` 可写。候选文件通过 max_page_count 限制大小，全部索引和完成标记写入、复核预算并同步文件后，才原子发布。取消、错误、预算不足或成员不一致都不发布半成品；启动时清理应用目录内遗留的构建文件。进度明确区分成员复制、各排序索引整理和发布，成员复制完成不等于全部准备完成。

准备期间返回 preparing 和范围成员进度；浏览器每 500 毫秒重试同一个请求游标。后续页面不再返回扫描续读游标。现有游标的签名、位置、待展示成员及起点仍被验证，旧的 Seek 状态直接通过新索引定位。已有会话和页面书签无需迁移。

Browser 父级在排名视图活跃期间每 20 秒续租，租约有效 90 秒，页大小或排序变化不会丢失范围保护。若构建既没有活跃视图，又超过 5 秒没有读取请求，则取消；关闭引擎也取消构建并等待退出。已完成任务状态不替代文件存在性：索引被回收或损坏后可以立即重建，不等待旧任务状态过期。

## 容量、复用和回收

索引计入临时缓存和总容量；设置页展示其字节数，资源接口还提供条目、完成构建及读取复用计数。构建时从当前总预算和临时预算中扣除其他已保留数据，最多使用剩余空间的一半且单份不超过 8 GiB，为构建工作空间留余量。发布前再次检查预算。该策略与已有缓存一样属于保留容量控制，不承诺进程内存或 SQLite 内部临时文件的绝对硬上限。

已完成文件跨引擎重启复用，正常保留期使用用户配置的临时闲置时长；会话内保留选项、容量压力和显式清理同样适用。最多保留 128 份；活跃范围租约和正在读取的文件不能被清理，未受保护文件按最近使用时间回收。文件最近使用时间最多每分钟持久化一次。构建私有文件单独计入工作中临时空间。

打开时校验版本、完整元数据和六个索引；发现损坏或不匹配的派生缓存后删除并重建。读取取消不会使正常索引失效。项目数据库、工作集格式、排名文件及原 SHA-256 不变，无需数据迁移。

首次进入一个尚未准备的固定范围需要完成一次全范围索引构建；该成本与固定成员规模有关，并没有消失。换到另一个固定结果，或缓存确实被清理后，也需要重新准备。正常保留期间的页大小变化、全部页面、方向和起点切换均直接读取同一索引。

## 验证

存储测试使用稀疏范围及大量相同/空名次，检查后部游标和帖子定位的 SQLite 指令数有界，验证取消、空间不足、成员数量不符、重新打开和原文件摘要。缓存测试覆盖活跃租约、读取保护、关闭视图取消、会话结束回收以及损坏恢复。

API 集成通过独立成员交集及排序结果核对 110 个连续页面和六个旧页书签，覆盖跨越缺失分级的大空档、并发 12/48/96 页大小、三类顺序和方向、旧游标、引擎重启及反复清理后重建。真实 React 夹具执行连续翻到第 110 页、刷新以丢弃内存页缓存、返回第 81 页，以及切换页大小；就绪索引下不得出现 preparing 或新增构建。生产范围的只读验证及性能证据保留在 `.local/reports`，不将测试夹具时间当作真实规模承诺。
