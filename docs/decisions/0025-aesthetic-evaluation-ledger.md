# 0025：美学评审的持久执行与图片准入

日期：2026-09-18。状态：第一阶段实现。

美学评审会产生付费且非确定性的远端调用。现有纯算子会重新计算输出进行校验，不能承担这类执行。此次新增独立评审执行器，复用 LLM 服务、来源适配器、项目租约和公共 SDK。

## 数据归属

- `project.sqlite` 升至 v10，仅新增阶段目录引用及输入保护关系。旧项目按现有机制先备份再迁移，不重算旧成果。
- 项目根目录的 `evaluation.sqlite` 是权威评审账本，独立模式 v1，使用 WAL + FULL。保存阶段配置、冻结候选、批次、尝试、模型返回及接受证据。它不属于可清理的预览或查询缓存。
- 一个项目使用一份账本。网络调用协程通过专用写线程提交短事务；确认返回发生在 COMMIT 之后。写队列最多 64 项、64 MiB，单项最多 32 MiB。第一版不延迟凑批。
- 候选按 64 项分页冻结并分批提交，不在项目写库中复制全量成员。冻结结束前保留工作集引用；阶段完成或取消前保留来源引用。未完成冻结不会发布为可调用阶段。
- 主库目录是可恢复投影。状态同步在主库写锁内重新读取权威账本，避免迟到的状态覆盖；重新获取项目租约时执行对账。两个数据库之间不假设原子提交。
- 接受证据具有单调序号、逻辑批次唯一约束和解析版本。曝光与保护状态在同一个接受事务中更新。后续估计器应消费证据水位，不把模型输出当作可删除缓存。

## 冻结与业务语义

第一阶段输入为已保存的工作集。阶段固定模型和连接版本、解析后的参数、System Prompt 原文及版本、候选范围、来源水位、图片规格、分组与观察规则、曝光次数和调用次数上限。User Prompt 根据当前批次生成，不进入全局预设管理。

同梯队使用 `meaningful_indifference_v1`：在指定标准下不存在有意义的质量差异。返回包含 `schema_version`、`tiers`、`elite_candidates`、`unjudgeable`。后者由 `id` 和 `reason` 组成。所有短 ID 必须恰好出现一次；拒绝、截断、遗漏、重复、未知 ID 不能成为有效证据。顶级提名必须属于已判断图片，可以为空，不增加额外曝光或分数。

Danbooru 分组读取资产来源观察：评级不一致标记 `conflict`，缺失标记 `unknown`，这些图片保留但不参与评审。年份取来源帖子的最早创建年份代理，保留规则和来源水位，不声称是作品创作年份。冻结后的分组不随每日索引更新改变。演示来源使用固定合成分组。

组批优先补齐曝光，同 Rating 内随机化顺序，以同年为偏好并保留混合年份位置。这里是证据采集的基线组批器，尚不提供统计置信度、比较图连通性保证或自适应争议检测。单 Rating 不足 16 张时使用小批次；不重复图片补齐批量。

## 发送与恢复

```mermaid
flowchart LR
  A[冻结阶段] --> B[领取批次]
  B --> C[图片准入与内容校验]
  C --> D[持久记录调用尝试]
  D --> E[远端调用]
  E --> F[返回先落盘]
  F --> G[本地结构与语义校验]
  G --> H[接受证据与保护状态]
```

创建阶段仅冻结输入，不自动调用模型。开始评审需要明确的运行操作。暂停停止新增发送并等待已发送调用返回；取消还会取消活动网络等待，已保存证据保留。

一次账本尝试对应一次网络尝试。本执行器禁用底层隐式 429 重试，保留失败记录并交由明确操作重新排队。单个逻辑批次最多 8 次尝试，只有一份有效结果进入证据；独立复评应创建新的逻辑观察。

新引擎取得项目租约时，已发送但没有保存返回的尝试变为 `outcome_unknown`，运行阶段转为暂停。它们不会自动重发。结果已保存但尚未解析的尝试可在本地继续处理，无需模型调用。该保证是本地证据不重复接受，不是供应商账单的 exactly-once 保证。

写入失败时已收到的付费返回保留在受限内存中重试，并停止新的评审派发。持续磁盘故障时关闭会等待落盘；强制结束仍可能失去尚未提交的返回，重启后按结果不明处理。不能把内存接收等同于持久保存。

## 图片和资源边界

第一版使用原始 WebP、JPEG、PNG 字节，不复用浏览器生成的 JPEG 缩略图，不改变压缩质量。单图上限 2 MiB，完整原生请求上限 12 MiB；超限停在发送之前。变体生成、远端文件复用和规格质量实验属于下一阶段。

引擎最多同时执行 8 个阶段；阶段配置允许 1–32 个请求，实际受共享资源额度约束。所有评审共享 512 MiB 的请求工作内存预留，单个请求保守预留 104 MiB，涵盖图片/JSON 副本和结果写入空间。因此这一版通常最多同时准备/等待 4 个请求；没有把配置中的 32 当作容量承诺。来源读取继续使用已有共享协调器。

按序列化请求字节，以 3,500,000 字节/秒（28 Mbps）控制发送准入间隔。它是对应用户约 40 Mbps 上行的保守起点，不是操作系统 TCP 限速器，也不包含项目外流量。接口提供在途请求、当前/峰值内存预留、请求体字节、写入队列字节指标；预留量不是 RSS 实测值。

阶段调用次数是硬上限，包括失败和结果不明。记录供应商 token 用量；未返回用量保持未知。尚未实现价格表、货币费用上限以及跨账户 RPM/TPM 预算。

当前实现严格核验冻结的模型和连接版本。修改这些配置后旧阶段停止发送，需要新建阶段；历史证据保持可读。凭据由现有凭据服务读取，不保存在评审配置或返回记录中。

## 项目生命周期与备份

运行阶段持有项目租约，关闭页面不终止后端工作。阶段引用参与对象删除保护。账本位置相对项目目录固定，随完整项目目录移动。

“备份评审账本”使用 SQLite Backup API，生成项目 `.backups` 中的独立一致 SQLite 文件。它只备份评审证据，不能代替完整项目备份；完整备份还需要项目元数据、成果及必要文件。打开项目时若有阶段引用但权威账本缺失，会明确报错，不悄悄创建空账本替代。

## 后续边界

本阶段没有发布全量统计排名、完成自适应采样、多模型融合或人工裁决；顶级提名只进入保护候选。开发顺序仍按[实施规划](../plans/aesthetic-ranking/implementation-and-validation.md)推进。下一阶段需要以小样本校准 Prompt、梯队语义、图片规格和估计器，再形成真正的全量榜单。
