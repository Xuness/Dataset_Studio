# 0053：Pixiv 公开运行、增量复查与现有工作台接入

日期：2026-10-03。继承 [0052](0052-pixiv-collections-and-canonical-media.md) 的作品、媒体和归档协议。归档仍为 2、在线为 3；采集控制契约为 2，控制数据库为 10。使用入口见[来源采集](../architecture/source-collections.md)。

## 完成状态与范围

`completed` 表示固定任务范围内的关系遍历、目录、详情、清单及所需媒体已处理并发布，没有实际任务缺口。公开账号可以正常完成任务；`visibility_verified=false` 独立保留，不再单独导致 `completed_with_gaps`。任务详情分别显示范围排除、未获取项、媒体缺口、发布积压以及登录显示条件。

Pixiv 的未知标记不推断为正常或 AI。`scope.include_unknown_markers` 明确控制未知分级、作品类型与 AI 标记；UI 默认勾选并允许修改。真实旧作品存在 `aiType=0`，必须保留原值，不能因为目录遍历结束就宣称这些作品已取得媒体。已建立任务的范围不随默认值改变；扩大范围创建新快照。

成功 JSON 无法规范化时，也先保存完整有界原文并归档为待检查结果。JSON 错误响应保留来源错误码及原文；登录或交互验证 HTML、Cookie 头不进入普通元数据。任务摘要保存 capture 引用，可通过有界 raw 读取检查，不用重新请求才能恢复诊断依据。

## 增量复查

任务定义增加可选 `refresh`：`all` 获取新详情与清单，`missing_or_stale` 在有效期内沿用完整旧快照。旧定义省略该字段时继续使用全量刷新行为。

沿用要求同一可比较访问条件、有效期内的详情与完整清单，以及所选配方的每页所需文件齐全。已发布媒体包丢失或截断进入完整性异常。元数据采集不能冒充已有原图；改变配方、缺页、过期或访问条件变化都需要重新获取。沿用只保存对既有观察和发布水位的证据引用，不伪造新的观察或下载时间，也不增加新下载计数。

同一次目录可将最多 256 个已满足作品的证据与目录一起归档，查找预算为 2 秒，剩余工作继续由普通队列接续。控制回放仍创建逐作品任务及父依赖，标明沿用的观察、清单和水位；中断重放不重复计数。这样避免为每个已完整作品单独写一个空事实批次。

作者目录每轮重新获取，同可比较条件的上一目录计算新增、仍列出、本次未列出数量。未列出仅为观察结果，保留既有作品、图片和历史证据。作品清单优先于后续独立详情进入处理，使新任务能边解析边下载。

文件级 `historical_if_same_locator` 仍是另一项显式策略：新清单中相同作品位置、地址、尺寸、帧表、配方的有效历史文件可以复用。快照沿用、历史文件复用、新下载和 HTTP 核验分别计数；没有把重新下载报告成 304。

## 周期与协调

手工创建和周期触发共享同一数据库事务、幂等请求及任务准入。相同湖、账号和完整定义的未结束运行任务合并，返回 `coalesced`；不同访问方式、预算或范围仍是不同意图。原请求键始终绑定原结果，即使该任务后来结束。

`needs_review` 不阻止显式新建复查，便于使用新可见条件或修复后的来源创建新快照；原待检查任务及证据保留。周期计划仍等待上一轮明确结束。

周期快照在现有后台进程中执行，支持修订保护、启停和移除。漏跑周期合并到最近一次；上一轮暂停、等待预算、凭据或人工处理时等待，不堆积新的副本。预算续跑不会修改固定任务定义。没有安装另一个常驻服务。

控制 v9 增加周期表与任务证据摘要。v10 补齐早期已标记为 v8、但缺少计数和发现边的开发库：迁移先持有运行器和执行锁，计数从任务重建，发现边从已接受归档恢复。升级、修复和版本推进在同一事务内完成；已有三湖任务和凭据保留。

## 前端和公开端口

不增加独立 Pixiv 页面。现有资料浏览支持 Pixiv 来源、作者／作品快捷筛选、页序与作者资料；排序依据来源能力选择，Pixiv 标签保留内部空格。筛选器增加作品类型和 Pixiv 标记的对应控件。

现有数据湖工作台使用有界联合读取列出两类任务与计划；各类写入继续通过其原协议。新建更新按来源切换表单，复用图片配方；设置中的数据湖 API 管理公开访问、加密会话导入、验证和清除。下载与调度、后台活动及位置重新关联也纳入 Pixiv。

账号 Cookie 不存入界面草稿、任务定义或可回读响应。真实登录、续期和分级显示条件仍需用户提供凭据后验收；公开运行的完成状态不替代该验收。
