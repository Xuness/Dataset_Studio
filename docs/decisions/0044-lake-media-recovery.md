# 0044 — 单图色彩异常隔离与图片 404 恢复

日期：2026-09-29。状态：已实现；色彩错误的任务状态由 [ADR 0070](0070-png-metadata-degradation-and-deterministic-media-exclusions.md) 修订。

## 触发与边界

Gelbooru 正式更新的灰度 JPEG 带有 RGB ICC，旧实现直接建立 L 到 RGB 的颜色转换并抛出未捕获的 `PyCMSError`，整项任务反复在同一文件退出。另外，大批图片曾返回 404，抽样复测时原地址已经恢复。HTTP 404 不足以证明帖子删除，也无法仅凭旧日志区分 CDN、上游存储或出口链路问题。

## 决定

- 带 RGB ICC 的 1/L/LA 灰度图片先展开为 RGB/RGBA，保留配套 ICC 与透明通道。其他需要色彩转换的模式继续执行 ICC 转换；LAB 的 A 通道不是透明度。自定义编码产物的 `processing_version` 为 4，配方身份和已有资产不变。
- `PyCMSError` 在单张编码边界转为 `needs_review / image_color_profile_error`，保留下载原件。不得通过丢弃 ICC、忽略校验或捕获所有异常来伪装成功；归档/持久化完整性错误仍使用任务级保护。
- 图片 404 归入 `failed`，遵守当前最多 8 次尝试和重试时间。共享图片通道在 60 秒内累计 8 次 404 后冷却至少 60 秒，保留更长的既有冷却。计数与截止时间使用现有原子速率文件及锁；已发出的请求可能继续返回。元数据 API、编码和发布不等待该冷却。
- 显式“重试未获取项”优先复用既有观察及图片断点。无可用地址、缺失元数据、来源已删除/受限及 404 尝试耗尽才重新获取元数据。不支持的媒体重新经过本地资格检查，不为每一条视频浪费 API 请求。“继续”仍不隐式重新排队已结束的单图结果。
- 媒体批次幂等键包含任务执行代次，防止显式重试归零尝试计数后，重复的失败/不支持结果命中已应用旧批次而使队列永远停留在 pending。同一执行中的崩溃恢复仍先对齐已提交批次；旧归档保持可读。
- 前端解释常见问题代码并保留原代码提示，增加待刷新元数据、需要检查的筛选入口。

无公共 DTO、控制库格式或数据湖格式迁移。正式任务的旧版待刷新队列不会全局自动转换；本次仅在暂停和执行锁保护下，依据不可变归档结果核对并修复指定任务，保留转换前的可逆记录。

## 验证

单测覆盖灰度 RGB ICC、透明通道、真正无法匹配的 ICC 单图隔离、404 恢复、元数据复用和耗尽后的刷新、共享冷却。实际问题文件及 6 个历史 404 地址另做隔离校验；详见[验收记录](../verification/2026-09-29-gelbooru-media-recovery.md)。
